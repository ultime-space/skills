# 输出格式

## 评审报告

1. **结论**：通过 / 需调整 / 无法判定。
2. **判据**：引用 `docs/foundations.md`、`docs/color.md`、`docs/typography.md`、`docs/space-shape.md` 或 `docs/layout.md` 的规则；不引用就不算规范。
3. **证据**：原值、合成后的值、实测对比度、目标与门槛。
4. **最近可行档**：档位、偏差、代价；没有就写「需要项目自定义」。
5. **风险**：未知底、模式嵌套、放大 / 窄视口 / 译文增长、热区与焦点。
6. **范围**：说明哪些是可评审项，哪些是项目自检或人检。

## 设计规格

1. **范围**：对象、平台、模式、密度、内容最坏情况。
2. **结构**：页面 / 组件骨架、信息层级、主行动。
3. **维度**：颜色、排版、空间与形状、布局各选什么，为什么。
4. **状态与风险**：关键状态、空态 / 错误 / 加载、未决项。
5. **建议**：最近可行档与代价；不写强制结论。

## 规则

- 不写实现状态。
- 不写度量快照；写取值来源或复算方式。
- 给不出判据的结论标「偏好」，不写成规范。
- 设计系统评审与项目自检分开写；不把「设计系统通过」当成「页面合格」。
- 只给建议与报告，不做强制检查，不下阻断性结论。
- 不复制源正文；需要时给链接与差异。
