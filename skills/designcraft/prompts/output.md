# 输出格式

## 评审报告

1. **结论**：通过 / 需调整 / 无法判定。
2. **判据**：引用 `docs/foundations.md`、`docs/color.md`、`docs/typography.md`、`docs/space-shape.md` 或 `docs/layout.md` 的规则；不引用就不算规范。
3. **证据**：原值、合成后的值、实测对比度、目标与门槛。
4. **最近可行档**：档位、偏差、代价；没有就写「需要项目自定义」。
5. **风险**：未知底、模式嵌套、放大 / 窄视口 / 译文增长、热区与焦点。
6. **范围**：说明哪些是可评审项，哪些是项目自检或人检。

## 设计规格

1. **范围**：对象、平台、模式、密度、内容最坏情况。
2. **结构**：页面 / 组件骨架、信息层级、主行动。
3. **维度**：颜色、排版、空间与形状、布局各选什么，为什么。
4. **状态与风险**：关键状态、空态 / 错误 / 加载、未决项。
5. **建议**：最近可行档与代价；不写强制结论。

## 方案集（结构方案）

1. **范围**：证据来源（设计稿 / 实现 / 两者，不一致以实现为准）、内容关系、优先目标、固定项、最坏内容、范围级别（A 排列级 / B 结构级）。
2. **诊断**：画面上的具体症状与位置；说明哪些问题不属于本次。
3. **方案卡 ×2–3**：结构名、结构、结构线框（不超过 8 行）、改动点、预期、五项代价（可比较性 / 一屏信息量 / 定位成本 / 最坏内容风险 / 一致性；没有对应场景的项，如营销页的可比较性，写「不适用」）、页面族约定、窄屏行为、什么偏好下选它。
4. **推荐**：选哪套、因为哪个目标优先；另给一句偏好开关。
5. **待确认**：视觉结论标「待人工确认」；需要业务侧取值的位置；不在本次范围。

方案集只描述结构与代价，不判定合规，不给唯一答案；每套方案必须在结构上不同，不是换颜色或圆角。官网 / 落地页只给单元、分区与密度建议，不给首屏叙事结论。

## 风格方案集

1. **范围**：想让人感觉到什么、目标用户与主场景、约束、现有系统选择。
2. **方案 ×2–3**：风格名、意图、维度选择（颜色 / 字体 / 形状 / 表面 / 动效 / 密度 / 构图）、用意、优点、代价与风险、不适合的情况、骨架引用、示例场景。
3. **对比与推荐**：一张对比表 + 推荐一套 + 一句偏好开关。
4. **警告**：对比度、性能、平台、可读性；警告不等于禁止。

只给一套、或只用形容词堆叠（「高级、干净、有质感」）都不算方案集。

## 规则

- 不写实现状态。
- 不写度量快照；写取值来源或复算方式。
- 给不出判据的结论标「偏好」，不写成规范。
- 设计系统评审与项目自检分开写；不把「设计系统通过」当成「页面合格」。
- 只给建议与报告，不做强制检查，不下阻断性结论。
- 不复制源正文；需要时给链接与差异。
