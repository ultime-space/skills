# 颜色规范

> 适用：主色选择、色族派生评审、深浅配对、对比度判定。
> 评审步骤见 [`scenarios/review-color.md`](../scenarios/review-color.md)；品牌色见 [`scenarios/configure-brand-color.md`](../scenarios/configure-brand-color.md)。

## 1 三个空间各管一件事

| 空间 | 用在哪 |
|---|---|
| **OKLCH** | 派生时求解明度 / 彩度 / 色相 |
| **sRGB** | 交付值与对比度计算 |
| **oklab** | 运行时混色插值 |

交付值里不出现 OKLCH 字面量：计算在 OKLCH，交付在 sRGB。

**同 L 不等于同对比度**：判断可读性一律换到 sRGB 相对亮度。

**评价顺序**：反解到实际输出色域 → 色域映射 → 透明合成 → 舍入 → 按前景 / 背景计算对比度。低于最低门槛的值不能靠四舍五入变成通过。

## 2 色族模型

三层分工：

- **可变的设计选择**：主题色相、锚点明度、彩度系数、中性色温、语义色相、画布温度。
- **派生的颜色角色**：每族 solid / soft / bare 下的 fill / ink / line 与强度 / 状态；实心填充的配对前景。
- **固定的门槛**：正文 4.5、实心面文字 4.5、图元 3.0；描边三档 1.16 / 1.45 / 3.0。

派生值不手写 hex；手改派生值会让全局选择失效。

```text
色相 + 锚点明度 + 彩度系数 → 锚点色
  ├─ 实心填充：按前景方向 × 两端值 × 目标反解
  ├─ 色族矩阵：底 × 用途 × 强度 × 状态
  ├─ 配对前景：按填充明度反解
  ├─ 浅底三件套 soft / border / text
  ├─ 强档 strong（图元 3:1）
  └─ 深底三件套 + 交互五态
```

**锚点不等于最终填充**：锚点只提供色相与彩度上限，填充明度由目标反解；同一目标下不同色族的解可以不同。

三条口径：

1. **色相是身份，默认几乎不偏**：偏移预算默认 2°（项目默认，不是通用结论）；邻近主题几乎不动，对向主题才用满预算。2° 不足以把 warning 的橙推成黄，也不会把 danger 的红推成品红。
2. **填充明度由目标反解**：先定全局前景侧与端点，再按目标求填充；评价用实际输出的相对亮度，不用 OKLCH L 代替对比度。
3. **彩度交给色域**：彩度 = 该色相 / 明度的色域上限 × 系数；色域不够时只降彩度，不降明度。

**墨色是默认**：彩度系数为 0 时主色不承载品牌身份，基色取深灰；浅底按「白 × 0.92 混基色」派生，描边目标 1.38、文字目标 6.0。需要品牌色时同时给色相与彩度。

**实心面按模式配对**：浅色模式配近白字、深色模式配近黑字；两端用同一明度配方（浅端 = 100 − Δ、深端 = Δ），Δ ≤ 2–3；不要求两端对比度相等，各自过 4.5。填充不达标时给警告，不翻转文字方向；纯图元或大字实心面可按 3.0 反解。

**不再生成装饰色阶**：插图 / 色纸需要明度展开时，由组件层用色族组合；承载文字仍回到填充 / 墨 / 线。

**按用途选角色**：文字、描边和图元各选对应用途角色；文字在自身背景达标，不代表用作焦点环也满足相邻颜色要求。

**两层颜色不要混用**：业务色（品牌与语义）与工具色（工具自身界面）是两套；语义色只给真语义，不当模块身份色。

## 3 中性色与表面

**中性族只有三项**：遮罩 / 阴影 / 环境遮蔽。它们单值、不参与模式，深浅共用，墨的极性恒定——阴影与遮罩永远是深墨，深色模式不用白阴影 / 白遮罩（那是光晕）。

**表面栈**：画布 + 叠在其上的 tint。四个面阶：画布（一级面容器，通常不透明；半透明需验证）、抬升面、浮层面、凹陷面。抬升一律变亮、下沉一律变暗，不随模式翻转。

**一级面容器是可读性风险区**：半透明可用，但要按最坏背景验证合成对比度；输入框、浮层 / 弹层 / 抽屉的主要内容、直接放在图片 / 渐变上的卡片 / 面板底不可控时，给底衬 / 遮罩 / 回退。完整规则见 [`depth.md`](./depth.md) §1。

**文字墨四档**，按对比度目标定值，alpha 是逐模式反解的结果：

| 档 | 用途 | 目标（对画布） |
|---|---|---|
| **主文字墨** | 主文字 | 7.2 |
| **次文字墨** | 次文字 | 6.0 |
| **辅助文字墨** | 辅助文字 / 元信息 | 5.0 |
| **禁用墨** | 占位 / 禁用 | 2.0 |

前三档按 1.2 的档位比排列（7.2 / 6 / 5）；第四档是状态，不参与档位比。前三档都高于 AA 的 4.5，主档在画布上达到 AAA；禁用档按状态豁免。

**深浅用同一套目标，alpha 各自反解**：同一档在两个模式下的目标对比度相同、alpha 不同。目标定义在画布上；抬升面 / 浮层面 / 凹陷面按声明底复核，最弱面不得低于该档门槛（正文 4.5、禁用 2.0）。

**透明度是载体，不是值位**：项目选的是目标档，alpha 由取值来源反解；评审按「声明底 + 合成后的实际颜色」计算，不对 alpha 本身判定。

**线是墨量，不是灰阶**：三档描边对中性面的对比度固定为 1.16 / 1.45 / 3.0。线色只引用中性线墨或语义色，叠在图片 / 彩色块上随底变化。

**中性温度**：两侧画布的色相 / 彩度按模式分别声明，默认真中性；要偏暖 / 偏冷必须两侧一致，或显式声明对冲；不允许一侧中性、一侧偏色。画布与灰阶同源；直接写 hex 等于声明「画布冷暖与体系脱钩」，必须写明理由。

## 4 语义色与状态

族：`primary`（主色 / 主操作；默认墨色不承载额外品牌身份）/ `success` / `warning` / `danger` / `info`。

**四族参数**：基底色相 `danger 0° / warning 30° / success 150° / info 210°`，锚点明度统一 0.60，彩度取色域上限 × 系数。四个值都在 30° 网格上：warning ↔ info 互为补色，danger ↔ success 保持红绿对立。

- **语义色的色相是锚点**，不借给模块当身份色；模块身份用 icon + 文案 + 中性面层级承担。
- **warning 用橙、danger 用红**：品牌主色尽量避开 20–45°（橙）与 350–10°（红）；真撞上时只报告，不自动旋转。
- 中性表面不新开色相，只从灰阶与 alpha 栈取。

**色族墨是实色，不用 alpha**：语义色的识别依赖色相纯度，半透明色叠在浅底上会去饱和；中性墨没有色相要保，所以中性墨用 alpha、色族墨用实色。

目标矩阵按 **底 × 用途 × 强度 × 状态** 四维展开：

```text
底：solid / soft / bare
用途：fill / ink / line
强度：weak / base / strong
状态：rest + hover / focus / pressed / selected / disabled / dragged / drop-target
配对前景：实心填充上的前景色（文字 / 图标），无强度 / 状态
```

**配对前景不是独立维度**：它是 solid 的配对槽位，不是第四种用途，也不是 `-on` 后缀。`ink` 与配对前景不是二选一：`ink` 是色族自己的文字色，配对前景是「这块实心面上放什么字能读」；彩色实心面必须用配对前景。

`focus` 是焦点环状态，不计入 fill 四状态；fill 只派生 hover / pressed / selected / disabled。

**三条文字线，按背景分工**：

| 线 | 背景 | 档位 | 目标 |
|---|---|---|---|
| 中性墨 | 画布 / 抬升面 / 浮层面 / 凹陷面 | 主 / 次 / 辅 / 禁 | **7.2 / 6 / 5 / 2.0** |
| 族墨 | solid / soft / bare | 强 / 中 / 弱 | **7.2 / 6 / 5** |
| 配对前景 | solid | 每族一档 | **4.5** |

**浅底三件套**：soft 由白 92% 混基色（对画布 1.1）；border 在浅底上再混白（1.38）；text 在浅底上反解（6.0，weak 5、strong 7.2）。

**状态色**：中性交互态 hover / pressed / disabled 对底的目标为 **1.08 / 1.12 / 1.03**，alpha 由目标反解，不写固定百分比；selected 混主色；focus 走焦点环，颜色取 3:1 的描边档。语义色每族成套派生**四个状态**（hover / pressed / selected / disabled），方向按「远离配对前景」；必须按最坏态评审。hover 只在有指针的设备上生效，触控端不得用 hover 传达信息。

**焦点态**：2px 焦点环、3:1 描边档、外扩 2px；不用描边或投影冒充。焦点指示按 WCAG 1.4.11 检查与相邻颜色 ≥3:1。

## 5 深浅模式与局部模式

- 两端成对（浅 / 深）；无后缀名只做跨模式开关；角色在每个主题作用域里原样重声明一次。
- 组件只读角色，不直接读原料值，否则深色值接不住。
- 模式是可嵌套的作用域：可以写在任意容器上，子树按最近一层解析；局部模式块的根必须不透明。
- 媒体背景先铺遮罩：内容放媒体上先铺中性遮罩，再按容器模式取色。
- 不预设反向嵌套能力：深页浅块与浅页深块是同一机制，但要按已有主题映射验证实际继承链。
- 系统跟随由项目决定：默认不做系统跟随；设计稿内容不应因为评审者系统是深色就整体变暗。
- 值的成对规则：中性值位走表面栈，每族 soft / border / text / strong / fill / 配对前景 / hover / pressed 两端成对；语义色的深色浅底是派生出的实色，不参与中性表面的 alpha 栈；fill 与配对前景随模式成对反解，selected / disabled 与页面深浅无关。

## 6 偏色归属

偏色（冷暖、品牌倾向、语义色相）是**全局选择**，不是角色层或组件层的职责。

| 层 | 管什么 | 不管什么 |
|---|---|---|
| **全局选择** | 中性预设、中性明度曲线、每模式色温、彩度系数、表面混色、环境偏色 / 高光偏色、语义色相、画布温度 | —— |
| **角色层** | 只做「值 → 角色」的等价映射，深浅主题各声明一次 | 不做混色 / 计算，不按主题改色相，不写第二套冷暖值 |
| **组件层** | 只读角色与组件自己的局部值 | 不定义色温，不写带色相的 hex（raw hex 只允许出现在 fallback 最末端） |

三条约束：

1. **画布与灰阶同源**：改中性预设或色温会同时改灰阶与画布；写死 hex 视为「画布冷暖与体系脱钩」，须注明理由。
2. **品牌倾向只有两条通道**：主色彩度 > 0 让主色带色相；表面混色 > 0 让表面 tint 混入主色。两者默认都是 0。
3. **光影偏色只走两个全局选择**：环境偏色默认继承中性墨，高光偏色默认纯白；主光染高光，环境染阴影 / 遮罩 / 环境遮蔽。

## 7 配对与 WCAG

**任何实心填充色都必须同时给出配对前景**，禁止拿「当前文字色」硬套。配对前景的目标是 4.5（普通文字）；填充按这个目标反解。

- 方向按模式声明，默认浅色模式配近白字、深色模式配近黑字；同一模式内全部语义族、全部状态必须同向。
- 默认端点为纯极（`#FFFFFF` / `#000000`），两端用同一明度配方，Δ ≤ 2–3；不要求两端对比度相等。
- 求解顺序是「先定方向，再反解填充」：填充不达标给警告，不翻转文字方向；只有纯图元或大字的实心面可按 3.0 反解。
- 彩色实心面是点缀，不是大面积背景；实心面默认只放主文字，需要次级信息时用配对前景 + alpha，并按最坏声明底评审。
- 静态填充用派生的配对前景；动态填充（运行时才知值）用运行时对比色 + 兜底，并先给一句兜底色。

**门槛**：

| 文本类型 | 门槛 |
|---|---|
| 普通信息文字（包括辅助提示、图注与元信息） | **≥ 4.5:1** |
| 大字号文本（约 24px 常规 / 18.67px 粗体） | ≥ 3.0:1 |
| 识别控件、状态或理解图形所需的非文本信息 | 与相邻颜色 ≥ 3.0:1 |

**目标是设计值，门槛是下限，放行是项目声明**：

- **目标**：中性 7.2 / 6 / 5、族墨 7.2 / 6 / 5、配对前景 4.5。
- **门槛**：普通文字 4.5、大字与图元 3.0、禁用 2.0。
- **评审分级**：≥ 目标 = `pass`；≥ 门槛但 < 目标 = `warn`；< 门槛 = `deviation`；未知底 = `unverified`，不假装通过。
- **颜色项只报告，不阻断**：颜色偏离只报告，由项目决定是否修正。
- 低对比是可选风格，不是隐式降级：低于 4.5 只能作为 `deviation` 登记，不能宣称 AA。

## 8 渐变

> 渐变是填充的一种，不是颜色角色。本节给判断顺序与经验区间，不给固定配方；用不用由内容与品牌决定。

**判断顺序**

1. **这层要不要渐变**：两端色差不足时，渐变看不出层次，还更容易出现台阶。层级改由面阶、边界、字重与间距承担。
2. **用哪个插值空间**：看两端色相距离。近似色相直接过渡即可；对立色相会经过低彩度中心、中段发灰，改用感知空间插值，或在中间补一个保色色标。
3. **色标怎么分布**：等距等于匀速；要非匀速就移动色标，或放一个不带颜色的位置提示。加色标不会增加可表示色阶。
4. **有没有台阶风险**：过渡长、色差小、目标设备色深有限，三者同时成立才需要处理。有风险再叠细颗粒，颗粒是修复手段，不是装饰。
5. **上面有文字吗**：默认插值时亮度单调，只验两端；换插值空间、叠在图片或透明底上时按整段采样，取最不利点。

**端点关系与观感**

| 关系 | 观感 | 代价 |
|---|---|---|
| 同色相浅到深 | 最稳，像光照或层次 | 差异过小时看不出 |
| 邻近色相 | 有方向感，仍可读 | 跨度大时中段略灰 |
| 对角色相 | 强烈、有张力 | 必须处理中段发灰，否则显脏 |
| 高彩度对高彩度 | 醒目，适合局部强调 | 面积大时刺眼，长时间观看疲劳 |
| 实色到透明 | 叠加与遮罩的基础 | 与「实色到白」不是一回事，写成白会发灰发白 |

**经验区间**

- 端点数量：两到三色足够表达方向；四色以上逐段检查中段彩度。
- 彩度：在目标基调上下调约一成到两成更耐看；品牌色固定时改用面积与位置控制强度。
- 过渡长度：短过渡更容易藏住台阶，也更容易显得突兀。
- 颗粒：只在有台阶风险时使用，强度以「看不见颗粒、只看见平滑」为准。

**常见滥用**

- 每个区块都铺渐变，背景失去层级。
- 全站同款高彩度多色渐变，品牌辨识度反而下降。
- 渐加上再叠渐变，两套方向互相打架。
- 纯黑或纯白文字直接压高彩度渐变，可读性通常不达标。
- 用渐变补偿布局错位，或掩盖间距不一致。

颗粒与材质的降级见 [depth](./depth.md)；叠在图片或未知底上的可读性处理见 §7。

## 9 评审口径

**可检查项**：各色族在浅 / 深、全部状态、登记中性面上的配对；无颜色字面量；混色按感知均匀色空间；偏色只在全局选择；语义色只用于状态语境；渐变文字按插值方式取最不利点。

**项目自检**：具体背景上的实际对比度、组件里的 hex 是否只在 fallback。

**必须人检**：局部模式嵌套、未知底（图片 / 视频 / 渐变 / 多层透明）、整体透明度、色觉差异、强制颜色、高对比、减少透明。

模型只证明被登记的配对与条件；真实背景、字体、焦点、辅助技术与设备表现仍需人工确认。
