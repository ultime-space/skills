# 数据色、图形与内容规范

> 适用：数据色板、图标尺寸与使用场景、图形 / 插画、内容层级与文案。
> 评审步骤见 [`scenarios/review-content.md`](../scenarios/review-content.md)。

## 1 数据色

数据可视化不是「把界面色板拿来用」，至少需要三类：

| 类型 | 用途 | 机制 | 常见错误 |
|---|---|---|---|
| **分类（categorical）** | 区分无顺序的类别 | 一组彼此可辨的色相，按固定顺序使用 | 相邻色相过近；类别超过色板数量后循环复用 |
| **连续（sequential）** | 表示有序数值 | 单色相明度 / 彩度渐变；浅色主题深色表示大值，深色主题反向 | 用彩虹色阶；把渐变当分类色 |
| **发散（diverging）** | 表示围绕中点的正负偏离 | 两个对立色相 + 中性中点 | 中点不代表零；正负方向不一致 |

- **状态色不能替代类别**：成功 / 危险表达状态，不表达「A 类 / B 类」；类别超出可辨范围时，不能只循环复用颜色。
- **对比度与类别可区分是两项验收**：图元与相邻背景通常 ≥ 3:1（WCAG 1.4.11），但「对比够」不等于「类别可辨」。
- **色觉差异**：红绿在 deutan 下可能接近，蓝紫在 tritan 下可能接近；用亮度差、形状 / 图案、文字标签、固定顺序补偿，不靠换一个更饱和的颜色。
- **模拟只做初筛**：色觉模拟不能替代真实用户测试。
- **数据色板不进系统**：系统只提供色族生成能力；图表色板的数量、顺序与可辨性策略归组件层 / 风格层。
- **深色数据色**：大面积高饱和在深色背景上更刺眼，通常降饱和或降面积；纯黑 vs 近黑是产品取舍。

## 2 图标

图标只规范**尺寸**与**使用场景**；图标资产使用 SVG，并由项目选择第三方图标集。本文件不规定具体图标库，也不规定图标绘制规范。

### 2.1 尺寸

| 尺寸 | 典型用途 |
|---|---|
| 12 | 角标、极小注脚 |
| 16 | 与正文同排、紧凑控件 |
| 20 | 按钮、表单前后缀 |
| 24 | 导航、工具栏、常规操作 |
| 32 | 空态、大标题、展示 |

- 尺寸档与控件高度分开：图标 24 不代表热区 24；热区按 [`space-shape.md`](./space-shape.md) §4 单独补。
- 行内图标与文字对齐用 `1em` 与 `cap` 的公式（见 [`typography.md`](./typography.md) §10），不要写死偏移。
- 同一组图标保持同一尺寸与视觉重量；不要混用不同母版导致大小不一致。

### 2.2 使用场景

| 场景 | 用法 |
|---|---|
| **行内** | 与文字同排，尺寸随字号；装饰图标不参与命名 |
| **图标按钮** | 按钮本身有可访问名称，图标作为装饰；热区按控件高度补足 |
| **导航 / 工具栏** | 使用固定尺寸（通常 24）；选中态靠颜色 / 形状 / 标签，不只靠图标变化 |
| **列表 / 卡片** | 图标只做辅助识别；不要让图标独自承担必要信息 |
| **空态 / 结果** | 可用较大图标（32）建立视觉重心；仍需要标题、说明与下一步 |
| **状态标记** | 图标 + 文字 / 颜色一起表达；不能只靠图标形状区分成功 / 警告 / 危险 |

### 2.3 可访问性

- **装饰图标**：`aria-hidden="true"`，不参与命名。
- **表意图标**：`role="img"` + `aria-label`，或由相邻文字命名；只靠 tooltip 在触屏不可达。
- **图标按钮**：按钮本身有可访问名称，图标装饰化；只写 `title` 在部分读屏下不稳定。
- **颜色**：单色图标用 `currentColor` 跟随文字；承载信息的图标与相邻背景 ≥ 3:1。
- **光学对齐**：数学居中不等于视觉居中；圆形、三角形、尖角需要微调。

## 3 图形与插画

- 图形（pictogram）与 UI 图标分开；图形的最小使用尺寸、留白与 UI 图标不同，不能把 24px 图标的规范直接套到 48px 图形。
- 插画适合空态、引导、营销；**图形不能独自承担必要信息**，必须有文字或替代文本。
- 风格漂移是常见风险：每个业务各画一套插画；需要时由风格层定义图形语言，不在组件层各自发挥。
- 深色模式、强制颜色、打印下要检查图形的可读性与回退。

## 4 内容设计

内容层级与文案是设计的一部分，不是实现后的填充。

### 4.1 层级

- 一屏只保留一个主行动；次级行动降级为文字按钮 / 链接。
- 标题说「这是什么」，正文说「为什么 / 怎么做」，按钮说「会发生什么」。
- 长内容先分组，再分节；不要用字号和颜色硬造层级，先用结构与间距。

### 4.2 标签与按钮

- 按钮用动词 + 对象：`保存更改`、`删除项目`，不用「确定」「继续」这类无语境词。
- 破坏性操作写清对象；需要确认或撤销，不立即执行。
- 导航用名词，动作按钮用动词；同一位置不要混用。

### 4.3 错误

- 说清「哪里错、为什么错、怎么改」；错误摘要逐条链接到字段。
- 不把技术错误码直接给用户；保留可复制的追踪 ID 给支持。
- 错误不只用颜色；用文字、图标、`aria-invalid` / `aria-describedby`。

### 4.4 空态、加载与结果

- 空态说明「为什么空」与「下一步做什么」，不只放插画。
- 加载文案用「正在加载…」「正在保存…」，省略号用 `…`；停止动画后仍有静态线索。
- 结果区分成功 / 失败 / 部分成功；失败给恢复路径，不只说「出错了」。

### 4.5 数字、日期与语言

- 数据比较用等宽数字（见 [`typography.md`](./typography.md) §6）；金额 / 百分比 / 日期 / 编号成列对齐。
- 日期 / 时间 / 货币用 `Intl.*`，不硬编码格式；相对时间要说明基准。
- 中英混排按 [`typography.md`](./typography.md) §8；接口原文原样展示，不替后端做排版清洗。
- 文案语气跟产品气质一致：精密而不冰冷，开放而不松散；不用夸张感叹号堆情绪。

## 5 评审口径

**可检查项**：分类 / 连续 / 发散色板是否被混用；图标尺寸是否落在 12 / 16 / 20 / 24 / 32；图标热区是否单独补足；图标是否有可访问名称；长标签 / 译文增长 / 截断是否有完整路径。

**项目自检**：具体图表色板顺序、图形资产风格、接口原文的排版。

**必须人检**：类别是否只靠颜色区分；色觉差异；空态 / 加载 / 结果是否有文字语义；数字 / 日期 / 货币是否按 locale 格式化；图标在深色 / 强制颜色下的表现。
