# 交互状态规范

> 源：设计规范 §10（快照 2026-11-05）。本文件是面向 AI 的提炼，不是规范真源。
> 适用：交互态、数据态、异步态、状态组合、输入环境与可访问性评审。
> 评审步骤见 [`scenarios/review-states.md`](../scenarios/review-states.md)。

## 1 状态分三类

| 类别 | 例子 | 语义归属 | 常见问题 |
|---|---|---|---|
| **交互态** | hover、focus、pressed、dragged | 伪类（`:hover` / `:focus-visible` / `:active`） | 触控没有 hover；`:focus` 与 `:focus-visible` 混用 |
| **数据态** | selected、current、checked、expanded、disabled、readonly、invalid | 原生属性 / ARIA | 用私有 `data-*` 代替语义，读屏读不到 |
| **异步态** | loading、pending、success、error、empty | `aria-busy`、`role="status"` / `alert`、文本 | 只靠动画或颜色，不留文字与播报 |

- **原生属性优先**：能用 `disabled` / `checked` / `open` / `aria-expanded` 表达的，不用私有 `data-*`。
- **私有 `data-*` 只服务样式**：它可以存在，但不能替代语义；读屏拿不到的私有状态不算状态。
- **一类状态只回答一件事**：按下、选中、当前、展开、加载不是同一件事，不能用一个视觉表达兼任。

## 2 状态载体与几何恒定

状态反馈有四类载体，按元件形态选：

| 载体 | 适合 | 不适合 |
|---|---|---|
| **覆盖层**（叠墨 / 叠色） | 块面、按钮、列表行 | 需要改变形状的指示物 |
| **换色** | 文字、图标、语义色块 | 需要保留原色的品牌块 |
| **描边 / 环** | 选中、焦点、错误 | 会改变布局的加宽边框 |
| **框内指示物** | 勾、点、滑块、箭头、进度 | 整块元件的位置 / 尺寸 |

**几何恒定**：状态反馈不改变元件外框的位置与尺寸。`translate` / `scale` / `rotate` / 宽高 / `inset` / `margin` 不用于表达 hover / active / selected / loading / invalid；框内指示物可以在固定外框内移动或旋转。

**状态层依赖底色**：覆盖层在图片、渐变、彩色块上不一定达到预期对比；这些底要单独验证，不能从中性面规范推定。

## 3 交互态

### 3.1 hover

- **只在有指针的设备上存在**：`:hover` 包在 `@media (hover: hover)` 内；触控端用按下态与触感 / 缩放反馈。
- **信息不能只在 hover 里**：触控用户拿不到；tooltip、操作按钮、关键说明必须有可点击 / 可聚焦的入口。
- **hover 不承担状态**：hover 只是「指针在这里」，不能代替 selected / current / expanded。
- **残留态**：混合输入设备上，点完仍可能保持 hover；不要用 hover 表达「已选中」。

### 3.2 focus

- **用 `:focus-visible` 做主指示**：它是浏览器按启发式判断需要显示指示器时匹配的状态，不是「仅键盘」开关；文本输入被点击后也可能匹配。
- **焦点必须可见**：任何键盘可聚焦元素都要有可见焦点；不要 `outline: none` 而没有替代。
- **强制颜色下不要抹掉 `outline`**：系统会用自己的高对比色替换。
- **焦点不被遮挡**：固定 header / tabbar / 浮层不能盖住焦点环；WCAG 2.4.11（AA）要求不完全遮挡，2.4.12（AAA）要求任何部分都不遮挡。
- **焦点环几何**：`outline` 2px + offset；不用 `border` / `box-shadow` 冒充。

### 3.3 pressed / dragged

- **按下立即反馈**：不带延迟；时长按面积取 `press` / `indicator` 角色。
- **按压不改几何**：用覆盖层或框内指示物，不用缩放 / 位移 / 宽高。
- **拖拽有替代**：拖拽 / 滑动 / 捏合 / 路径手势需要点击 / 键盘替代（WCAG 2.5.7 及例外）；拖拽中禁用文本选择、给被拖元素 `inert`。
- **拖拽预览不改变布局**：预览层脱离文档流，原位置保留占位或明确的收起状态。

## 4 数据态

| 语义 | 属性 | 适用 | 注意 |
|---|---|---|---|
| 当前页面 / 位置 | `aria-current="page"` / `"step"` / `"location"` | 导航、面包屑、步骤条 | 一个容器内通常只有一个；不要用颜色代替 |
| 选中项 | `aria-selected` | tabs、listbox、grid | 只在复合控件内使用；普通链接不用 |
| 切换按钮 | `aria-pressed` | 可反复开关的按钮（加粗、收藏） | 与「选中」不同：按钮不进入选择集合 |
| 勾选 | 原生 `checked` / `aria-checked` | checkbox / radio / switch | checkbox 支持 `mixed`（半选）；radio 没有半选 |
| 展开 | `aria-expanded` | disclosure、菜单、树 | 与 `hidden` / `display` 同步；`<details>` 原生自带 |
| 禁用 | `disabled` / `aria-disabled` | 表单控件 / 任意元素 | 见 §4.1 |
| 错误 | `aria-invalid="true"` + `aria-describedby` | 表单控件 | 只改边框颜色不够 |
| 只读 | `readonly` | 展示已有值、可复制 | 可聚焦、可读、不可改 |

- **选中 ≠ 当前 ≠ 展开**：三者可以同时存在，但语义不同；不要用一个属性兼任。
- **视觉只做映射**：颜色、图标、形状是语义的映射，不反过来定义语义；WCAG 1.4.1 要求不能只靠颜色传达信息。

### 4.1 禁用与只读

| 方式 | 可聚焦 | 阻断行为 | 读屏语义 | 适用 |
|---|---|---|---|---|
| 原生 `disabled` | 否 | 是（表单控件） | 禁用 | 表单控件、确定不可用 |
| `aria-disabled="true"` | 不改变原有可聚焦性 | 否，需要手动阻断 | 禁用 | 需要被发现的禁用项、语义适用的自定义控件 |
| `readonly` | 是 | 否（可聚焦、可读、不可改） | 只读 | 展示已有值、可复制 |
| 不禁用 + 校验 | 是 | 否 | 正常 | 提交按钮（推荐） |

- **提交按钮优先不禁用**：禁用态对比度差、用户不知道为什么不能点，也看不到错误；保持可点，提交时给行内错误与摘要。
- **禁用态不要整块 `opacity`**：会把文字、图标、描边一起降到不可读；只换禁用墨，保留边界与结构。
- **禁用不等于移除**：需要被发现的禁用项保留在可聚焦 / 可读路径里，或用 `aria-disabled` 保留焦点。

### 4.2 错误与校验

错误有四个决定：**何时**出现、**在哪**显示、**怎么**关联、**怎么**汇总。

- **何时**：输入时实时校验反馈快但打断多；失焦校验温和；提交时最稳。`:user-invalid` 只在用户交互后匹配，但不是所有目标浏览器都支持，也无法表达业务规则。
- **在哪**：行内错误紧跟字段；页面级错误用摘要或 banner。
- **怎么关联**：控件写 `aria-invalid="true"`，错误文案通过 `aria-describedby` 关联；只改边框颜色不够。
- **怎么汇总**：错误摘要把焦点移到摘要、逐条链接到字段、字段旁加「错误：」前缀；读屏、键盘与视觉三条通道一致。

校验成功通常不需要颜色提示；如果要用，需同时给文字或图标，避免只靠颜色。

## 5 异步态

- **加载**：按钮用 spinner + `aria-busy`；区域用骨架；长任务用进度条。按钮进入加载态后应阻断重复提交（禁用或拦截），但不要靠 `disabled` 让按钮从 Tab 顺序消失。
- **状态消息**：普通提示用 `role="status"`（不打断），需要立即播报的错误才用 `role="alert"`。
- **乐观更新**：先改界面再请求，失败时回滚并给出可理解的错误；不能让界面停留在「已成功」的假象。
- **空态**：空态是结果的一种，需要说明「为什么空」与「下一步做什么」，而不是只放插画。
- **停止动画后仍有线索**：spinner / 骨架停下后，静态图形、文案与语义仍需说明正在处理；焦点与最终状态不能依赖动画结束回调才成立。

## 6 状态组合与最坏态

- **组合是允许的**：selected + hover + pressed 可以同时出现；状态层可以叠加，但同一时刻最多两层视觉反馈，超过就是噪音。
- **按最坏态评审**：正常态通过不能替代 hover / focus / pressed / selected / disabled 的验证；状态改变填充或覆盖层后重新评价前景。
- **状态方向**：语义色状态按「远离配对前景」移动（见 [`color.md`](./color.md) §4）。
- **状态不改变语义**：视觉状态不能替代属性；属性状态也不能保证视觉可辨，两者分别验证。

## 7 输入环境

| 项 | 触控 | 指针 + 键盘 |
|---|---|---|
| hover | 不存在，不能承载信息 | 可用，但包在 `@media (hover: hover)` |
| 焦点 | 少见（外接键盘） | 必达；`:focus-visible` + 完整 Tab 顺序 |
| 目标尺寸 | 按平台惯例放大（44 / 48） | 可到 28–32 |
| 光标 | 无 | `pointer` / `text` / `not-allowed` / `grab` |
| 焦点管理 | — | roving tabindex、焦点返回、`inert` 背景、不被固定元素遮挡 |

- **目标尺寸归 [`space-shape.md`](./space-shape.md) §4**：视觉尺寸、热区、相邻间距分开验证；图标尺寸不等于热区。
- **键盘顺序 = 阅读顺序**：视觉重排不能改变 DOM 顺序；如果必须改变，逐页验证焦点顺序与可操作性（WCAG 2.4.3）。
- **安全区**：全出血布局让出 `env(safe-area-inset-*)`；固定底栏不盖住内容与焦点。
- **手势替代**：拖拽 / 滑动 / 捏合 / 路径手势需要点击 / 键盘替代，除非该手势是必要的（WCAG 2.5.7 及例外）。

## 8 评审口径

**可检查项**：状态用原生属性 / ARIA 表达；hover 只在 hover 设备生效；focus 可见且不被遮挡；状态切换不改几何；选中 / 当前 / 展开 / 按下能区分。

**必须人检**：禁用 / 只读 / 错误是否可理解；加载 / 空态 / 错误是否有文字语义；最坏态对比度；读屏 + 键盘 + 视觉三条通道。
