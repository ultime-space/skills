# 组合原则与场景

> 源：设计规范 §13（快照 2026-11-05）。本文件是面向 AI 的提炼，不是规范真源。
> 适用：页面级构图判断、场景取舍、设计批评的前置检查。
> 评审步骤见 [`scenarios/review-critique.md`](../scenarios/review-critique.md)。

## 1 构图原则

| 原则 | 一句话 | 检查 |
|---|---|---|
| **层级** | 一屏先回答「先看什么、再看什么、最后看什么」 | 闭眼回忆，能否说出三个层次 |
| **分组 / 接近** | 相关的靠近，无关的拉开；分组靠间距，不靠框 | 去掉边框后，分组是否仍成立 |
| **对齐** | 同一组元素共享一条轴；对齐优先于平均 | 是否有一条可解释的基线 |
| **对比** | 需要区分的元素在字号、字重、墨、面阶上拉开 | 去掉颜色后，层级是否还在 |
| **重复** | 同一语义在全站用同一组合 | 两个页面是否用了两种角色 |
| **平衡** | 视觉重量分布合理；不对称要有意图 | 重心是否偏向一侧而没有理由 |
| **留白** | 留白是结构，不是剩余空间 | 去掉留白后，是否更清楚？通常不是 |
| **一个主行动** | 一个区域只保留一个主按钮 | 是否出现两个同等强度的主按钮 |
| **渐进披露** | 先给必要信息，再按需展开 | 首屏是否被次要信息淹没 |
| **内容优先** | 先解决内容层级，再选容器与装饰 | 去掉卡片 / 阴影后，内容是否仍成立 |

**跨维度代偿是反模式**：用阴影补层级、用描边补间距、用颜色补状态、用动效补缺失的反馈、用透明补面阶。缺什么补什么，不要让一个维度替另一个维度还债。

## 2 场景对照

| 场景 | 优先 | 建议的维度取向 | 常见错误 |
|---|---|---|---|
| **产品 UI** | 效率、可预期、状态清楚 | 中性面、克制字阶、comfortable / compact、tonal / outline、短动效 | 用营销式大标题挤压操作区；状态只靠颜色 |
| **营销 / 落地页** | 叙事、节奏、第一印象 | 更强的字号对比、更大的留白、少量强调色、克制的动效 | 居中 hero + 三列卡片 + 紫色渐变；信息密度过低 |
| **编辑 / 阅读** | 行宽、行高、层级 | 窄容器、较大行高、serif / display 搭配、tonal 面、少阴影 | 行宽拉满；标题与正文只差一点点 |
| **仪表盘 / 数据** | 比较、扫描、密度 | compact、tabular-nums、outline / tonal、数据色分类 | 把状态色当类别色；卡片过多没有主次 |
| **展示 / 纸面** | 观看、解释、对照 | 清晰层级、较大留白、24 栅格、说明纸与展示纸分开 | 把产品 UI 的密度直接搬到纸面；稿外写字 |
| **移动 / 小程序** | 热区、单手、安全区 | 触控尺寸、底部操作、safe-area、少 hover | 把桌面双栏缩到手机；用 hover 承载信息 |

**场景不是风格**：同一场景可以有不同的风格表达；先满足场景的可用性，再选风格。

## 3 构图与风格的分工

- **构图**回答「信息怎么排、层级怎么建立、视线怎么走」。
- **风格**回答「用哪一组身份维度表达气质」。
- 先构图，后风格；风格不能修补没有层级的结构。

## 4 构图评审问题

1. 首屏是否只有一个主行动？次级行动是否明显更弱？
2. 去掉所有边框、阴影、底色后，分组与层级是否仍成立？
3. 同一语义在两个页面是否用了同一角色 / 面阶 / 间距？
4. 视觉顺序与 DOM / 焦点顺序是否一致？
5. 最坏内容（最长标题、空数据、错误、译文增长）是否仍成立？
6. 是否有跨维度代偿？删掉那个维度，问题是否还在？
7. 这个构图是否在服务内容，而不是在套模板？

## 5 场景取舍

- **产品 UI**：优先可预期与效率，减少装饰，状态必须清楚。
- **营销**：允许更强的对比与更大的留白，但不要把信息密度压到不可用。
- **编辑 / 阅读**：行宽与行高优先于装饰；标题与正文必须跨档。
- **仪表盘**：比较与扫描优先；数据色分类，状态色不替代类别。
- **展示 / 纸面**：观看与解释优先；纸面结构、设备壳与页面骨架由具体实现决定。
- **移动**：热区、单手操作、安全区优先；hover 不能承载信息。

## 6 评审口径

**可检查项**：是否只有一个主行动；分组是否靠间距；同一语义是否用同一角色；视觉顺序与 DOM 顺序是否一致。

**必须人检**：去掉边框 / 阴影 / 底色后的层级；最坏内容；跨维度代偿；场景是否服务内容。
