# 评审建议

> 源：设计规范 §16 + §3.4 / §3.6（快照 2026-11-05）。本文件是面向 AI 的提炼，不是规范真源。
> 适用：设计评审的流程、证据、分级、报告与边界。

## 1 两条评审轨道

| 轨道 | 回答 | 判据 | 结论 |
|---|---|---|---|
| **规范评审** | 是否符合可引用、可复算的规范 | 档位、对比目标、命名、边界、状态 | `pass` / `warn` / `deviation` / `unverified` |
| **设计批评** | 是否好用、好看、清楚、有气质 | 层级、信息架构、认知负荷、情绪、工艺 | 分数 / 问题清单 / 建议 |

- 规范评审只对可引用、可复算的条款下结论；未知底标 `unverified`，不假装通过。
- 设计批评必须给证据与建议；分数不能替代规范结论。
- 风格层只进入设计批评与警告，不新增强制门槛。

## 2 评审流程

1. **定范围**：对象、平台、模式、密度、声明底、内容最坏情况。
2. **定轨道**：规范评审 / 设计批评 / 两者都做。
3. **找判据**：原则、语言、颜色、排版、空间形状、布局、表面光影、动效、状态、内容。
4. **取证据**：原值、合成后的值、实测对比度、截图、任务路径。
5. **给分级**：`pass` / `warn` / `deviation` / `unverified`；设计批评另给分数与问题清单。
6. **给最近可行档**：档位、偏差、代价；没有就写「需要项目自定义」。
7. **写风险**：未知底、模式嵌套、放大 / 窄视口 / 译文增长、热区与焦点、性能。
8. **写范围**：哪些是可评审项，哪些是项目自检或人检。

## 3 评审报告

按 [`templates/review-report.md`](../templates/review-report.md)：

- 结论
- 范围
- 判据
- 证据
- 最近可行档
- 风险
- 不在本次范围
- 建议

## 4 设计批评

设计批评不改变规范结论，只回答「好不好用、清不清楚、有没有气质」。

| 维度 | 问题 | 证据 |
|---|---|---|
| **层级** | 第一眼看到什么？是否是该看的东西？ | 截图 + 3 秒回忆 |
| **信息架构** | 分组是否合理？导航是否可预测？ | 任务路径 / 卡片分类 |
| **认知负荷** | 一屏要记多少东西？是否可以渐进披露？ | 任务步数 / 选项数 |
| **情绪 / 气质** | 是否符合品牌与场景？ | 关键词对照 |
| **工艺** | 对齐、间距、图标、文案是否一致？ | 逐项截图 |
| **原创性** | 是否像模板 / 默认审美？差异点是否有理由？ | 与常见默认对照 |

评分只做辅助：1–5 分要附证据与建议；分数不能替代规范结论，也不能用「好看」推翻可访问性。

## 5 评审边界

- **可评审范围**：设计值、派生结果、设计系统提供的配对与角色。
- **项目自检**：页面选择器、具体背景上的实际对比度、组件里的 fallback。
- **人检**：未知底、局部模式嵌套、真实字体裁切、键盘 / 读屏、强制颜色、打印、性能。
- **只给报告与建议**：本 skill 不做强制检查，也不下阻断性结论；使用者可以选择遵循，也可以选择不完全遵循。

## 6 检查证明不了什么

- 值落在档位，不等于视觉合格。
- 对比度算对，不等于真实背景、字体、设备上可读。
- 状态属性齐全，不等于读屏与键盘体验正确。
- 构图符合规则，不等于内容层级合理。
- 风格 recipe 成立，不等于品牌与场景合适。
