# 项目类型与页面角色

> 适用：判断「这类项目、这个页面先解决什么」；给倾向与权重，不给模板，也不替代结构方案。
> 与其它文档的分工：本文件回答「先解决什么」；[patterns.md](./patterns.md) 回答「怎么排」；[composition.md](./composition.md) 回答「构图维度怎么取向」；合规判断仍走 [review.md](./review.md)。

## 1 怎么用

- **先类型、后角色**：先定项目类型与当前阶段，再定页面角色；只取对应的两张卡，不填满 8 × 10 的矩阵。
- **角色优先**：类型调权重，角色定任务。同一官网的详情页也要满足详情页的基本任务；冲突时角色优先。
- **只写倾向**：卡片用「通常」「常见」「代价是」，不写「必须」「禁止」；每张卡都留「业务可自定」。
- **不按类型套页面**：类型卡里的页面清单只用于检查遗漏，不是模板；页面顺序由内容关系与目标决定。
- **类型可复合**：同时符合两类时，取最影响当前任务的一类；另一类只作为权重，不叠加卡片。例如面向老人的内容站，按内容任务取 T2，适老要求作为权重。
- **与构图场景不并列**：构图场景表是维度取向（密度、对比、留白），类型卡是任务先后。同一页面可以同时是「后台」与「仪表盘」：前者定先后，后者定取向。
- **来源只作提炼**：本文件从三档来源提炼——规则（来源明文）、条件（有适用边界）、归纳（多源综合）；写进卡片时一律降为经验，不逐条标注。平台硬限制与无障碍硬要求单独成节，不与经验混写。

## 2 类型卡

### T1 官网 / 品牌

- **目标与阶段**：获客期建立价值主张，评估期给演示与规格，决策期给证据与联系；阶段不同，首屏不同。
- **首屏**：说服型。价值主张 / 产品演示 / 社会证明三选一，并让人知道下方还有内容；给 1–4 个主任务入口与真实样例。
- **典型二级页**：产品 / 方案 / 案例 / 关于 / 联系。
- **倾向**：叙事与整幅内容优先，密度低；信任靠可核验的证据，不靠形容词；每页一个主行动，研究资料不设注册墙。
- **常见错误**：把欢迎语当价值主张；首屏做成封死的整屏；两个同等强度的主按钮；只放客户标志没有结果。
- **不适用**：品牌已有认知、单一意图投放、主要靠外部深链进入时，教育型长叙事收益下降；整页为图片、DOM 无结构时结构方案不成立，先要设计源。

### T2 门户 / 内容

- **目标与阶段**：留存与自助为主；先让人找到，再让人读完。
- **首屏**：找路型。搜索 + 1–4 个高频任务 + 更新 + 分类或 A–Z + 帮助与状态；知识库偏检索，内容站偏编辑推荐。
- **典型二级页**：分类索引 / 文章 / 无结果 / 帮助 / 错误。
- **倾向**：倒金字塔；内容可扫读；更新与责任方可见；订阅类行动不抢主任务。
- **常见错误**：用营销首屏替代任务入口；创意类目命名；文章长墙；无结果页只放推荐。
- **不适用**：站点只有一两级时，面包屑与重策展首页收益低；用户主要从外部深链进入时，页面级标题与摘要比首页更重要。

### T3 电商 / 交易

- **目标与阶段**：从浏览到下单；先送达可比较的列表，再降低结算摩擦。
- **首屏**：找路型。搜索、类目、活动位、推荐、订单入口；活动位不压过搜索与类目。
- **典型二级页**：商品列表 / 搜索结果 / 商品详情 / 购物车 / 结算。
- **倾向**：中高密度；便于视觉比较；筛选要让用户知道当前条件；结算字段优先于步骤数；访客可结账。
- **常见错误**：价格或库存要滚很远；筛选没有已选概览；强制注册；错误只在顶部提示。
- **不适用**：B2B 报价、订阅、配置器、高客单商品；这些更像「方案 + 表单」，列表与结算经验不成立。

### T4 工具 / 效率

- **目标与阶段**：快速完成任务；首次使用与熟练使用要分开。
- **首屏**：找路型（任务入口变体）。继续 / 最近 / 新建优先，再给待办与指标；运营型看板实时可行动，分析型看板日更供判断。
- **典型二级页**：编辑器 / 列表 / 设置 / 空态。
- **倾向**：低装饰、高内容；高频操作随手可达，低频能力二次披露；入口要能快速回到工作。
- **常见错误**：首屏铺满能力；设置无分组；渐进披露藏掉高频路径；空态只写「暂无」。
- **不适用**：专家高频路径、复杂编辑器在移动端；移动端只做查看、轻编辑与审批。

### T5 社区 / UGC

- **目标与阶段**：持续供给内容与互动；冷启动期重创作与推荐，成熟期重回找与关系。
- **首屏**：找路型（信息流变体）。内容 + 一键创作；常见五栏：首页、发现、发布、消息、我；入口不承担全部功能。
- **典型二级页**：信息流 / 详情 / 发布 / 搜索 / 个人 / 设置。
- **倾向**：互动可达，不藏成不可见手势；切换栏目后能回到原处；浏览适合连续流，回找或比较改分页。
- **常见错误**：返回丢位置；手势与系统返回冲突；错误只靠颜色；内容质量缺失时仍加密度。
- **不适用**：找特定内容、比较长列表、强关系链产品；这类首页未必是信息流。

### T6 后台 / 管理

- **目标与阶段**：处理数据与任务；日常运营与异常处理优先于探索分析。
- **首屏**：找路型（待办变体）。待办与异常优先，指标次之；运营型看板一眼可判、可行动。
- **典型二级页**：列表 / 详情 / 审批 / 设置。
- **倾向**：高密度优先；列表任务是一眼扫过再进详情或就地处理；批量动作随手可用；筛选与搜索状态可见。
- **常见错误**：卡片替代高密度列表；工具栏堆满动作；加载中写成「无记录」；无权限只隐藏入口不给原因。
- **不适用**：探索式分析、移动端重度操作；这两类改用分析视图或桌面主操作台。

### T7 游戏 / 娱乐

- **目标与阶段**：沉浸与节奏；新手引导、日常循环、活动期的节奏不同。未做专门调研，以下只作方向提示。
- **首屏**：沉浸优先（例外，不套入口两型）。主视觉与当前活动优先，任务入口让位；不据此定固定页面清单。
- **典型二级页**：不列固定清单；按角色卡自行映射，本类型只提示沉浸与节奏。
- **倾向**：专用展示优先于通用列表；动效与反馈承担节奏；关键数值与奖励要可读，不被氛围盖住。
- **常见错误**：把后台表格直接搬进游戏；动效盖过可读性；活动入口压过主循环。
- **不适用**：信息密度高的管理或阅读场景；专用记分 / 对局界面结构自由度低，硬套方案库会产出空话。

### T8 公共服务 / 适老

- **目标与阶段**：看懂并办成；一次办结优先，学习成本其次。
- **首屏**：找路型。服务清单或搜索 + 分类；显著的长辈版入口，并同步搜索别名；不把服务埋进多层导航。
- **典型二级页**：服务详情 / 表单流程 / 结果页 / 帮助 / 错误。
- **倾向**：低密度、大版块、少装饰；一页一问；错误要能定位到具体字段；结果页给凭证与下一步。
- **常见错误**：一页塞多个问题；只靠星号标必填；错误只变红；线上是唯一渠道却未达无障碍要求。
- **不适用**：高密度表格与图表场景；线性放大不能解决密集数据，需另给替代视图。

## 3 角色卡

### R1 入口

- **要回答**：我现在该做什么。
- **必需元素**：主任务入口（1–4 个）、搜索或找路、当前状态、下一步。
- **常见结构**：说服型（价值主张 + 证据 + 主行动）/ 找路型（搜索 + 高频任务 + 更新 + 分类；含任务入口、信息流、待办等工作台变体）；同一入口只选一型为主；沉浸型按类型卡例外处理，不强行归入两型。
- **对应条目**：S3、S4、S10、S16。
- **平台差异**：移动端单栏、主行动常驻；桌面端可多列与常驻导航；小程序入口受标签栏与包体约束。
- **常见错误**：欢迎语代替任务；入口承担全部功能；两个同等主行动。
- **业务可自定**：入口数量、是否放推荐、是否个性化。

### R2 索引 / 列表

- **要回答**：有哪些、怎么筛、怎么进详情。
- **必需元素**：条目、数量或范围、筛选与搜索、已选条件、进入详情或就地操作。
- **常见结构**：行 / 卡 / 块；分组或不分；表格用于多属性比较。
- **对应条目**：S3、S4、S5、S6、S11。
- **平台差异**：移动端筛选进抽屉、条目操作收进选择态；桌面端筛选常驻、批量在工具栏。
- **常见错误**：筛选无已选概览；卡片替代高密度列表；同类条目元素位置不一致。
- **业务可自定**：密度、分组、每页数量。

### R3 搜索与无结果

- **要回答**：有没有、条件对不对、怎么改。
- **必需元素**：原查询、结果数、筛选条件、无结果原因、放宽条件或可浏览路径。
- **常见结构**：结果列表 + 筛选；无结果单独一态，不混入推荐。
- **对应条目**：S5、S11（无结果与首次为空分开）。
- **平台差异**：移动端搜索置顶、历史可见；桌面端筛选常驻。
- **常见错误**：把推荐当结果；清空查询；只说「没有找到」不给出口。
- **业务可自定**：是否给近义建议、是否保留历史。

### R4 详情 / 产品页

- **要回答**：这是什么、能不能用、下一步做什么（只读详情可以没有下一步）。
- **必需元素**：名称与价值句、关键属性、状态或可用性、证据、主行动或明确出口、次要信息。
- **常见结构**：头部摘要 + 分区 + 末尾折叠；主辅并置或独立页。
- **对应条目**：S1、S2、S7、S15。
- **平台差异**：移动端单栏、返回只在详情屏；桌面端可主辅并置。
- **常见错误**：只读详情硬塞主行动；关键属性折进折叠；主行动在长页末尾；规格与图脱节。
- **业务可自定**：分区顺序、证据形态。

### R5 内容阅读

- **要回答**：读得下去、看得懂、找得到下一段。
- **必需元素**：标题即答案、摘要、描述性小标题、正文、更新信息、相关入口、反馈。
- **常见结构**：单栏窄容器；侧栏目录或折叠目录；系列导航。
- **对应条目**：S2、S15；行宽与行高走对应维度文档。
- **平台差异**：移动端单栏、目录折叠；桌面端侧栏常驻。
- **常见错误**：长墙无小标题；脚注承载关键信息；标题写成问题却不回答。
- **业务可自定**：行宽、是否给目录。

### R6 表单 / 流程

- **要回答**：填什么、错在哪、能不能中断。
- **必需元素**：进度或步骤、字段说明、必填表达、错误摘要与字段提示、暂存或退出、提交结果。
- **常见结构**：一页一问 / 单页分组；汇总 + 字段两处错误。
- **对应条目**：S9、S12、S14。
- **平台差异**：移动端底部固定提交、少字段；桌面端可分组并排，但长文本不并排。
- **常见错误**：一页多问；只顶部报错；必填只靠星号；错误后清空输入。
- **业务可自定**：步骤拆分、是否可暂存。

### R7 账户 / 设置

- **要回答**：改什么、影响什么、如何撤销。
- **必需元素**：分组、当前值、影响说明、保存与撤销、危险操作分离。
- **常见结构**：按任务分组的长页 / 分组入口 + 独立页。
- **对应条目**：S4、S9、S14。
- **平台差异**：移动端分组入口进独立页；桌面端可侧栏分组。
- **常见错误**：无分组长表单；保存后无反馈；危险操作与主行动相邻。
- **业务可自定**：分组粒度、即时保存或显式保存。

### R8 专题 / 方案 / 案例

- **要回答**：为什么现在看、和我像不像、下一步是什么。
- **必需元素**：主题或客户、起点与问题、做法、可核验结果、引语或证据、下一步；方案页另需按用户自我识别分群。
- **常见结构**：整幅内容 + 分区叙事；方案索引 + 方案详情；案例索引 + 案例详情。
- **对应条目**：S16、S10、S7。
- **平台差异**：移动端单栏、证据后置；桌面端可并置证据与正文。
- **常见错误**：只放标志墙；不可核验的奖项；按组织架构而非用户自我识别分群。
- **业务可自定**：证据形态、是否给筛选。

### R9 状态页

- **要回答**：现在是什么状态、能不能恢复、去哪里。
- **必需元素**：状态说明、原因、影响范围、恢复动作或出口、联系路径。
- **常见结构**：首次为空 / 条件未就绪 / 无结果 / 无权限 / 出错 / 加载中；几态文案分开。
- **对应条目**：S11、S13、S14。
- **平台差异**：移动端动作只留一个；桌面端可给替代路径与详情。
- **常见错误**：加载中写成无记录；无权限只隐藏入口；错误只给代码。
- **业务可自定**：插画、是否给自助修复。

### R10 帮助 / 联系

- **要回答**：找不到时去哪、问谁、多久有回应。
- **必需元素**：可搜索的帮助入口、按任务组织的步骤、联系渠道、服务时间与时区、真人或自动应答、响应预期。
- **常见结构**：帮助中心 + 联系页；文章 + 反馈；转人工出口。
- **对应条目**：S2、S9、S11。
- **平台差异**：移动端优先电话或即时渠道；桌面端可给完整表单与知识库。
- **常见错误**：按产品模块堆文档；只给表单不给电话；联系方式藏在关于页下。
- **业务可自定**：渠道优先级、是否给在线客服。

## 4 平台运行时约束

这些是平台行为，不是设计偏好；开工前先确认，避免设计完成再返工。

| 平台 | 约束 | 影响 |
|---|---|---|
| 小程序 | 标签栏页必须在主包；页面跳转不能指向标签栏页；单包与总量有体积上限；授权随用随申请，拒绝后要走失败分支 | 入口层级与包体在开工前定；不能等设计完成再拆包 |
| iOS / Android | 底部标签 3–5 个平级，iPadOS 可转侧栏；返回与系统手势要避让；安全区要预留 | 入口形态与返回路径；底部操作不压安全区 |

## 5 规范硬要求

这些是标准写的硬要求，用来检查；不是本文件自造的规则，也不下阻断结论。

| 来源 | 硬要求 | 用法 |
|---|---|---|
| WCAG 2.2 | 1.4.3 正文 4.5:1、大字 3:1；1.4.11 控件与状态 3:1；2.4.7 焦点可见；2.5.8 触控目标最小 24px | 原生 App 不直接套用 WCAG；按适用场景取用 |
| 国内适老条款 | 更大的字号与行距、更大的热区（建议 60 × 60）、禁用多指手势、限制诱导性广告与按钮 | 与 WCAG 分列；不把两套数值混成一套 |
| 跨体系换算 | 触控目标分别来自 Web、平台、适老三个体系，不能互换 | 按适用体系分别取值；不把某个数字当通用值，也不取最大值当通用值 |
| 性能指标 | LCP / INP / CLS 用于检查真实用户的首屏与交互 | 是检查指标，不是设计值；重媒体页先算结构成本 |

## 6 适老与无障碍：经验与写法

- **硬要求**：见第 5 节；这里不重复数值。
- **经验**：结构熟悉、步骤清楚、可撤销、不依赖记忆、一次少给信息。这些是条件性经验，不做阻断结论。
- **写法**：硬要求只出现在第 4–5 节；类型卡与角色卡只写经验，避免把无障碍降成风格偏好。
- **失效**：WCAG 面向 Web 内容，原生 App 不直接适用；线性放大遇到密集表格与图表不成立，需替代视图。

## 7 组合与输出

1. 先取类型卡与阶段，再取角色卡；只取两张，不填满矩阵。
2. 类型调权重，角色定任务；冲突时角色优先。
3. 再进 [patterns.md](./patterns.md)：类型与角色决定「先解决什么」，S 条目决定「怎么排」，五项代价说明换掉了什么。
4. 输出加一节「类型与角色对照」：类型 / 阶段 / 角色 / 本次先解决的 1–2 件事 / 不适用项。
5. 角色卡里的「业务可自定」必须保留在输出里，不替业务做默认决定。
6. 类型卡不是模板：清单只用于检查遗漏，不按类型直接套页面。

## 8 来源与边界

- **对照的公开材料**：公开设计体系（政府服务、电商后台、移动平台）、可用性研究、平台开发文档（小程序）、无障碍标准与国内适老条款。
- **只取结构、条件与失效边界**：不复制文案、截图或视觉资产；研究里的比例数字不写入。
- **三档证据只用于标注来源**：写进建议时一律降为经验；平台约束与规范硬要求单独成节。
- **未取得或不可靠的内容不写**：抓取失败的页面、二手清单、单品牌案例、把某平台规范当跨产品定律。
- **边界**：不覆盖营销首屏叙事、导航与信息架构、多步流程的具体编排；这些走构图、结构方案，或直接标「不在范围」。
