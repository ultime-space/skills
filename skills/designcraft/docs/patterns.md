# 结构方案库

> 适用：内容与结构已定，需要换一种排法看效果的场景；给出多种结构、各自的代价与偏好开关，不判定合规。
> 与其它文档的分工：`layout.md` 回答「有哪些构图模式、容易在哪失效」；本文件回答「同一份内容可以换成哪几种结构、各付什么代价」。合规判断走 [`review.md`](./review.md)。

## 1 三个维度

方案不是从页面类型里挑的，是从三个维度推出来的。

### 1.1 内容关系（决定可选结构的上限）

| 关系 | 判断依据 | 常见结构 |
|---|---|---|
| **单条对象** | 一个实体，多个属性或分组 | 详情页分层、披露位置 |
| **同构集合** | 多条结构相同的条目 | 行 / 卡 / 块、分组 |
| **比较集合** | 需要跨条目比数值或状态 | 表格、列优先、堆叠 |
| **主辅** | 次要内容只在选中主内容时才有意义 | 并置、独立页面 |
| **序列** | 条目有先后、历史或步骤 | 时间线、步骤条、分段带 |
| **录入** | 用户按字段填写 | 标签位置、栏数 |
| **异构聚合** | 一屏放多种不同类型的块 | 等权网格、主轴 + 次轴、问题分区 |

关系判断错，后面选什么结构都不成立：把比较集合当同构集合，会做成卡片墙然后失去可比性。

判定顺序：先看有没有跨条目对照数值或状态的需求——有就是比较集合；没有再看是不是同类条目重复（同构集合）；一个对象多组属性是单条对象；其余按主辅、序列、录入、异构聚合判断。

一页可以有多组关系：各组分别判断，在输出里列出；不要为了归成一个关系而合并语义不同的块。

### 1.2 决策变量（决定选哪一档）

- **目标**：找（locate）、比（compare）、扫（scan）、读（read）、填（fill）。
- **字段数与描述长度**：单行、两句、长句，直接决定行与卡能不能用。
- **条目数量**：少到可以主推，多到只能压缩。
- **容器宽度**：按容器算，不按设备名算。
- **数据状态**：正常、空、无结果、不可用、加载中、部分失败。
- **变更频率与位置保持**：刷新时是否需要留在原位。

### 1.3 可动的结构量（方案卡里实际改的东西）

| 量 | 可选值 |
|---|---|
| 容器形态 | 行（单行条目）、卡（独立容器）、块（等宽视觉单元）、区（带标题的分区）、表（行列）、轴（时间或步骤） |
| 列数与方向 | 单列、双列、三列；横排、纵排 |
| 分组 | 无、组标题、折叠组 |
| 主次 | 等权、主轴 + 次轴、强弱阶梯 |
| 密度 | 一行可容纳的信息量 |
| 披露层级 | 全部展开、摘要 + 展开、摘要 + 独立页 |
| 位置 | 就地、独立页面、并置侧栏 |

### 1.4 代价只记五项

| 代价 | 问什么 |
|---|---|
| **可比较性** | 跨条目对照还能不能做 |
| **一屏信息量** | 用户一屏能看到几条 |
| **定位成本** | 找到某一条要走几步 |
| **最坏内容风险** | 最长文案、空数据、译文增长时是否塌掉 |
| **一致性** | 同类单元、同类操作在页内与页面族内是否同位置、同形态 |

一份数据有多套正确答案，本质是这五项在换。方案卡必须写出换掉了什么，只说「更好看」不算。

**可以标「不适用」**：营销页、单条详情这类没有跨条比较的场景，可比较性与定位成本可能整项落空；如实写「不适用」，不为了凑满五项而编造影响。

**一致性的两种**：页内混用两种形态（例如一组宫格、一组横条）是**代价**，可以换；同类操作在页面族里换位置，建议保持并说明差异——这是使用者的决定，不是硬规则。一致性默认只评页内；只有输入提供了同族页面时才评跨页，否则写「仅页内」，不凭空推测。

## 2 结构方案

每条给：适用条件、结构、代价、反例、窄屏行为、偏好开关。编号用 S，避免与其它编号体系混读；编号按加入顺序，不表示优先级：S1–S10 结构关系，S11–S13 状态姿态，S14–S16 结构与内容适配。

范围边界：官网 / 落地页的首屏叙事、故事顺序与主视觉占比不在本库范围；对这类页面只给单元形态、分区与密度建议，不给叙事结构结论。

### S1 详情页分层

- **适用**：一个对象有 5 个以上属性，能分成 2–4 个语义组；页面有 1 个主动作。
- **结构**：头部（对象名、状态、主动作）→ 摘要区（3–5 个最能决定判断的键值，横向并排）→ 分区（每组小标题 + 键值或短列表，组间靠间距分，不靠框）→ 末尾（次要属性、历史、关联对象，默认折叠）。
- **代价**：分区越多滚动越长；键值对齐要求统一标签列宽，否则左侧参差；摘要选错字段，用户必须滚动才能判断。
- **反例**：属性少于 5 个仍分区；摘要与分区重复同一批字段；主动作放在长页底部；用折叠隐藏判断必需的信息。
- **窄屏**：键值由两列改为标签在上、值在下；主动作移到页面底部固定栏；分区标题可吸顶。
- **偏好**：判断靠少数关键值 → 摘要加厚；判断靠完整信息 → 摘要压薄、分区提前。

### S2 长内容的披露位置

- **适用**：单条内容里有会超过一屏的段落或多组信息；多数用户只需要结论。
- **结构**：三选一——就地展开（摘要 + 展开，展开后原位替换摘要）、独立页面（摘要 + 查看全部，返回回到原条目）、并置侧栏（宽屏辅栏，窄屏改为独立页面）。
- **代价**：就地展开把后面的内容推走，连续阅读被打断；独立页面多一次导航与返回；并置占宽，主内容变窄。
- **反例**：两级以上折叠；把判断必需的信息藏在折叠里；展开入口写成「更多」这类无指向文案。
- **窄屏**：并置一律退为独立页面；就地展开后高度超过约两屏时改独立页面。
- **偏好**：需要对照上下文 → 并置；偶尔看一次 → 就地；内容自带章节 → 独立页面。

### S3 同构集合的单元形态与密度

- **适用**：3 条以上结构相同的条目，字段固定，描述不超过一句。
- **结构**：三档；列数要与组内条目数整除（或最后一格用等宽占位），否则最后一行留空位。

```text
A 行      B 卡（两列等高）   C 块（两到三列，可加组标题）
[图] 标题  ┌──────┐          ┌──────┐
     副标  │ [图] │          │ [大图]│
           │ 标题 │          │ 标题 │
           │ 副标 │          │ 副标 │
           └──────┘          └──────┘
```

- **代价**：A 一屏条数最多但视觉平，缺少停顿；B / C 一屏条数约为 A 的一半，副标题换行会撑破等高网格；C 的图标权重最高，条目不重要时显得空。
- **反例**：条目要横向比对两个以上字段（改用表格）；副标题是长句（用列表加披露）；只有 3–4 条却铺三列，留下大片空白。
- **窄屏**：B 退为单列卡或行距更大的行；C 降为两列或单列；A 不变。
- **偏好**：目标是快速定位 → A；要入口感与分组 → B；只有少数条目需要被主推 → C。比效果（视觉选择）→ 图先于名称；按名称找 → 名称先于图。

### S4 集合的分组

- **适用**：集合有 2–5 个稳定类目（类型、时间、状态、归属）。
- **结构**：组标题（小标题 + 上下间距）+ 组内条目；组间不加框、不加分隔线；类目多时组标题可折叠；组内只露前几条时给「查看更多」，否则类目只剩封面。
- **代价**：组标题吃纵向空间；组内只有 1–2 条时分组显得多余；折叠会把内容藏起来，需要用户主动展开。
- **反例**：类目由数据动态生成且数量不定（分组会不断变长）；组内差异大于组间差异（分组没有解释力）；用分组代替排序。
- **窄屏**：组标题吸顶，随滚动替换；组多时提供锚点列表。
- **偏好**：类目是用户心智里的切分 → 分组；只是数据属性 → 平铺加排序。

### S5 表格与卡片列表的取舍

- **适用**：需要在条目之间横向比较，或需要容纳长度不一的描述。
- **结构**：表格（表标题说明这张表是什么、稳定列序、数字右对齐）；卡片列表（每条一卡，字段纵向排列）。
- **代价**：表格列多时需横向滚动或缩字；卡片列表失去跨行比较，但能容纳长文本与不等长内容。
- **反例**：用表格做页面布局；把表格数据做成卡片网格后仍声称可比较；列多到需要横向滚动仍不拆分、不分层。
- **窄屏**：见 S6，同一条数据只选一种退法。
- **偏好**：比较数值 → 表格；浏览对象、找入口 → 行或卡片；两者都要 → 表格加行内展开。

### S6 多列数据的窄屏退法

- **适用**：多列数据，容器宽度小于表格所需宽度。
- **结构**：三选一，同一条数据只选一种。

```text
① 滚动壳            ② 列优先               ③ 堆叠卡
[表头固定]          [关键 2–3 列 + 展开]    [每条一卡，键值纵排]
[········→]         [其余列进详情]          [失去列对齐]
```

- **代价**：① 右侧列默认不可见，用户不知道还有列；② 丢掉次要列，可比较范围缩小；③ 完全失去跨行比较。
- **反例**：报表、对账类界面用 ③；按设备名而不是容器宽度决定降级点；降级后保留表头样式却没有列对齐。
- **窄屏**：三种退法本身就是窄屏行为，切换点由容器宽度决定。
- **偏好**：必须逐行比较 → ①；列重要性分层明显 → ②；只需逐条查看 → ③。

### S7 主辅并置与退法

- **适用**：次要内容只在主内容被选中时才有意义（列表与详情、正文与注释、编辑与预览）。
- **结构**：宽屏双栏（主宽辅窄，辅栏独立滚动）；中屏只留主内容，详情进独立视图；窄屏单栏加返回。
- **代价**：并置时主内容变窄；中屏失去并置比较；返回路径必须显式，不能只靠手势。
- **反例**：窄屏把两栏压成各占一半；返回同时承担「关闭」和「回上一级」；主内容为空时辅栏仍占位。
- **窄屏**：单栏加返回；选中态只在双栏出现，单栏用进入与返回表达。
- **偏好**：频繁来回切换 → 并置；低频查看 → 独立页面。

### S8 序列结构

- **适用**：条目有先后、历史或步骤语义。
- **结构**：三选一——时间线（单轴 + 时间列 + 内容列）、步骤条（固定顺序 + 当前步 + 完成态）、分段带（按时间块分组，块内平铺）。
- **代价**：轴占横向；步骤条暗示顺序唯一，可乱序时会误导；分段带在数据稀疏时出现大量空白。
- **反例**：时间只是排序不是语义，仍画轴；可乱序的步骤做成线性步骤条；完成项与未完成项权重相同。
- **窄屏**：轴左移，时间改到条内首行；步骤条横向滚动或改为纵向列表。
- **偏好**：要读过程 → 时间线；要引导完成 → 步骤条；要快速扫 → 分段带。

### S9 表单的标签位置与栏数

- **适用**：3 个以上字段的录入界面。
- **结构**：标签位置三选一——标签在字段上方（默认）、标签在左（字段短、数量少、宽屏）、占位符代替标签（仅当含义无歧义且字段极少）。栏数默认单列；只让成对且互不依赖的字段并排（如起止日期），并排后两列等宽。
- **代价**：标签在左要求统一标签列宽，译文变长会挤压输入区；标签在上更占纵向；占位符作标签时输入后标签消失。
- **反例**：用占位符承载必填说明；把长表单做成两列以「省空间」；并排字段的错误提示挤成一团。
- **窄屏**：一律单列、标签在上；用分区标题分组，不用分栏。
- **偏好**：字段多、纵向快速填写 → 标签在上单列；字段少、宽屏、横向对照 → 标签在左。

### S10 异构卡片的聚合

- **适用**：一屏要放 6 个以上不同类型的块（指标、图表、列表、快捷入口）。
- **结构**：分组依据先按用途（要行动 / 要观察），再看数据来源；同一来源但用途不同应拆开。聚合方式三选一。

```text
① 等权网格        ② 主轴 + 次轴        ③ 问题分区
[ ][ ][ ]         [   主块   ][次]     组一 ───────
[ ][ ][ ]         [   主块   ][次]     [ ][ ][ ]
                  [   主块   ][次]     组二 ───────
```

- **代价**：等权网格没有主次，用户不知道先看哪个；主轴布局在窄屏重排后主块可能落到最后；问题分区产生空白。
- **反例**：总览数字与明细块同尺寸；把状态色当类别色；窄屏重排后顺序与重要性不一致。
- **窄屏**：主轴降为单列且主块置顶；等权网格降为两列或单列；问题分区保留组序。
- **偏好**：判断依赖一个总览数 → 主轴；块之间平权 → 等权；块属于不同问题 → 问题分区。

## 3 状态姿态

状态语义见 [`states.md`](./states.md)；这里只讲同一状态可以怎么摆。

### S11 空态的四种语义

- **适用**：集合为空、筛选无结果、内容不可用。
- **结构**：四选一——首次为空（说明这里会出现什么 + 一个创建动作，可选插画）、筛选无结果（说明当前条件 + 清除或放宽）、条件未就绪（说明缺什么 + 最小动作，如选区域、登录）、不可用（说明原因 + 重试或求助）。
- **代价**：四态共用一套文案会误导；插画占位大，动作容易被推到首屏之外。
- **反例**：空态里塞推荐内容抢占主动作；用插画代替原因；搜索无结果仍写「还没有数据」。
- **窄屏**：文案一到两句，动作只留一个，不堆叠次要链接。
- **偏好**：用户能自己解决 → 给动作；不能解决 → 给原因与出口。

### S12 表单错误的两处呈现

- **适用**：字段 3 个以上，提交后可能多处失败。
- **结构**：顶部汇总（失败数量 + 每条锚点到字段）与字段旁说明同时出现，两处用同一句文案。
- **代价**：汇总占位，滚动后不可见；同一句写两遍，措辞不一致时更混乱。
- **反例**：只在字段旁报错，长表单看不到全局；只在顶部报错，用户要自己找；用颜色代替文字。
- **窄屏**：汇总放在标题下方，提交后焦点移入汇总；字段说明跟随字段换行。
- **偏好**：一次提交多处失败 → 两处都给；单字段失败 → 字段级即可，汇总可省。

### S13 加载姿态

- **适用**：首屏数据加载、局部刷新、耗时不可预期的操作。
- **结构**：三选一——骨架（结构与最终内容一致）、进度（可取消、给剩余量）、保留旧内容（局部刷新时弱化旧内容而非清空）。
- **代价**：骨架形状猜错会让人误判布局；没有真实进度的进度条是假信息；保留旧内容需要明确的「正在更新」标记。
- **反例**：用循环装饰动画代替进度；加载遮住整页导航；局部刷新先清空再填。
- **窄屏**：骨架只保留主要块，不逐行复刻；进度与取消同屏可见。
- **偏好**：结构可预期 → 骨架；时长可预期 → 进度；内容已存在 → 保留旧内容。

## 4 结构与内容适配

形态不只要跟数据量匹配，还要跟「同一位置会换内容」和「内容长度不可控」这两件事匹配。

### S14 条件块与互斥结构

- **适用**：同一位置在不同身份、状态或权限下显示不同内容（推广 / 非推广、已绑定 / 未绑定、有 / 无权限）。
- **结构**：三选一——同骨架换内容（同一标题位、同一边距，只换内部字段与主行动）、整块替换（整幅图或另一种卡，需固定高度）、条件消失（不占位，后续内容上移）。
- **代价**：同骨架需要抽象出共同字段，设计成本最高但布局最稳；整块替换会造成跳动与位置记忆失效；条件消失省空间，但会让人怀疑内容丢了。
- **反例**：同一位置一边是三指标卡、一边是整幅图片；两块高度差很大却不留最小高度；切换后主行动换了位置。
- **窄屏**：两套结构都要能在窄容器成立；整块替换时给容器最小高度，避免切换跳动。
- **偏好**：字段大体同构 → 同骨架；纯运营曝光 → 整块替换但定高；低频条件 → 可消失，保留间距。

### S15 长文本的容器分配

- **适用**：自由文本（简介、说明、备注）与结构化字段同屏。
- **结构**：三选一——不进网格（长文本整行，结构化字段仍两列）、就地折叠（三行 + 展开）、独立页面（摘要 + 查看全部）。
- **代价**：整行占高度；折叠需要入口与展开状态；独立页多一次跳转。
- **反例**：长文本塞进等宽键值格或表格列；截断却不给查看全文；表格列宽被内容撑开导致横向抖动。
- **窄屏**：一律整行，不并排；表格降为堆叠卡时，长文本放在键值下方。
- **偏好**：长文本本身是判断依据 → 整行或折叠；只是补充说明 → 独立页。

### S16 整幅内容的放置

- **适用**：不可拆分的内容块——运营图、广告、视频、嵌入表单；改变宽度或裁切会失真。
- **结构**：三选一——集中段（所有整幅块收进一段，放在功能段之后）、带尾单次（每个分区末尾最多一张）、横向序列（同组整幅块横向滑动，露出当前与下一张）。
- **代价**：集中段拉长页面，功能区与运营区被明确分开；带尾单次让每个分区都变长；横向序列牺牲同屏对照，增加滑动。
- **反例**：把整幅图塞进卡片或网格，形成卡内卡；同一屏放三张以上整幅块；把整幅块插在两个相邻功能块之间。
- **窄屏**：本身就是窄屏形态；同屏整幅块数量随页面视觉重量下降，视觉越重越少。
- **偏好**：运营为主 → 集中段；功能为主 → 带尾单次；数量多且同质 → 横向序列。

## 5 页面族约定（参考）

同类页面、同类操作尽量固定在同一槽位。这是参考，不是硬性规则：项目可以自定，Refine 只做提示，不替使用者裁决。

适用范围：列表型、表单型的管理端与移动页。官网、单条详情、游戏页没有这些槽位，不套用本表。

| 槽位 | 管理端 | 移动端 |
|---|---|---|
| 页面级新增 | 列表页工具栏右端 | 列表页底部主行动 |
| 批量操作 | 表格上方，紧邻筛选 | 长按或选择态后出现在底部 |
| 条目级操作（编辑 / 删除） | item 内固定一端（默认右端） | item 卡片内固定位置（页眉或页脚，二选一并全站统一） |
| 筛选 / 搜索 | 列表页顶部 | 列表页顶部，吸顶 |
| 表单提交 | 弹窗页脚右端 | 页面底部固定栏 |
| 危险操作 | 与主行动分离，不紧邻 | 二次确认，不与主行动并排 |

用法建议：

1. 同类页面用同一槽位；要换就整族一起换，避免逐页漂移。
2. 同一页的同类单元用同一位置，少因数据多少而改变。
3. 有选择时，主行动最好能看出作用于哪一项（例如按钮写明当前选中项）。
4. 与本页既有约定不同时，标出差异与影响范围，由使用者决定是否接受。

槽位表和规则都不是门槛：项目可以自定，Refine 只做提示，不替使用者裁决。本文件的条目处理单页结构；跨页问题只检查与提示，不在这里重排全站。

## 6 组合与冲突

一屏通常同时用到 2–3 条：详情页 = S1 分层 + S2 披露 + S12 错误；列表页 = S3 单元 + S4 分组 + S11 空态。

冲突按目标裁决，不按「哪条更现代」：

| 冲突 | 裁决 |
|---|---|
| S3 卡片 vs S5 表格 | 要比较用表格；卡片不能承载比较 |
| S4 分组 vs S10 问题分区 | 类目切分用 S4；不同问题域用 S10 |
| S1 摘要 vs S2 折叠 | 判断必需的信息进摘要，不进折叠 |
| S6 滚动壳 vs 堆叠卡 | 报表用滚动壳或列优先；对象列表可用堆叠卡 |
| S14 条件块 vs S10 聚合 | 同位置按身份切换用 S14；多个块同时并存用 S10 |
| S15 长文本 vs S1 摘要 | 长文本不进摘要；摘要只放短键值 |
| S16 整幅块 vs S10 聚合 | 整幅块不参与聚合网格，只决定放在哪一段 |

**共同约束**（正文在各自文档，此处只引用）：分组靠间距不靠框；一个区域一个主动作；视觉顺序不改变 DOM 顺序；最坏内容必须成立。
