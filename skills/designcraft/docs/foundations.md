# 设计基础：原则、语言、流程

> 适用：设计任务的前置判断、维度选择、评审与输出。

## 1 设计原则

只保留与视觉、交互、信息设计直接相关的原则。

| # | 原则 | 一句话 | 检查 |
|---|---|---|---|
| P8 | **反馈先于装饰** | 动效表达状态变化和因果；没有信息量的动画不做 | 去掉动效，状态还能理解吗 |
| P9 | **横切不可后补** | 可访问性、性能、韧性、安全在每一层都要成立 | 键盘 / 读屏 / 对比度 / 触控过吗 |
| P10 | **骨架先于边界** | 可见边界可以省，空间骨架与结构槽位不能省 | 去掉可见边界后布局是否仍成立 |
| P11 | **两极完整** | 有轻就有重、有快就有慢、有大就有小、有深就有浅 | 这条轴的另一极在哪 |
| P12 | **看得见就进内核** | 影响视觉的进内核；进内核必须有轴、有极、有命名、有合同。进内核 ≠ 默认启用 | 它落在哪条轴上 |
| P13 | **先找不变量** | 两端不能相等时，换一个守恒量；结构对称优先于数值对称 | 两端「同一个数」是什么 |
| P14 | **物理先于样式** | 阴影 / 高光 / 层级按 3D 光学计算；动效按距离、面积与因果选时长 | 光从哪来？物体在第几层 |
| P15 | **无档可依时用倍数** | 没有正好对应的档，用已有档的整数倍，并写明「哪一档 × 几」 | 这个值是哪一档的几倍 |
| P16 | **数字要能算回去** | 关键数值由约束推导，或引外部出处；两样都没有就是还没找到约束 | 这个数能写成谁的函数 |
| P17 | **归约** | 能被下层算出来的，就不留在上层；新增抽象先证明下层表达不了 | 下层已有机制能表达它吗 |
| P18 | **自描述优先** | 元素或代码自身能表达的不再加说明文字或复述式注释；说明只补自身表达不了的信息 | 删掉说明 / 注释后，读者还能正确理解吗 |

> P9 在设计语境只展开可访问性分支；P12 的「内核」在设计语境读作「系统」。
> P18 的边界：可访问名称、错误原因、空态下一步、数据来源与时间，是元素自身无法表达的信息，不能以自描述为由删掉。

**占位恒定**：状态不改变元素在布局中的占位、不引起重排；允许小幅、不触发重排的视觉变形。

**P10 的退化检查**：去掉描边、底色、阴影后，元素仍要占位正确、文字不贴边、相邻单位不互相挤压。圆角属于骨架，不属于装饰；大圆角必须做内容避让。

**P11 / P13 的对称检查**：每条变化轴两端齐全；两极不必相等，先找能严格对称的维度；不能时换守恒量；再不能时写明谁让位（数值让位、结构不让位）。

**P16 的出处分级**：

| 级 | 出处 | 例 |
|---|---|---|
| 强 | 可推导 | 文字档明度由 4.5:1 反解；卡片宽由容器与间距计算 |
| 中 | 标准 / 研究 / 产品 | WCAG、平台目标尺寸、产品字阶 |
| 弱 | 行业惯例 | `cols` / `span`、`h1`–`h6`、原生标签 |

## 2 设计语言

### 2.1 一个设计值回答四个问题

- **名字**：稳定、可读、可引用。
- **角色**：这个值是干什么的（主文字、卡片内衬、浮层面…）。
- **值**：具体的尺寸、颜色、时长、比例。
- **约束**：两端、对比目标、适用范围、失效条件。

### 2.2 设计维度

| 维度 | 回答什么 | 本 skill 文档 |
|---|---|---|
| 颜色 | 用哪个色、能不能读、深浅怎么配对 | `color.md` |
| 排版 | 用哪一档字、什么角色、怎么换行 | `typography.md` |
| 空间与形状 | 隔多远、多大、多圆、有没有边界 | `space-shape.md` |
| 表面与材质 | 面是什么、半透明怎么用、块怎么分 | 后续 `depth.md` |
| 光影 | 光从哪来、离底面多远、深色怎么读 | 后续 `depth.md` |
| 动效与反馈 | 变的时候怎么动、动多久、怎么停 | 后续 `motion.md` |
| 交互状态 | 现在是什么状态、状态怎么被感知 | 后续 `states.md` |
| 布局与构图 | 页面怎么排、空间怎么分、怎么换行 | `layout.md` |
| 数据色、图形与内容 | 数据怎么区分、图标怎么用、文案怎么说 | 后续 |
| 组合与风格 | 这些维度怎么组合成一种气质 | 后续 |

### 2.3 值与角色

- **原料值**：直接从尺度上取的值，如 16px、1.6 行高、300ms。
- **语义角色**：把原料值按用途命名，如正文、卡片内衬、浮层面。
- **角色稳定，值可调**：同一角色在不同项目可以指向不同原料值，但语义不变；不要用值当角色名。
- **角色只引用或组合原料**，不复制值；别名只做指针。
- **放哪**：两个以上场景共用、换主题也不能变的用途 → 角色；只属于某个组件内部的 → 组件内部约定。

### 2.4 模式与密度

- **模式**：浅色、深色、局部模式。局部模式块的根必须是不透明面；媒体内容先铺遮罩，再按容器模式取色。模式是作用域，不进名字。
- **密度**：comfortable / compact 是角色指向的重映射，不是第二套原料值。紧凑只让角色指向更小的档；字号、圆角、光学间距不参与。
- **不预设反向嵌套**：深页浅块与浅页深块是同一机制，但实际继承链要按已有主题映射验证。

### 2.5 命名原则

- **语义角色保留名字**：主文字、次文字、卡片内衬、浮层面；名字说明用途，不说明当前值。
- **数值阶梯用序号**：字号、间距、圆角、阴影、时长等连续尺度用序号，单调递增；序号必须在文档或示例里带值对照。
- **不要用值当名字**：`16`、`300ms`、`#FFFFFF` 不是角色名。
- **一个角色只允许一个名字**；别名只做指针。
- **名字里不带模式与默认状态**：light / dark / rest / comfortable 是作用域或默认值，不进名字。

### 2.6 输出格式

设计系统是平台中立的。DTCG 这类格式可以作为设计值的交换与导出形式；具体文件结构、命名映射与平台适配由实现决定，本 skill 不规定。

## 3 设计流程

### 3.1 前置五问

| 问题 | 要确认什么 | 影响 |
|---|---|---|
| **目的** | 这个界面 / 组件解决什么问题？谁在用？ | 信息层级、密度、主行动 |
| **内容** | 内容的层级、长度、变化范围、最坏情况 | 排版、换行、空态、加载 |
| **语气** | 克制 / 安静 / 编辑感 / 技术 / 温暖 / 强烈 | 风格、颜色、形状、动效 |
| **约束** | 平台、输入方式、性能、无障碍、品牌 | 尺寸、动效、材质、降级 |
| **差异点** | 用户记住它的是什么？哪一件事必须做对？ | 视觉重心、交互重点 |

「语气」不等于「大胆」。默认取向是平衡：先判断需要多少强度，再决定用多少。

### 3.2 决策顺序

1. **定范围**：对象、平台、模式、密度、内容最坏情况。
2. **定结构**：页面 / 组件骨架、信息层级、主行动。
3. **取维度**：颜色、排版、空间、表面、光影、动效、状态。
4. **组风格**：需要时再选风格家族；默认不选。
5. **做评审**：对比度、焦点、热区、重排、降级。
6. **写输出**：设计规格或评审报告，不写实现状态。

- **不发明档位**：没有对应档时按 P15 用倍数，或标记「需要项目自定义」。
- **不跨维度代偿**：不用阴影补对比度、不用描边补间距、不用动效补缺失状态、不用透明补层级。
- **不在第一步选风格**：风格是维度组合的结果，不是起点。

### 3.3 设计反模式

| 症状 | 为什么错 | 正确做法 |
|---|---|---|
| 动效不尊重 reduced-motion | 前庭敏感用户不适 | `prefers-reduced-motion` 分支 |
| 用「数值相等」冒充对称 | 两端底色不同，硬凑相等必然牺牲一端 | 先找不变量 |
| 为了「看得见」违反物理 | 深色硬拉阴影 / 辉光破坏方向语义 | 接受上限，用面差 + 边缘环 |
| 可见值缺席时连槽位一起删 | 以后启用要改结构 | 保留角色与属性，值用透明 / 无 |
| 阴影与高光不同源 | 观感假，深浅模式互相打脸 | 同一光源，暗边遮光、亮边受光 |
| 无对应档时写一次性字面值 | 档位失去系统意义 | 用已有档的整数倍 |
| 无意图的默认审美 | 通用字体、紫色渐变、居中 hero + 卡片网格；看起来像模板 | 先回答前置五问，再按维度取值 |
| 风格先于内容 | 为了毛玻璃 / 轻拟物牺牲可读性与层级 | 先解决内容与结构，再叠加风格 |
| 用装饰补结构 | 用分隔线、阴影、图标填没有层级的区域 | 先补信息层级与间距 |

### 3.4 两条评审轨道

| 轨道 | 回答 | 判据 | 结论 |
|---|---|---|---|
| **规范评审** | 是否符合可引用、可复算的规范 | 档位、对比目标、命名、边界、状态 | `pass` / `warn` / `deviation` / `unverified` |
| **设计批评** | 是否好用、好看、清楚、有气质 | 层级、信息架构、认知负荷、情绪、工艺 | 分数 / 问题清单 / 建议 |

- 规范评审只对可引用、可复算的条款下结论；未知底标 `unverified`，不假装通过。
- 设计批评必须给证据与建议；分数不能替代规范结论。
- 风格层只进入设计批评与警告，不新增硬性门槛。

### 3.5 输出建议

- **设计规格**：结构骨架、文字角色、颜色配对、表面层级、状态矩阵、动效计划、无障碍检查、未决项。
- **评审报告**：结论、判据、证据、最近可行档、风险、范围边界。
- **风格 brief**：风格意图、维度配方、固定不变量、示例、警告。

### 3.6 只给报告与建议

本 skill 只提供设计知识、报告与建议；使用者可以选择遵循，也可以选择不完全遵循。它不做强制检查，也不替使用者做决定。

如果实现侧要做自动检查，那是实现自己的事；本 skill 不规定检查方式，也不把检查结果当成设计结论。
