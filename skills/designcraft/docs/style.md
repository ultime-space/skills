# 风格体系

> 适用：选择 / 组合风格、写风格 brief、判断风格是否越界。
> 评审步骤见 [`scenarios/build-style.md`](../scenarios/build-style.md)。

## 1 风格 = 维度组合

一种风格由一组选择构成：

```text
风格 = 颜色倾向 × 字体语气 × 形状语言 × 表面 / 光影 × 动效气质 × 密度 × 构图
```

- **风格不新增维度**：所有取值仍来自颜色、排版、空间形状、表面光影、动效、状态、布局。
- **风格不改骨架**：间距、尺寸、圆角基座、边界宽度、焦点几何、对比目标仍按原规则；风格可以选「圆角基座的哪一档」，但不能发明新的基座。
- **风格不是默认**：默认是中性 / 安静；风格是显式选择，需要内容与品牌理由。

## 2 身份维度与骨架维度

| 类别 | 内容 | 风格层能否动 |
|---|---|---|
| **骨架** | 间距档、尺寸档、边界宽度、焦点几何、对比目标、投影三层几何、语义色相 | 不逐个改；只能整体换档或按既有档选择 |
| **身份** | 品牌色相 / 彩度、画布冷暖 / tint、字体栈、字号基准、圆角基座、表面策略、光影方向 / 柔度、动效手感、密度预设 | 可以组合成风格 |
| **派生** | alpha、配对前景、状态色、tint 值、阴影 alpha | 只由目标反解，风格不直接写 |
| **业务侧** | 页面布局、组件结构、材质配方、特殊密度、品牌资产 | 风格层只给建议，不替业务决定 |

> 工具如何暴露这些可配项、配置工具允许改哪些，不属于本章；那是实现侧的工具决策。本章只描述「设计上可以怎么组合」。

## 3 系统原生风格（优先）

先用我们自己的维度组合出好看、稳定的风格。下面是方向，不是固定配方。

| 风格家族 | 气质 | 维度取向 | 适合 | 注意 |
|---|---|---|---|---|
| **中性 / 安静** | 精密、克制、不抢内容 | 中性画布、低彩度、400/500/600、中等圆角、tonal 面、轻阴影、标准曲线、comfortable | 工具、后台、通用产品 | 容易显得「没有性格」；靠字重、间距、少量强调建立层级 |
| **编辑 / 阅读** | 有节奏、可长读 | 较强字号对比、serif / display 搭配、较大行高、窄行宽、tonal 面、少阴影、克制动效 | 内容、文档、品牌故事 | 不要把行宽拉满；标题与正文必须跨档 |
| **密集 / 数据** | 高效、可扫描 | compact、tabular-nums、小控件、outline / tonal、清晰分隔、短动效 | 后台、表格、监控 | 热区必须兜底；不要用 hover 承载信息 |
| **柔和 / 圆润** | 亲和、松弛 | 较大圆角、柔和 tint、低对比面、柔和曲线、comfortable | 生活、健康、消费 | 圆角变大要检查内容避让与同心；低对比要检查正文 |
| **锐利 / 技术** | 精确、工程感 | 小圆角、outline 策略、mono 强调、清晰线条、快曲线、compact | 开发者工具、规格、数据 | 线条多时容易噪；靠间距与字重分层，不靠更多线 |
| **温暖 / 人文** | 柔和、有温度 | 暖中性、柔和字体、较松间距、tonal 面、缓慢曲线 | 教育、内容、服务 | 暖色不要污染语义色；对比度仍按规范 |

## 4 流行风格 recipe（其次）

以下是「用我们的维度组合出来的表达」，不是外部风格库。先作为候选，具体取值由风格研究再定。

| 风格 | 维度取向 | 适合 | 警告 |
|---|---|---|---|
| **毛玻璃 / glassmorphism** | 半透明面 + 背景模糊 + 环境高光 + 主光偏色；背景需要有内容可透 | 浮层、hero、展示卡 | 对比度依赖底；性能成本高；不支持背景模糊时要有实色回退；一级面容器是风险区，透明度可控且合成对比度达标即可，不强制白底；正文 / 主表单优先近不透明或给底衬 |
| **扁平 / 简洁** | 填充 × 边界 两轴组合（纯色面 / 线框 / 两者叠加 / 无框），可不叠光影；强字阶、大留白 | 工具、内容、移动端 | 扁平不等于没有层级；没有阴影时靠字阶、间距、面阶；不要把所有块做成同权卡片 |
| **线框 / wireframe** | outline 策略、1px 线、少填充、mono 标签 | 规格、原型、技术展示 | 线多容易噪；线对比要够；生产界面要补层级，不能只靠线 |
| **色块 / color-block** | 大面积 tonal 色块、品牌色相、强配对前景、少边界 | 品牌页、活动页、展示 | 大面积高饱和会压内容；语义色不要当装饰色；色觉差异要检查 |
| **浮雕 / 轻拟物 / neumorphism** | 轻微高光 + 投影 + 同色面（凸起形态），低对比；按压靠状态层或深度档 | 装饰块、大按钮、展示 | 天然低对比；正文 / 主表单要额外确认；强制颜色 / 打印下会退化；重拟物的形态反转归风格层，系统只给能力 |

**扁平的组合轴**：线框 / 纯色面 / 线框 + 纯色面 不是三个子风格，是「填充 × 边界」两个轴上的取值，再叠光影是第三维。边界只做四边或无；单边线读作分隔符，不作容器边界。焦点统一一种样式，只改颜色或叠加外环，不改宽度与几何。

**常见反例**（合法但不好看）：四边描边 + 同边高光（双线）；描边 + 明显投影（两套边界语言）；深面 + 强黑投影（黑叠黑）；玻璃 + 实线边框（材质感断开）；轻拟物 + 描边（光影被切成两层）；面差、投影、高光、描边同时强（视觉过载）。

**使用顺序**：先系统原生风格，再流行 recipe；流行 recipe 不是默认，也不是「更高级」。建议同一产品最多选一种主风格，不要混用两套互相打架的语言。

## 5 形状语言的装饰选择

> 本节只给应用经验，不新增规则。硬约束只有两条，且都不是本节发明的：四角取自同一派生集（档位严格）；同心、内容避让、相邻角按短边归一化照常适用。其余是偏好与代价。

**用不用是偏好**

默认四角等值。非对称是显式选择，需要能说出来源：模仿真实物件（气泡、票据、标签）、单侧贴边时的收口、指向内容来源的方向。说不出来源就退回等值，不因为「看起来更活泼」去改一个角。

**常见形态**

| 形态 | 典型用法 | 取法 | 代价 / 风险 |
|---|---|---|---|
| 三圆一尖 | 对话气泡 | 指向来源的一侧取更小一档或直角，其余三面同档 | 尾巴角过小会读成缺角；尾巴与文字基线不对齐时，气泡会像两个元素 |
| 单侧收口 | 贴边卡片、抽屉、分段控件 | 贴边一侧取直角，外侧取同档 | 组内相邻两块的相接角必须一致，否则出现错位缝；中间块两侧都直角时容易读成断裂 |
| 缺口 | 票券、优惠券、凭证 | 缺口与圆角分开处理，不用半径模拟 | 用半径凑缺口会破坏短边归一化；独立角形能力要先确认目标平台支持 |
| 对角同档 | 装饰块、异形卡片 | 左上与右下同档、右上与左下同档 | 只调两个角时另外两角极易取错档；方向感很强，不适合有阅读流向的容器 |
| 全圆 | 徽标、标签、头像 | 取短边一半，随高度变 | 不是固定档；高度变化后要重新夹紧 |

**反例**

- 同一界面出现两种以上非对称母题，读者会当成没对齐。
- 用非对称补偿布局错位，或掩盖间距不一致。
- 在默认卡片、表单、正文容器上改一个角，只为「不那么呆板」。
- 把缺口、尾巴、斜切都用半径硬凑；它们是角形或裁切问题，不是半径问题。

**代价**

逐处手写、不能整体换肤；母题变化要逐处改；组件复用后容易各自漂移。需要全局统一时，先收敛成一个可复用的命名值，再让组件引用。

**与风格家族的关系**

形状语言是风格维度之一，非对称形状可以成为一套风格的表达；但它不是任何风格家族的必要条件，也不构成标签。「柔和 / 圆润」说的是圆角基座的大小，四角不同是另一个量，可以叠在任意基座大小上。

## 6 警告，不是硬门槛

风格层不新增硬门槛。对比度、性能、可读性问题以**警告 / 建议**呈现：

- **对比度**：低对比风格天然存在；按 [`color.md`](./color.md) §7 报告 `pass / warn / deviation / unverified`，不阻断；正文 / 主表单由项目决定是否接受。
- **性能**：模糊、阴影、大面积透明有成本；给出面积、层数、滚动场景的建议。
- **可读性**：低对比、长行、过密、过多装饰；给建议，不替项目做最终取舍。
- **平台**：背景模糊、混合模式、某些字体在目标平台可能不可用；给回退建议。
- **已有规范仍然成立**：风格层不豁免对比度报告、减少动效、无障碍基线；但它不新增「风格禁止」条款。

## 7 风格方案集

一份可用的风格方案集至少包含 2–3 套方向，每套写：

1. **意图**：3–5 个形容词 + 一句话「想让人感觉到什么」。
2. **维度选择**：颜色、字体、形状、表面 / 光影、动效、密度、构图各选什么，为什么。
3. **用意**：这套想传达什么、适合什么场景。
4. **优点**：这套在可读性、辨识度、性能、维护上的长处。
5. **代价与风险**：对比度、性能、平台、可读性、维护成本。
6. **不适合**：什么情况下别选它。
7. **骨架引用**：哪些骨架 / 规范不动；只引用，不逐项改。

最后给对比与推荐，并保留选择权。只给一套、或只给形容词，都不算方案集。

## 8 常见问题

- 风格先于内容：先选毛玻璃 / 轻拟物，再硬塞内容。
- 一套产品混用两种主风格：一半扁平、一半拟物。
- 用低对比风格承担正文 / 主表单，却没有额外确认可读性。
- 把流行风格当默认，缺少品牌 / 内容理由。
- 用装饰（渐变、纹理、光效）替代层级与间距。
- 风格 recipe 写死 hex / 字体，脱离系统全局选择与角色。

## 9 评审口径

**可检查项**：风格是否只组合既有维度；是否只动身份维度；是否保留骨架 / 对比目标；是否只有一种主风格。

**必须人检**：低对比风格在正文 / 主表单上的可读性；性能成本；平台回退；风格是否服务内容与品牌。

## 10 风格之后的感知质量

- 风格选完后，按 [`perceived-quality.md`](./perceived-quality.md) 诊断；高级感不是一种独立风格，也不新增维度。
- 同一风格家族内，质量下限由秩序、完成度、克制等信号决定；风格只决定组合，不保证做得精致。
- 不要把流行 recipe 当更高级；也不要用低对比、慢动画、隐藏信息换「高级」。
- 风格方案集给选择；感知质量诊断给修改顺序。两者不互相替代。
