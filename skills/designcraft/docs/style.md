# 风格体系

> 源：设计规范 §14（快照 2026-11-05）。本文件是面向 AI 的提炼，不是规范真源。
> 适用：选择 / 组合风格、写风格 brief、判断风格是否越界。
> 评审步骤见 [`scenarios/build-style.md`](../scenarios/build-style.md)。

## 1 风格 = 维度组合

一种风格由一组选择构成：

```text
风格 = 颜色倾向 × 字体语气 × 形状语言 × 表面 / 光影 × 动效气质 × 密度 × 构图
```

- **风格不新增维度**：所有取值仍来自颜色、排版、空间形状、表面光影、动效、状态、布局。
- **风格不改骨架**：间距、尺寸、圆角基座、边界宽度、焦点几何、对比目标仍按原规则；风格可以选「圆角基座的哪一档」，但不能发明新的基座。
- **风格不是默认**：默认是中性 / 安静；风格是显式选择，需要内容与品牌理由。

## 2 身份维度与骨架维度

| 类别 | 内容 | 风格层能否动 |
|---|---|---|
| **骨架** | 间距档、尺寸档、边界宽度、焦点几何、对比目标、阴影三槽位几何、语义色相 | 不逐个改；只能整体换档或按既有档选择 |
| **身份** | 品牌色相 / 彩度、画布冷暖 / tint、字体栈、字号基准、圆角基座、表面策略、光影方向 / 柔度、动效手感、密度预设 | 可以组合成风格 |
| **派生** | alpha、配对前景、状态色、tint 值、阴影 alpha | 只由目标反解，风格不直接写 |
| **业务侧** | 页面布局、组件结构、材质配方、特殊密度、品牌资产 | 风格层只给建议，不替业务决定 |

> 工具如何暴露这些可配项、配置工具允许改哪些，不属于本章；那是实现侧的工具决策。本章只描述「设计上可以怎么组合」。

## 3 系统原生风格（优先）

先用我们自己的维度组合出好看、稳定的风格。下面是方向，不是固定配方。

| 风格家族 | 气质 | 维度取向 | 适合 | 注意 |
|---|---|---|---|---|
| **中性 / 安静** | 精密、克制、不抢内容 | 中性画布、低彩度、400/500/600、中等圆角、tonal 面、轻阴影、标准曲线、comfortable | 工具、后台、通用产品 | 容易显得「没有性格」；靠字重、间距、少量强调建立层级 |
| **编辑 / 阅读** | 有节奏、可长读 | 较强字号对比、serif / display 搭配、较大行高、窄行宽、tonal 面、少阴影、克制动效 | 内容、文档、品牌故事 | 不要把行宽拉满；标题与正文必须跨档 |
| **密集 / 数据** | 高效、可扫描 | compact、tabular-nums、小控件、outline / tonal、清晰分隔、短动效 | 后台、表格、监控 | 热区必须兜底；不要用 hover 承载信息 |
| **柔和 / 圆润** | 亲和、松弛 | 较大圆角、柔和 tint、低对比面、柔和曲线、comfortable | 生活、健康、消费 | 圆角变大要检查内容避让与同心；低对比要检查正文 |
| **锐利 / 技术** | 精确、工程感 | 小圆角、outline 策略、mono 强调、清晰线条、快曲线、compact | 开发者工具、规格、数据 | 线条多时容易噪；靠间距与字重分层，不靠更多线 |
| **温暖 / 人文** | 柔和、有温度 | 暖中性、柔和字体、较松间距、tonal 面、缓慢曲线 | 教育、内容、服务 | 暖色不要污染语义色；对比度仍按规范 |

## 4 流行风格 recipe（其次）

以下是「用我们的维度组合出来的表达」，不是外部风格库。先作为候选，具体取值由风格研究再定。

| 风格 | 维度取向 | 适合 | 警告 |
|---|---|---|---|
| **毛玻璃 / glassmorphism** | 半透明面 + 背景模糊 + 边缘高光 + 高光偏色；背景需要有内容可透 | 浮层、hero、展示卡 | 对比度依赖底；性能成本高；不支持背景模糊时要有实色回退；一级面容器是风险区，透明度可控且合成对比度达标即可，不强制白底；正文 / 主表单优先近不透明或给底衬 |
| **扁平 / 简洁** | 去阴影、tonal 或 outline、强字阶、大留白、少装饰 | 工具、内容、移动端 | 扁平不等于没有层级；没有阴影时靠字阶、间距、面阶；不要把所有块做成同权卡片 |
| **线框 / wireframe** | outline 策略、1px 线、少填充、mono 标签 | 规格、原型、技术展示 | 线多容易噪；线对比要够；生产界面要补层级，不能只靠线 |
| **色块 / color-block** | 大面积 tonal 色块、品牌色相、强配对前景、少边界 | 品牌页、活动页、展示 | 大面积高饱和会压内容；语义色不要当装饰色；色觉差异要检查 |
| **浮雕 / 轻拟物 / neumorphism** | 明暗 + 柔和阴影 + 同色面、低对比 | 装饰块、大按钮、展示 | 天然低对比；正文 / 主表单要额外确认；强制颜色 / 打印下会退化；性能成本中等 |

**使用顺序**：先系统原生风格，再流行 recipe；流行 recipe 不是默认，也不是「更高级」。建议同一产品最多选一种主风格，不要混用两套互相打架的语言。

## 5 警告，不是硬门槛

风格层不新增硬门槛。对比度、性能、可读性问题以**警告 / 建议**呈现：

- **对比度**：低对比风格天然存在；按 [`color.md`](./color.md) §7 报告 `pass / warn / deviation / unverified`，不阻断；正文 / 主表单由项目决定是否接受。
- **性能**：模糊、阴影、大面积透明有成本；给出面积、层数、滚动场景的建议。
- **可读性**：低对比、长行、过密、过多装饰；给建议，不替项目做最终取舍。
- **平台**：背景模糊、混合模式、某些字体在目标平台可能不可用；给回退建议。
- **已有规范仍然成立**：风格层不豁免对比度报告、减少动效、无障碍基线；但它不新增「风格禁止」条款。

## 6 风格 brief

一份可执行的风格 brief 至少包含：

1. **意图**：3–5 个形容词 + 一句话「为什么是这个风格」。
2. **维度选择**：颜色、字体、形状、表面 / 光影、动效、密度、构图各选什么，为什么。
3. **固定不变量**：哪些骨架 / 规范不动。
4. **示例**：一个主场景 + 一个最坏场景（长内容 / 空态 / 错误）。
5. **警告**：对比度、性能、平台、可读性。
6. **不做什么**：容易滑向的反例。

## 7 常见问题

- 风格先于内容：先选毛玻璃 / 轻拟物，再硬塞内容。
- 一套产品混用两种主风格：一半扁平、一半拟物。
- 用低对比风格承担正文 / 主表单，却没有额外确认可读性。
- 把流行风格当默认，缺少品牌 / 内容理由。
- 用装饰（渐变、纹理、光效）替代层级与间距。
- 风格 recipe 写死 hex / 字体，脱离系统全局选择与角色。

## 8 评审口径

**可检查项**：风格是否只组合既有维度；是否只动身份维度；是否保留骨架 / 对比目标；是否只有一种主风格。

**必须人检**：低对比风格在正文 / 主表单上的可读性；性能成本；平台回退；风格是否服务内容与品牌。
