# 交互状态评审

## 目标

判断交互态、数据态、异步态是否用正确的语义表达；状态组合是否可辨；输入环境是否覆盖触控、指针与键盘。

## 输入

- 页面 / 组件 / 状态清单；需要时附截图与交互说明。
- 先确认平台与输入方式（触控 / 指针 / 键盘 / 混合）。

## 步骤

1. **状态分类**：交互态、数据态、异步态是否分开；是否用私有 `data-*` 替代语义。
2. **交互态**：hover 是否只在 hover 设备；focus 是否用 `:focus-visible` 且可见；pressed 是否立即反馈。
3. **数据态**：selected / current / checked / expanded / disabled / readonly / invalid 是否用原生属性或 ARIA；是否只靠颜色。
4. **禁用与只读**：是否区分；提交按钮是否优先不禁用；禁用态是否整块 `opacity`。
5. **错误**：何时出现、在哪显示、怎么关联、怎么汇总；是否有 `aria-invalid` / `aria-describedby`；是否只改边框颜色。
6. **异步态**：加载、成功、失败、空态是否有文字语义；是否只靠动画或颜色；停止动画后是否仍有线索。
7. **组合**：selected + hover + pressed 是否可辨；最坏态对比度是否复核。
8. **几何**：状态切换是否改变外框位置 / 尺寸；是否用缩放 / 位移 / 加宽边框表达状态。
9. **输入环境**：触控是否有按下态；键盘焦点顺序是否成立；目标尺寸是否达标；手势是否有替代。
10. **强制颜色 / 读屏**：状态是否仍有边框、图标或文字线索；读屏是否能获知状态与结果。

## 输出

按 [`prompts/output.md`](../prompts/output.md)：

- 结论（通过 / 需调整）
- 每条判据与证据（状态 → 语义 → 视觉）
- 风险（触控、键盘、读屏、强制颜色）
- 不把「有颜色变化」当成「状态成立」

## 反例

- 用 hover 承载关键信息。
- 用 2px `border` 加宽表达选中。
- 禁用态整块 `opacity: 0.5`。
- 错误只把边框变红，没有文字与关联。
- 加载态只放 spinner，没有文案与语义。
