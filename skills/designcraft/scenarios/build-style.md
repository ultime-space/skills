# 构建风格

## 目标

为一个品牌 / 产品 / 页面给出 2–3 套风格方案，每套写清用意、优点与代价，由使用者选择。不新增设计值，不改骨架，不给唯一答案。

## 输入

- 品牌 / 产品、目标用户、主场景、内容最坏情况。
- 现有系统选择（颜色、字体、圆角、表面、动效、密度）；没有就明确标注。
- 约束：平台、性能、无障碍、品牌资产。
- 可选：品牌已有的偏好、竞品参照、明确排斥的方向。

## 步骤

1. **定意图**：3–5 个形容词 + 一句话「想让人感觉到什么」。
2. **出 2–3 套候选**：一套系统原生风格（基准），一到两套有明确意图的流行 recipe 或维度偏移；每套必须服务不同的意图，不是同一套的强弱版。
3. **选身份维度**：每套给出颜色倾向、字体语气、形状语言、表面 / 光影、动效手感、密度、构图。
4. **引用骨架**：间距、尺寸、边界宽度、焦点几何、对比目标、阴影几何、语义色相不改；需要不同密度时从既有档位取。
5. **做示例**：每套一个主场景 + 一个最坏场景（长内容 / 空态 / 错误）。
6. **写用意与代价**：这套想解决什么、适合谁；优点；代价与风险；什么情况下不适合。
7. **给推荐与开关**：推荐一套并说明依据；写一句「如果你更看重 X，就选另一套」。
8. **列警告**：对比度、性能、平台、可读性；警告不等于否决。

## 输出

按 [`templates/style-brief.md`](../templates/style-brief.md) 输出。2–3 套方案，每套写清：

- 风格意图
- 身份维度选择与理由
- 用意：想传达什么、适合什么场景
- 优点
- 代价与风险
- 不适合的情况
- 骨架与规范引用（哪些不动）

最后给对比与推荐，保留选择权。

## 禁止

- 只给一套并把偏好写成结论。
- 用形容词堆叠代替维度选择（「高级、干净、有质感」不算方案）。
- 不新增设计值 / 骨架。
- 不把流行风格当默认，也不把「更强烈」当成「更高级」。
- 不用风格覆盖对比度、焦点、热区等结论；警告不等于禁止。
