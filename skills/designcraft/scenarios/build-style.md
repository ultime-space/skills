# 构建风格

## 目标

为一个品牌 / 产品 / 页面选择或组合一种风格，输出可执行的风格 brief：意图、维度选择、固定不变量、示例与警告。不新增设计值，不改骨架。

## 输入

- 品牌 / 产品、目标用户、主场景、内容最坏情况。
- 现有系统选择（颜色、字体、圆角、表面、动效、密度）；没有就明确标注。
- 约束：平台、性能、无障碍、品牌资产。

## 步骤

1. **定意图**：3–5 个形容词 + 一句话「为什么是这个风格」。
2. **选路径**：优先系统原生风格；需要更强辨识度时，再选一个流行 recipe。不要同时选两套主风格。
3. **选身份维度**：颜色倾向、字体语气、形状语言、表面 / 光影、动效手感、密度、构图。
4. **守骨架**：间距、尺寸、边界宽度、焦点几何、对比目标、阴影几何、语义色相不动。
5. **做示例**：一个主场景 + 一个最坏场景（长内容 / 空态 / 错误）。
6. **列警告**：对比度、性能、平台、可读性；不写成硬性禁止。
7. **写不做什么**：容易滑向的反例。

## 输出

按 [`templates/style-brief.md`](../templates/style-brief.md) 输出。必须写清：

- 风格意图
- 选了哪些身份维度，为什么
- 哪些骨架 / 规范不动
- 主场景与最坏场景
- 警告与回退

## 禁止

- 不新增设计值 / 骨架。
- 不把流行风格当默认，也不把「更强烈」当成「更高级」。
- 不用风格覆盖对比度、焦点、热区等规范结论。
- 不写死第三方资源或具体品牌资产；需要时标「由项目提供」。
