# 组件设计规格

## 目标

从一个组件 brief 出发，给出可执行的设计规格：解剖结构、尺寸、文字、颜色、状态、交互反馈与无障碍。不写代码。

## 输入

- 组件类型、使用场景、平台、密度、内容最坏情况。
- 是否已有同类组件；是否需要与现有角色 / 面阶 / 间距对齐。

## 步骤

1. **解剖结构**：根、内容、图标、标签、辅助信息、操作区；哪些是必需槽位。
2. **尺寸**：控件高度档、内衬、图标尺寸、热区；视觉尺寸与热区分开。
3. **文字**：每个文字块用哪个角色；长内容 / 译文增长 / 截断路径。
4. **颜色**：中性面 / 语义色 / 配对前景；对比目标与最坏底。
5. **形状**：圆角、边界、焦点环；同心是否成立。
6. **状态**：默认、hover、focus、pressed、selected、disabled、loading、error。
7. **反馈**：press / state / focus 的载体与时长；状态不引起重排。
8. **无障碍**：名称、角色、值、键盘、焦点、目标尺寸、强制颜色。
9. **未决项**：需要项目或实现决定的事项。

## 输出

按 [`templates/design-spec.md`](../templates/design-spec.md) 输出。必须写清：

- 解剖结构与必需槽位
- 尺寸 / 间距 / 圆角 / 边界
- 文字角色与内容最坏情况
- 状态矩阵
- 反馈与动效
- 无障碍检查
- 未决项与不在本次范围

## 禁止

- 不发明新角色 / 新档位；没有就标「需要项目自定义」。
- 不把视觉尺寸当热区。
- 不用状态反馈改变外框几何。
- 不写代码、内部路径、实现状态。
