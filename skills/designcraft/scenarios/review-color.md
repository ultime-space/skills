# 颜色评审

## 目标

判断文字、描边、填充与渐变背景上的配对是否达到目标；区分「低于设计值」「低于门槛」「未知底」三种情况。

## 输入

- 背景色 / 声明底（画布、抬升面、浮层面、凹陷面、soft、solid）。
- 文字使用的颜色、字号、字重。
- 是否有已声明的中性底；未知底要单独标记。
- 渐变另给：端点、声明的插值空间、色标位置、文字所在位置；无色端点、近中性端点与可能越界单独标记。

## 步骤

1. 先分背景类：中性面用中性墨；族墨底用色族墨；实心填充用配对前景。
2. 对比度换到 sRGB 相对亮度；透明 / 叠层先合成再算。
3. 对照目标：中性 `7.2 / 6 / 5 / 2.0`；族墨 `7.2 / 6 / 5`；配对前景 `4.5`。
4. 对照门槛：普通文字 4.5、大字与图元 3.0、禁用 2.0。
5. 分级：`pass` / `warn` / `deviation` / `unverified`；未知底不判通过。
6. 低于目标时给最近可行档；低于门槛时说明需要改全局选择、改填充还是登记例外。
7. **渐变**：先确认插值空间是否声明或可反解；色相距离大时算中段彩度比值，低于 20% 基本判灰区，20–60% 记明显降彩；彩色到中性检查无色端点；文字按整段最不利点采样；大面积低对比暗色渐变检查台阶；换空间后核对品牌端点与路径越界。

## 输出

按 [`prompts/output.md`](../prompts/output.md)。必须写清：

- 背景类与声明底
- 实测对比度 / 目标 / 门槛
- 分级与理由
- 是否在已声明范围内；未声明范围只给建议
- 渐变另写：插值空间、中段彩度比值、最不利点位置与对比、越界与回退

## 反例

- 拿「看起来够黑」代替合成后的对比度。
- 把辅助文字当图元档用 3.0 判。
- 在图片 / 视频 / 多层透明等未知底上直接判 `pass`。
- 未声明插值空间就直接判 `pass`。
- 只验渐变两端就宣布整段通过。
- 把对立色相换空间当成万能修复，不核对品牌端点与越界。
- 把渐变文字当单色文字，只测一处。
- 把配对前景当成独立维度，或拿 `ink` 硬套彩色实心面。
