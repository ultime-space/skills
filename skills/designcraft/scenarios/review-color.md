# 颜色评审

## 目标

判断文字、描边、填充的配对是否达到目标；区分「低于设计值」「低于门槛」「未知底」三种情况。

## 输入

- 背景色 / 声明底（画布、卡片、浮层、凹陷、soft、solid）。
- 文字使用的 token 或实际颜色、字号、字重。
- 是否在 core 合同范围内（core / 语义表 / 配置器）。

## 步骤

1. 先分背景类：中性面用中性 `ink`；族墨底用 `tone.*.ink`；实心填充用 `tone.*.solid.foreground`。
2. 对比度换到 sRGB 相对亮度；透明 / 叠层先合成再算。
3. 对照目标：中性 `7.2 / 6 / 5 / 2.0`；族墨 `7.2 / 6 / 5`；`foreground` `4.5`。
4. 对照门槛：普通文字 4.5、大字与图元 3.0、禁用 2.0。
5. 分级：`pass` / `warn` / `deviation` / `unverified`；未知底不判通过。
6. 低于目标时给最近可行档；低于门槛时说明需要改 seed、改填充还是登记例外。

## 输出

按 [`prompts/output.md`](../prompts/output.md)。必须写清：

- 背景类与声明底
- 实测对比度 / 目标 / 门槛
- 分级与理由
- 是否在 core 审计范围；上层项目只给建议

## 反例

- 拿「看起来够黑」代替合成后的对比度。
- 把 `tertiary` 当图元档用 3.0 判。
- 在图片 / 渐变底上直接判 `pass`。
