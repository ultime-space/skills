# 数据、图形与内容评审

## 目标

判断数据色、图标尺寸与使用场景、图形 / 插画、内容层级与文案是否成立；不在时给出建议。

## 输入

- 页面 / 图表 / 组件 / 文案；需要时附截图与数据说明。
- 先确认数据关系（分类 / 连续 / 发散）、图标使用场景、内容最坏情况。

## 步骤

1. **数据色**：是否区分分类 / 连续 / 发散；状态色是否被当类别色；类别超过色板数量是否只循环复用。
2. **类别可辨**：是否只靠颜色；是否有标签、图案、形状或固定顺序补偿；色觉差异是否初筛。
3. **图表对比**：图元与相邻背景是否 ≥ 3:1；对比够是否被误当成类别可辨。
4. **图标尺寸**：是否落在 12 / 16 / 20 / 24 / 32；同组是否同尺寸、同视觉重量。
5. **图标场景**：行内、图标按钮、导航、列表、空态是否选对；图标是否独自承担必要信息。
6. **图标可访问性**：装饰图标是否 `aria-hidden`；表意图标是否有名称；图标按钮是否有可访问名称；热区是否单独补足。
7. **图形 / 插画**：是否与 UI 图标分库；是否承担必要信息；深色 / 强制颜色 / 打印是否退化。
8. **内容层级**：是否只有一个主行动；标题、正文、按钮是否各说各的事。
9. **错误 / 空态 / 加载**：是否说明原因、下一步、恢复路径；是否只靠颜色或动画。
10. **数字 / 日期 / 语言**：是否用等宽数字；是否按 locale 格式化；中英混排是否合规。

## 输出

按 [`prompts/output.md`](../prompts/output.md)：

- 结论（通过 / 需调整）
- 每条判据与证据（原值 → 建议 → 偏差）
- 风险（色觉、图标热区、长文案、locale）
- 不把「有颜色 / 有图标」当成「信息成立」

## 反例

- 用成功 / 危险色区分普通类别。
- 图标 24 就当热区 24。
- 图标按钮只写 `title`。
- 空态只放插画，不说明为什么空。
- 日期硬编码格式，不按 locale。
