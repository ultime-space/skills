# 结构与布局评审

## 目标

判断间距、控件高度、密度、热区、圆角、边界与焦点是否落在规范内；页面结构、滚动归属、栅格与响应式是否成立。不在时给出最近可行档。

## 输入

- 页面 / 组件 / 设计值表；需要时附截图、容器宽度、平台与输入方式。
- 先确认密度（comfortable / compact）与页面类型（移动 / 平板 / 桌面 / 纸面）。

## 步骤

1. **间距**：是否落在 4 的倍数与登记档位；光学档（2 / 6）是否只在组件内部；块间距是否用外边距硬造。
2. **控件高度**：是否落在 24 / 32 / 40 / 48 / 56；行高是否 = 控件高 + 上下内衬。
3. **密度**：同一页面是否混用两种密度；compact 是否回答了热区兜底。
4. **热区**：视觉尺寸、热区、相邻间距是否分别验证；移动端是否达到 44 的默认主张。
5. **圆角**：是否落在派生集；同心是否满足贴角、等宽内衬、结果为正；内容是否避让。
6. **边界**：同一层级是否只有一种边界手段；选中 / 焦点是否不占布局、不加宽。
7. **布局**：是否只有一个主滚动容器；navbar / tabbar 是否常驻且不遮挡；安全区是否让出。
8. **栅格与断点**：内容栅格是否由容器决定；断点是否只做参考线；换行是否由内容驱动。
9. **响应式**：320px 重排、200% 文字缩放、DOM 顺序与焦点顺序、RTL、打印。
10. **最坏内容**：长标题、空态、错误、译文增长时是否仍成立。

## 输出

按 [`prompts/output.md`](../prompts/output.md)：

- 结论（通过 / 需调整）
- 每条判据与证据（原值 → 最近档 → 偏差）
- 风险（热区、裁切、重排、焦点遮挡）
- 不把「落在档位」当成「结构成立」

## 反例

- 用外边距造卡片间距。
- compact 只缩小视觉高度，不补热区。
- 内外同半径，看起来像两条平行弧线。
- 卡片同时用底色阶、描边和阴影。
- 多个滚动容器互相嵌套。
- 视觉顺序与 DOM / 焦点顺序不一致。
