# 页面设计规格

## 目标

从一个 brief 出发，给出可执行的设计规格：结构、文字角色、颜色配对、表面层级、状态、动效与无障碍检查。不写代码，不绑定具体实现。

## 输入

- 页面类型、目标用户、主任务、平台、模式、密度、内容最坏情况。
- 已有品牌 / 设计值（如果有）；没有就明确标注。

## 步骤

1. **前置五问**：目的、内容、语气、约束、差异点。
2. **结构**：页面骨架、主滚动容器、常驻区域、主行动；页面级布局按 [`docs/layout.md`](../docs/layout.md)。
3. **层级**：首屏信息层级；一屏一个主行动；渐进披露。
4. **文字角色**：标题、正文、说明、元信息分别用哪个角色；不新增字号档。
5. **颜色**：中性面 / 语义色 / 配对前景；对比目标与最坏底。
6. **空间与形状**：间距、控件高度、密度、圆角、边界；热区单独补。
7. **表面与光影**：面阶、分块策略、阴影 / 环境遮蔽 / 边缘高光；同一层级一种边界手段。
8. **状态**：默认、hover、focus、pressed、selected、disabled、loading、error、empty。
9. **动效**：进入 / 离开 / 屏内移动 / 按压 / 加载；减少动效兜底。
10. **内容**：标题、按钮、错误、空态、加载文案；数字 / 日期 / locale。
11. **无障碍**：对比、焦点、热区、键盘顺序、读屏、强制颜色。
12. **未决项**：需要项目或实现决定的事项。

## 输出

按 [`templates/design-spec.md`](../templates/design-spec.md) 输出。必须写清：

- 结构骨架与信息层级
- 每个区域用的角色 / 面阶 / 间距
- 状态矩阵
- 动效计划
- 无障碍检查
- 未决项与不在本次范围

## 禁止

- 不发明档位 / 角色；没有就标「需要项目自定义」。
- 不写代码、内部路径、实现状态。
- 不把风格当作结构问题的解决方案。
- 不把建议写成强制结论。
