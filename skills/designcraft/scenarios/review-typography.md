# 排版评审

## 目标

判断一份设计稿或组件样式的字号、字重、行高、字距与角色是否落在规范内；不在时给出最近可行档。

## 输入

- 页面 / 组件 / 设计值表；需要时附截图与容器宽度。
- 先确认场景（产品 UI / 内容阅读 / 纸面展示），三者取档策略不同。

## 步骤

1. 列出每个文字块的字号 / 字重 / 行高 / 字距。
2. 字号是否落在 9 档：`10 / 12 / 14 / 16 / 18 / 20 / 24 / 32 / 40`；不在就给最近档与偏差。
3. 字重是否 ∈ `400 / 500 / 600`；`<b>` / `<strong>` 取 600。
4. 行高是否来自 4 档；可换行文字 ≥ 1.4；单行居中必须走居中布局，不用行高制造垂直居中。
5. 字距是否来自 5 档；中文不加负字距。
6. 角色是否对齐：`display / page / card / nav / row / body / desc / meta / mini`；同一档内的差异用字重与区域隔离，不靠加字号。
7. 内容阅读可降一档（16 → 14），控件不降。
8. 角色用到的每个字号档，是否都在项目范围里。

## 输出

按 [`prompts/output.md`](../prompts/output.md)：

- 结论（通过 / 需调整）
- 每条判据与证据（原值 → 最近档 → 偏差）
- 风险（200% 放大、窄视口、译文增长）
- 不把「落在档位」当成「视觉合格」

## 反例

- 16 / 600 与 16 / 500 混用，但说不清哪个是 `row`、哪个是 `nav`。
- 用行高把单行文字压到按钮中心。
- 中文加 `-0.02em` 负字距。
