# 动效与反馈评审

## 目标

判断时长、循环、延迟、曲线、角色与编排是否成立；反馈是否表达状态与因果；减少动效与平台降级是否兜底。

## 输入

- 页面 / 组件 / 交互说明；需要时附录屏或时序。
- 先确认交互类型（进入 / 离开 / 屏内移动 / 按压 / 加载 / 强调）与平台。

## 步骤

1. **时长**：是否来自 6 档；是否有字面量；是否对布局属性做过渡。
2. **循环**：是否只用于 loading / progress / 环境动效；是否把循环当更长的过渡。
3. **延迟**：是否只用于编排；进入 / 离开是否带延迟；序列总预算是否 ≤ 500ms。
4. **曲线**：进入减速、离开加速、屏内标准、连续量匀速；是否直接写贝塞尔曲线。
5. **角色**：进入是否慢于离开；press / color / focus / indicator 是否不带延迟；角色是否只指向设计值。
6. **编排**：是否优先重叠而不是等待；stagger 是否只用于首屏可见项；退出是否不 stagger。
7. **可打断**：快速开关、中途取消、元素移除、最终状态、滚动位置、焦点返回是否成立。
8. **反馈**：press / state / focus 是否按面积与形态选；同一次交互是否不超过两层。
9. **几何**：状态反馈是否改变外框位置或尺寸；框内指示物是否只在框内移动。
10. **减少动效**：时长 / 延迟是否清零；循环是否显式停；状态是否仍可见；焦点与最终状态是否不依赖动画结束。
11. **平台**：小程序 / Web / 原生是否有对应降级；是否依赖不可用能力。

## 输出

按 [`prompts/output.md`](../prompts/output.md)：

- 结论（通过 / 需调整）
- 每条判据与证据（原值 → 目标 → 偏差）
- 风险（布局抖动、不可打断、减少动效、性能）
- 不把「有动效」当成「有反馈」

## 反例

- 进入 200ms、离开 300ms。
- 用 600ms 循环做 loading。
- 对高度或外边距做过渡。
- 退出序列也 stagger。
- 减少动效下把循环时长清零，但无限循环仍在跑。
