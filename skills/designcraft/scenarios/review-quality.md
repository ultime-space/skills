# 感知质量评审

## 目标

判断一套界面是否读得出预期的质量，指出哪些信号在支撑、哪些在抵消，并给出修改顺序。不产出风格配方，不新增设计值，不下阻断性结论。

## 输入

- 页面 / 组件 / 设计稿；能看渲染优先。只有源码时，视觉结论标「未验证」。
- 品类、价格带、品牌承诺、目标受众；缺失时显式问，问不到按假设标注，并说明影响哪些结论。
- 最坏内容：长文案、空态、错误态、译文增长、窄容器。
- 当前风格家族与已有主信号（如果有）。

## 步骤

1. **声明意图**：用一句话写清这套高级感想让人推断什么；写不出就说明当前只能给偏好。
2. **选主信号**：从 [`docs/perceived-quality.md`](../docs/perceived-quality.md) 的六类信号中选 1–2 个主信号，其余降为次信号。
3. **查下限**：对比度、字号、热区、焦点、性能、降级是否仍成立；感知质量不构成豁免。
4. **查完成度**：错字、破图、状态缺失、对齐漂移、跨页不一致、真实内容与空态是否齐全。
5. **取证**：用首因、盲评与最小量表收集感知证据；分数只作辅助，不替代判断。没有条件取证时标「未验证」，不编造结果。
6. **给修改顺序**：先修缺陷，再调主信号，最后才加装饰；说明哪些问题只是偏好。

## 输出

按 [`prompts/output.md`](../prompts/output.md) 的评审报告格式，并补：

- 意图：这套高级感想让人推断什么。
- 主信号：支撑与抵消的证据各是什么。
- 下限问题：哪些可读性、可用性、无障碍问题仍存在。
- 缺陷清单：位置、现象、影响。
- 感知证据：首因、盲评或量表结果；标注证据强度。
- 修改顺序：缺陷 → 主信号 → 装饰。
- 边界：哪些结论只是偏好，哪些需要同界面验证。

## 反例

- 只给「高级、精致、有质感」等形容词，不落到可观察项。
- 把黑、金、衬线、大留白当作通用配方，不问品类与品牌承诺。
- 只改颜色、圆角、阴影，就宣称完成了「高级感优化」。
- 所有信号一起拉满，没有主次。
- 用感知分数当阻断性结论，或用美观推翻可读性与可用性结论。
