# 评审分级与边界

## 目标

把「没达标」「没验」「项目自检」分开，避免一个二进制门槛把未知底判成通过，也避免把上层页面的问题算进设计系统的结论。

## 输入

- 报告行：`pair / ratio / need / target / level / mode / profile / reason / apca`。
- 背景是否已声明；是否属于设计系统的可评审范围。

## 分级

| 条件 | 级别 |
|---|---|
| `ratio ≥ target` | `pass` |
| `floor ≤ ratio < target` | `warn` |
| `ratio < floor` | `deviation` |
| 未知底 | `unverified` |

- `deviation` 只报告，不阻断。
- 例外登记：配对 / 理由 / 负责人 / 复核日期；到期回到 `warn`。
- APCA 只做 `info`，不作门槛。

## 边界

- **可评审范围**：设计值、派生结果、设计系统提供的配对。
- **项目自检**：页面选择器、具体背景上的实际对比度。
- **人检**：局部模式嵌套、图片 / 视频 / 渐变 / 多层透明、整体透明度、色觉差异、强制颜色。

## 输出

- 按报告行列出级别与理由。
- 明确哪些项不在可评审范围。
- 不把「设计系统通过」写成「页面合格」。
- 不把建议写成强制检查；不做阻断性结论。
