# 结构方案（Refine）

## 目标

内容与结构已定，只调整排列、分组、主次与密度：给出 2–3 套结构不同的方案，写清各自代价，由使用者选择。不判定合规，不给唯一答案。

## 报告边界

本场景只出方案集：不产出 HTML、不改文件、不替用户落地。结构线框只在 Markdown 内表达（框、方向、分组），不超过 8 行。用户选定方案后是否落地，由后续请求决定。

## 触发与不触发

| 请求 | 模式 | 场景 |
|---|---|---|
| 点名改哪里（「把间距调大」） | Plan | 直接给调整，不启动本场景 |
| 从 brief 出新页面 | Plan | [`compose-page.md`](./compose-page.md) |
| 已有页面，只调结构、排列、层级、密度 | Plan | **本场景** |
| 判断是否合规 | Audit | [`review-critique.md`](./review-critique.md) |
| 选风格 | Plan | [`build-style.md`](./build-style.md) |
| 只换颜色、圆角、装饰 | — | 不算结构方案；按风格与评审处理 |

## 输入

必须拿到：

- **证据强度**：能看渲染 > 设计稿 > 源码。能打开运行页面时先看渲染；只有源码时，视觉结论标「未验证」；设计稿若是实现的镜像（注释直接引用实现路径），只取视觉意图与比例，不当独立设计源。
- **证据来源**：设计稿、实现代码，或两者。两者都读时先比结构事实是否一致；不一致以实现为准，并在输出里标注差异。
- 固定内容与结构（字段、条目数量、最坏文案）。
- 当前排列方式，以及用户不满意的点（平、挤、散、没重点）。
- 场景与平台、容器宽度。
- 约束：必须保留的元素、不可动的顺序、数据状态。

输入通常不带**空态、加载、错误态与最坏内容**；必须显式问，问不到就按经验假设并在输出里标注。容器宽度等关键事实缺失时，标注「按假设推得」，并写明这一假设会影响哪些结论。

可选：用户不喜欢什么、参考对象、是否允许改分组或顺序。

## 步骤

开始前先按 [`docs/project-types.md`](../docs/project-types.md) 取类型卡与阶段、角色卡，写下「本次先解决什么」与不适用项；类型只调权重，不替代结构判断。

### 1 证据与目标

1. **定证据**：确认是渲染、设计稿还是源码；只有源码时，所有视觉判断标「未验证」，不凭截图或想象补事实。
2. **定目标**：找、比、扫、读、填，哪一个优先；同时列出最坏内容与证据来源。
3. **定关系**：按 [`docs/patterns.md`](../docs/patterns.md) §1.1 判断内容关系（单条、同构集合、比较集合、主辅、序列、录入、异构聚合）；一页有多组关系时分别列出。先定目标再定关系，避免「是否需要比」这一判断反过来依赖关系。

### 2 诊断闸门

只保留通过「诊断三证」的症状；缺一条就降为「偏好」或不写：

- **现象**：具体哪一块、哪一行、什么状态、能观察到什么。
- **影响**：它影响找、比、扫、读、填中的哪一项，或影响最坏内容。
- **可改**：存在一个不改变内容与意图的结构改动能解决它。

默认套路只作候选，不是结论。命中以下任一条，仍要过三证：

- 所有区块都做成等权卡片；
- 所有条目都是「图标 + 标题 + 副标题」；
- 首屏都是大标题 + 三列卡片；
- 同一页所有内容用同一种容器；
- 每个分区都一样长、一样重。

「看起来普通」不构成诊断；只有它确实影响某个目标或最坏内容时才保留。

**停止条件**：没有症状通过三证时，直接写「没有值得改的结构问题」，最多给 1–2 条偏好，不进入方案卡。

### 3 方案生成

4. **取变体**：取 2–3 个结构方向（可用多个条目组合），优先跨档（行 / 卡 / 块、单栏 / 双栏、展开 / 独立页），不要同一档的三个微调。
5. **写代价**：每条按五项报账——可比较性、一屏信息量、定位成本、最坏内容风险、一致性。
6. **查约定**：对照页面族约定，确认新增、条目操作、筛选、提交、危险操作仍在原槽位；有冲突就写明影响范围，不擅自改全站。
7. **给推荐与开关**：推荐一套并说明理由；写一句「如果你更看重 X，就选另一套」。

### 4 交付校验

- **固定项**：内容、字段、顺序与动作是否都还在；没有擅自改动用户声明为固定的部分。
- **最坏内容**：长文案、空数据、译文增长、窄容器是否仍成立。
- **结构重心**：是否只有一套主结构；三套是否只是同一模板的微调。
- **确认项**：视觉结论标「待人工确认」，不声称已通过评审。

## 两级范围

| 级别 | 允许动 | 默认 |
|---|---|---|
| **A 排列级** | 容器形态、排列方向、主次、对齐、密度 | 是 |
| **B 结构级** | 在 A 之上允许重排分组或调整顺序 | 否，需用户明确同意 |

B 级只在页内重排，不改导航、页面归属与信息架构；这些属于更上层的决定。官网 / 落地页的叙事顺序只在用户明确授权时按 B 级处理。

用户说「不好看」通常只授权 A；改分组或顺序会动到信息架构，先问。

## 不硬编码

- 用相对关系表达：「图标明显大于正文行高」「标题与副标题纵向堆叠」「卡片等高」。
- 需要具体值时写「由业务侧按自身设计值取」，不冒充系统值、不发明档位。
- 可以给占位变量名，但占位不是可发布的设计值。
- 不把某一套方案写成默认规则。

## 输出

按 [`templates/option-set.md`](../templates/option-set.md) 输出方案集：范围、诊断、2–3 张方案卡、推荐与偏好开关、交付校验、待确认。

诊断不成立时，按停止条件输出，不套方案卡。

线框只画结构（框、方向、分组），不超过 8 行；细节线框会被误读成定稿。

## 禁止

- 三套只是换颜色、换圆角、换阴影，结构没变。
- 用类型卡直接套页面清单，或用类型倾向替代结构判断。
- 按页面长相直接选条目，跳过「先定目标、再定关系」。
- 没有通过三证的诊断仍强行出方案。
- 直接给一套「最佳实践」，不留选择。
- 把方案写成强制规则或阻断结论。
- 改动用户声明为固定的内容、顺序或字段。
- 在方案里引入新的字号档、间距档或颜色角色。
- 擅自改动页面族的操作槽位；跨页一致性问题只提示，不在这里重排全站。
- 产出 HTML、直接改文件，或把 Markdown 线框做成可交付页面。
- 把默认套路清单当规则；它只用于诊断扫描。
