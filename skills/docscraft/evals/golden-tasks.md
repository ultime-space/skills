# Golden Tasks

> 用途：人工 / agent 回归 Docscraft 的行为。每条任务只测一个判断，不测文风。
> 记录：版本、通过 / 失败、误报数、漏报数、审稿轮次。

## 1. 找出双份正文

- 输入：README 与 rules 各写一份同一规则。
- 期望：指出两处、建议保留哪一处、其它改指针。
- 失败信号：只说“有重复”，不指出位置 / 不给合并方案。

## 2. 迁移 `.agents/rules/` 正文

- 输入：旧项目正文在 `.agents/rules/`，`rules/` 只有索引。
- 期望：正文迁到端 `rules/`，`.agents/rules/` 只留“先读”索引。
- 失败信号：双写；只改新路径不改旧链接。

## 3. 写 ADR

- 输入：一个已做的架构取舍，有两个备选方案。
- 期望：背景、选项、决定、后果、验证齐全；写代价；不复制规范全文。
- 失败信号：只有决定；没有备选；把 ADR 写成规范。

## 4. 规则过期

- 输入：判断型规则无 owner、复核日期已过。
- 期望：标过期、降级为“参考”、给出续期 / 删除建议。
- 失败信号：继续当硬门禁；直接删除不记录。

## 5. AI 入口过长

- 输入：`AGENTS.md` 超过两屏，包含完整规范。
- 期望：保留先读、≤12 红线、验证命令；其余移到 `rules/` / `docs/`。
- 失败信号：只做排版；把正文复制到另一个文件。

## 6. 事实漂移

- 输入：文档手写字段清单，源码已变更。
- 期望：指出事实型内容应生成；给生成源 / 查询命令。
- 失败信号：直接改文档数字；不找来源。

## 7. 上游文档复制

- 输入：仓库复制了上游组件库文档全文。
- 期望：改用 canonical link + 本地差异 + 版本要求。
- 失败信号：继续维护全文；只加一句“参考官方”。

## 8. 可移植性

- 输入：待抽成 skill 的本地笔记，含客户名、本机路径、个人偏好。
- 期望：只保留通用方法；项目事实 / 本机路径 / 偏好留在本地。
- 失败信号：整段搬进 skill；保留绝对路径。

## 评分

- 每条：pass / fail。
- 目标：一次通过率上升，审稿轮次下降；不以“写得多”为通过标准。
