# 交付前清单 v1

> 2026-10-27 · v1
> 用途：约束 Audit 模式的判定与交付前自检，防止把「链接全绿 / 测试通过」写成「文档没问题」。
> 范围：文档分层、真源、规则、决策、链接、生成物、示例与术语；代码架构判断用 Codecraft。
> 关系：方法见 `docs/guides/04-drift-guards.md`；格式见 `prompts/output.md`；入口契约见 `docs/contracts/03-ai-context.md`。

## 1. 必填结构

Audit 报告必须包含：

1. **结论**：文档是否可作为真源；主要风险是什么。
2. **范围与方法**：仓库 / 目录、只读声明、执行的命令、未执行项与原因。
3. **文档地图**：入口、正文、决策、生成物、索引各在哪。
4. **逐条判定**：D1–D13 全覆盖；不适用写 `na` 并说明原因。
5. **问题表**：问题、证据、影响、优先级。
6. **修复计划**：阶段、内容、可回滚、验收。
7. **验证**：命令 + 结果；不能跑要写原因。
8. **局限**：机检覆盖不到的部分。

逐条判定表固定为：

```md
| ID | 判定 | 证据 | 局限 |
|---|---|---|---|
| D1 | warn | `README.md:24` 与 `rules/api.md:8` 同一错误码规则各写一份 | 未检查历史分支 |
```

## 2. 判定口径

| 判定 | 含义 |
|---|---|
| `pass` | 有人工抽样或机检覆盖，且没有相反证据 |
| `pass（结构）` | 只通过了结构类检查（链接、路径、术语表）；不能替代语义判断 |
| `warn` | 存在相反证据、覆盖不完整，或只有部分满足 |
| `fail` | 明确违反，且会造成真源错误、规则失效或信息外泄 |
| `na` | 该检查项不适用；必须写原因 |

证据要求：

- 文件级：`path/to/file.md:line`；不要只写目录。
- 命令级：写出命令与结果；计数必须带可复现的检索式。
- 禁止「整体清晰」「基本一致」这类无证据结论。
- 一个检查项有多个子项时逐项给证据；不能用一个子项代表全部。

## 3. 判定矩阵

| ID | 判定方式 | `pass` 条件 | 常见误判 |
|---|---|---|---|
| D1 | 人工 + 检索 | 同一事实只有一份正文，其余位置只放指针 | 措辞不同就当两份；只看入口不看正文 |
| D2 | 人工 + 结构检索 | README / AGENTS / rules / docs / ADR 职责清楚，入口不超过两屏 | 入口很长但「什么都有」 |
| D3 | 人工 | 人 / agent / 维护者各有入口，不互相复制正文 | 把 README 当 agent 入口用 |
| D4 | 人工 + 到期表 | 每条规则能归入事实 / 约束 / 判断；判断型有 owner 与复核日期 | 只写「保持一致」，不写怎么检查 |
| D5 | 机检 + 人工 | 事实漂移：字段 / 类型 / 默认值 / 目录清单来自生成源或查询命令 | 链接全绿就判 `pass` |
| D6 | 机检（链接 + 路由） | 结构漂移：路径变更后入口、索引、链接同步 | 只改新路径，不查旧链接 |
| D7 | 机检（lint / CI）+ 人工 | 规则漂移：写了「必须」的规则有对应检查；检查变更时规则同步 | lint 通过，但规则本身写错 |
| D8 | 人工 | 决策漂移：ADR 与现行规范、实现一致；不一致时有后续 ADR | 把 ADR 当规范正文维护 |
| D9 | 机检 | 链接漂移：内链与跨仓链接可达；公开文档无内部路径 / 主机名 | 忽略域名清单过长；只查 Markdown 不查 HTML |
| D10 | 机检（重生成 diff） | 生成物漂移：生成物标注勿手改，重生成 diff 为空 | diff 为空，但生成源错了 |
| D11 | 机检 + 人工 | 示例漂移：命令 / 代码示例可执行；不可执行的标「示意」 | 示例写了但没人跑 |
| D12 | 机检（术语表）+ 人工 | 术语漂移：每套文档只保留一份术语表；同一概念一种叫法 | 每个单元格都加中文，维护两份翻译 |
| D13 | 机检（密钥 / 路径 / 链接）+ 人工 | 安全与引用：无隐私、凭据与内部路径；第三方引用有来源与许可；外部文档不引内部 | 只扫密钥就判 `pass`；截图、示例与引用不查 |

## 4. 一致性检查

出结论前必须交叉检查；发现矛盾就降级：

| 场景 | 要求 |
|---|---|
| D5 判 `pass`，但只跑了链接检查 | 降为 `pass（结构）` 或 `warn`；事实没有来源 |
| D7 判 `pass`，但只有 lint，规则本身无 owner / 到期 | 改为 `warn` |
| D9 判 `pass`，但死链检查忽略了大量域名 | 改为 `warn`，列出忽略项 |
| D10 判 `pass`，但没有重生成比对 | 改为 `warn`；只能写「生成物有只读标记」 |
| D1 判 `pass`，但入口与正文各写一份同一规则 | 改为 `fail`；先合并再加新内容 |
| D8 判 `pass`，但 ADR 与现行规范相反 | 改为 `warn`；补一份新的 ADR |
| D13 判 `pass`，但只跑了密钥扫描 | 改为 `warn`；隐私、引用与许可未抽查 |
| 只跑了结构测试（链接 / 术语 / 版本对齐） | 所有项最多 `pass（结构）`，不能写成 `pass` |

## 5. 机检映射

| 检查项 | 机检形态 |
|---|---|
| D5 事实清单 | 从源码 / 类型 / 配置生成，或给出查询命令 |
| D6 路径与入口 | 链接检查 + `SKILL.md` 路由存在性测试 |
| D7 约束规则 | lint / typecheck / 单测 / CI 阻断 |
| D9 链接 | lychee / markdown-link-check / 自建链接测试 |
| D10 生成物 | 重生成 + `git diff --exit-code` |
| D11 示例 | 脚本执行或 doctest |
| D12 术语 | 术语表测试 / prose lint |
| D13 安全与引用 | secret scanning + 内部路径 / 主机名模式 + 人工抽查截图、示例与引用 |
| D1 / D2 / D3 / D4 / D8 | 只能人工；写 owner 与复核方式 |

## 6. 交付前自检

- [ ] D1–D13 全部出现，或写明 `na` 与原因
- [ ] 每条 `pass` / `warn` 都有路径或命令
- [ ] 所有计数都能用文中命令复现
- [ ] 已做一致性检查，没有把「结构测试通过」写成「文档没问题」
- [ ] 已写明机检覆盖不到的部分
- [ ] 没有客户名、内部路径、密钥
- [ ] 隐私、第三方引用与许可已检查（D13）
- [ ] Audit / Plan 只读；未改文件
- [ ] 修复计划每阶段可回滚、有验收

## 7. 计划表

```md
| 阶段 | 内容 | 可回滚 | 验收 |
|---|---|---|---|
| 0 | 修正错误事实与入口 | 纯文档，单 commit 可回退 | 描述与检索结果一致 |
| 1 | 合并双份正文 | 保留旧文件一个版本 | 只剩一份正文与指针 |
```

要求：

- 每阶段可独立回滚，不用「重来一遍」。
- 验收必须是可执行命令或可检索结果，不写「感觉完成」。
- 不写时间估算；写依赖与顺序。
- 先修入口与错误事实，再合并重复正文。
