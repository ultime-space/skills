# 文档安全与引用边界

> 2026-10-28 · v1
> 用途：判断哪些内容不能进文档、第三方内容怎么引、版权与许可怎么处理、发现泄漏怎么处置。
> 范围：README、AGENTS、rules、docs、ADR、交付文档与对外报告。
> 关系：代码与仓库密钥扫描归 Codecraft A21；本文只管文档内容与引用。安全红线不可豁免。

## 1. 先分级

| 级别 | 谁可以看 | 例子 | 写法 |
|---|---|---|---|
| Public | 任何人 | 公开 README、对外报告、发布说明 | 不含内部路径、主机名、客户名 |
| Internal | 团队 / 仓库成员 | rules、内部 docs、ADR | 可写内部路径，不写凭据与客户隐私 |
| Confidential | 指定人 | 合同、客户数据、密钥、审计底稿 | 不进 git；放 `.local/` 或私密存储；不进提示词 |

- 不确定时按更高一级处理。
- 外部文档不引用内部文档、内部路径、内部主机名、内部系统名。
- 交付物从声明的交付目录取，不整体打包 `docs/`。

## 2. 隐私与个人信息

禁止把真实个人数据写进文档，包括正文、示例、截图与日志片段：

- 姓名、手机号、身份证 / 护照、地址、邮箱、头像、车牌、订单号、病历、薪资。
- 生产数据、真实用户对话、客服工单原文。
- 截图里的账号、余额、通讯录、通知栏。

要求：

- 示例统一用占位符：`<手机号>`、`user@example.com`，人名用「用户 A」。
- 截图打码或重绘；去掉 EXIF 与定位；必要时用构造界面替代真实截图。
- 客户名、项目代号按合同约定脱敏；不确定就问。

## 3. 凭据与内部信息

- 禁止出现：密码、token、AK/SK、连接串、私钥、Cookie、内网 IP / 域名、VPN 地址、内部系统名。
- 示例配置只写占位符与环境变量名，不写真实值。
- 文档里出现密钥：**停止编辑 → 删除 → 提示轮换 → 检查历史提交**；删文件不等于安全。
- 截图、附件、示例文件同样适用，不只正文。

## 4. 第三方引用

- 标来源：名称 + 链接 + 版本 / 访问日期；没有链接的写「来源待确认」，不冒充事实。
- 区分事实与观点：官方文档、源码、发布记录是事实；博客、演讲、二手对比是线索。
- 引用限度：只引关键句与结论；不整段复制、不改写后当原创、不用引用替代原文。
- 不引用不可公开的内部资料；不把付费或受限内容大段贴进公开文档。
- 同一事实只留一份正文；外部已有正文用 canonical link + 本地差异。

引用句式：

> 来源：<名称>（<链接>，访问 YYYY-MM-DD，版本 <version>）

## 5. 版权与许可

- 使用第三方文本、图片、字体、图标、代码片段前，先确认许可：能否商用、能否修改、是否要求署名、是否要求同许可分发。
- 保留必要的版权声明与署名；不删除原作者信息。
- 专有或未声明许可的内容，默认不复制、不改编；需要时取得书面授权。
- 客户提供的素材只在授权范围内使用；文档里标注来源与授权范围。
- 代码片段优先给最小可运行示例或伪代码，避免整段搬运。

## 6. 发现后的处理

| 情况 | 动作 |
|---|---|
| 发现密钥 / 凭据 | 停止、删除、提示轮换、检查历史与构建产物 |
| 发现个人隐私 | 停止、脱敏、确认是否已外发 |
| 发现未授权引用 / 版权内容 | 停止、移除或替换为链接、补授权或署名 |
| 不确定 | 按更高分级处理，先问 owner；不猜 |

## 7. 怎么检查

- 机检：secret scanning、内部路径 / 主机名模式、死链、附件元数据。
- 人工：抽查示例、截图、第三方引用与许可声明。
- 审计：对应 `docs/contracts/08-checklist.md` 的 D13；`0 findings` 只写「静态未命中」，不等于通过。
- 安全红线不可豁免；不能登记为例外。

## 反模式

- 用真实截图演示功能，忘了打码。
- 从博客整段复制结论，不标版本与日期。
- 把客户合同条款贴进公开文档。
- 引用付费报告的大段内容。
- 示例配置写真实 AK/SK，注释说「已脱敏」。
- 发现密钥后只删当前文件，不轮换、不查历史。
