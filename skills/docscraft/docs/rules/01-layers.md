# 文档分层

> 用途：决定一条内容放哪里，以及各层之间的边界。
> 口径：入口只做索引与红线；正文只留一份；决策只记理由。

## 推荐布局

```text
repo/
├── README.md              # 人：是什么、怎么跑、目录、贡献
├── AGENTS.md              # agent：先读什么、红线、验证命令
├── client/
│   ├── AGENTS.md          # 端级入口
│   └── rules/             # 端级正文：页面 / API / 状态 / 类型 / 样式
├── server/
│   ├── AGENTS.md
│   └── rules/
├── docs/
│   ├── adr/               # 决策记录
│   ├── architecture/      # 架构说明（只放稳定结论）
│   └── ...                # 交付 / 设计 / 运维文档
├── .agents/rules/           # 只做入口索引，不放正文
└── .local/notes/          # 本地调研 / 草稿，不进 git
```

## 各层职责

| 层 | 读者 | 放什么 | 不放什么 |
|---|---|---|---|
| `README.md` | 人 | 项目定位、快速开始、目录、流程、贡献入口 | 细则、长规则、决策论证 |
| 根 `AGENTS.md` | agent | 先读顺序、≤12 条红线、项目状态、验证命令 | 完整规则正文、教程 |
| 端 `AGENTS.md` | agent | 端级入口、端级红线、端级验证 | 重复根入口 |
| `rules/` | 维护者 / agent | 事实、约束、判断型规则；按领域拆分 | 决策历史、营销文案 |
| `docs/` | 人 / 维护者 | 交付文档、架构说明、设计说明、运维手册 | 日常规则正文 |
| `docs/adr/` | 维护者 | 决策、备选方案、取舍、后果 | 现行规范全文 |
| `.agents/rules/` | agent | “该读哪些文件”的索引 | 规则正文 |
| `.local/notes/` | 个人 | 调研、草稿、对比、临时结论 | 项目真源、客户可公开内容 |

## README / AGENTS / rules / docs 的边界

### README

回答“我第一次来，怎么开始”。控制在可扫读的长度；细节链接到 `docs/` 或 `rules/`。

### AGENTS

回答“agent 开工前必须知道什么”。建议 ≤12 条红线，每条是：

```text
禁止 X，因为 Y。
反例：……
```

验证命令写在入口，不写在每条规则里。

### rules

回答“这一类事情具体怎么做”。按领域拆分，例如：

- `pages.md`：页面结构、路由、状态
- `api.md`：请求层、错误、契约
- `types.md`：类型来源、命名、生成
- `styles.md`：token、布局、响应式

每条规则必须能归入事实 / 约束 / 判断（见 `docs/rules/05-rule-types.md`）。

### docs

回答“交付物、架构、设计、运维怎么做”。可以长，但只放稳定结论；过期内容删除或移入 ADR。

## agent 入口目录的定位

agent 入口（如 `.agents/rules/`、`AGENTS.md`）只做索引：

```md
# 先读

1. ../../AGENTS.md
2. ../rules/pages.md
3. ../rules/api.md
```

不要把正文放进去。原因：

- 入口随 agent 变化，正文会跟着失效
- 与 `rules/` 形成第二真源
- 历史项目迁移时容易只改一边

老项目正文写在 agent 入口目录里的，按“迁移”处理，不做长期双写。

## 内容放哪里：决策树

```text
这条内容是什么？
├─ 事实（字段 / 清单 / 形状）
│  ├─ 能从源码 / 类型生成 → 生成物 + 查询命令
│  └─ 不能生成 → rules/ 的事实段，标注来源
├─ 约束（必须 / 禁止）
│  ├─ 能机检 → lint / CI，文档只写入口
│  └─ 不能机检 → rules/，写清条件与反例
├─ 判断（取舍 / 例外）
│  ├─ 一次性决策 → ADR
│  └─ 长期规则 → rules/ + owner + 复核日期
├─ 操作步骤 → docs/ 或 README 的快速开始
└─ 调研 / 草稿 → .local/notes/（不进 git）
```

## 新增一个端 / 包时

1. 建 `<area>/AGENTS.md`，只写入口、红线、验证。
2. 建 `<area>/rules/`，按领域拆正文。
3. 在根 `AGENTS.md` 加一行指针，不复制端级内容。
4. 在根 `README.md` 的目录表加一行。
5. 检查是否有旧 `.agents/rules/` 正文需要迁移。

## 迁移旧项目

1. 先盘点：哪些正文在 `.agents/rules/`，哪些在 README / docs。
2. 把正文迁到 `<area>/rules/`，按领域拆；`.agents/rules/` 只留索引。
3. 合并重复：同一规则只留一份，其它改指针。
4. 更新根 / 端 `AGENTS.md` 与 README 链接。
5. 跑链接检查、生成物比对、示例验证。
6. 旧路径保留一个版本的重定向说明，下一次删除。

## 反模式

- README 里写完整规则，rules 里再写一遍
- 根 AGENTS 复制端 AGENTS
- `.agents/rules/` 存正文，`rules/` 存索引
- `docs/` 里放会频繁变化的规则
- ADR 里写现行规范全文
- 迁移时只改新路径，不改旧链接
