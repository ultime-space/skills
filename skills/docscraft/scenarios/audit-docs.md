# 审计现有文档

## 何时用

接手项目、文档混乱、agent 经常读错规则、准备重构文档结构前。

## 输入

- 仓库路径 / 分支
- 范围：全仓 / 某个端 / 某个目录
- 读者：人 / agent / 维护者

## 先读

项目 `README.md` → 根 / 端 `AGENTS.md` → `rules/` → 相关 `docs/`。

## 步骤

1. 画文档地图：入口、正文、决策、生成物、索引。
2. 标出每条事实的唯一来源；找不到来源的标“待确认”。
3. 找双份正文：同一规则 / 同一事实出现两次以上。
4. 找入口问题：README / AGENTS 是否说清“先读什么”；是否超过一屏。
5. 找规则问题：是否分事实 / 约束 / 判断；判断型是否有 owner / 日期。
6. 找漂移：过期字段、命令、数字、链接、生成物、示例。
7. 找 `.agents/rules/` 正文残留。
8. 出最小修复计划：先入口与错误事实，再合并重复正文。

## 输出

按 `prompts/output.md`：

- 结论
- 文档地图
- 问题表（证据 / 影响 / 优先级）
- 修复计划（阶段 / 回滚 / 验收）
- 验证
- 局限

## 验收

- 只读；不改文件
- 每条结论有路径 / 命令
- 不把“链接全绿”当成文档没问题
- 计划每阶段可回滚、有验收
