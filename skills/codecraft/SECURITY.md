# Security Policy（安全策略）

> 定位：漏洞与凭据泄露的报告方式；不在这里披露细节。
> 状态：现行（2026-10）。
> 关系：文档安全边界见 `docs/rules/00-constitution.md` §3.6；AI 约束见 `docs/contracts/02-ai-contract.md`。

## 报告

- 不要在公开 Issue 中粘贴密钥、令牌、客户数据或可利用细节。
- 通过仓库的私有安全通道联系维护者；没有通道时先开一个不含敏感信息的 Issue，说明「需要私下同步」。
- 报告请包含：受影响的版本、最小复现、影响面、建议修复方向。

## 处理

1. 维护者确认后先轮换已泄露的凭据，再修代码。
2. 修复进入 `fix/<主题>` 分支，`rebase main` 后合并。
3. 破坏性修复在 CHANGELOG 标注；需要时补回归测试。

## 范围

- 本包是静态规则与 CLI，不执行网络请求；主要风险是密钥 / 隐私被写进规则、示例或报告。
- 依赖漏洞按 `npm audit` / 依赖升级处理，不在规则层重复实现。
