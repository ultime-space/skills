# 设计模式工具箱（可选）

> 用途：AI 与人的「可选工具」，不是必背清单；按力（forces）选，不按名字选。
> 范围：模式本身与语言无关；第 4 / 5 节分别是 JS/TS 惯用与前端 / UI 专用。
> 术语：English（中文）。
> 原则：**先有痛点，再选模式；没有代价说明的模式，不许用。**

## 0. 选型四问

1. **变化点是什么？** 创建、结构、行为、数据、交互、横切？
2. **生命周期是什么？** 一次性、请求级、页面级、应用级？
3. **有替换需求吗？** 多实现、多平台、mock、灰度？
4. **代价是什么？** 文件数、缩进、运行时、认知、包体积？

> 四问答不出来，说明还不需要模式；先写直白代码（A14）。

## 1. 创建型（Creational）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Singleton（单例） | 保证一个类只有一个实例，并提供全局访问点 | 配置、日志、连接池、全局 store | 业务状态、可测试性要求高、多实例 | 全局可变状态、测试隔离差 |
| Factory Method（工厂方法） | 定义创建接口，让子类 / 实现决定实例化哪个类 | 多实现、按环境 / 平台选择 | 只有一个实现、创建逻辑简单 | 多一层间接 |
| Abstract Factory（抽象工厂） | 创建一组相关对象家族 | 多主题 / 多平台组件族 | 只创建一个对象、家族不稳定 | 抽象重、扩展成本高 |
| Builder（建造者） | 分步构建复杂对象 | 多参数、可选步骤、配置对象 | 参数少、对象简单 | 样板多 |
| Prototype（原型） | 通过克隆已有对象创建新对象 | 初始化昂贵、对象结构复杂 | 对象简单、需要独立构造 | 深浅拷贝陷阱 |

## 2. 结构型（Structural）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Adapter（适配器） | 把外部接口转成内部统一接口 | 多平台请求 / 存储 / 路由 / 导出 | 只有一个实现且不会换 | 多一层映射、能力差异被抹平 |
| Bridge（桥接） | 抽象与实现分离，各自独立变化 | 多维度变化（平台 × 主题） | 只有一个维度 | 抽象层增加 |
| Composite（组合） | 树形结构，叶子与容器同一接口 | 菜单、组件树、文件树、槽位 | 扁平列表、层级不稳定 | 递归、调试深 |
| Decorator（装饰器） | 动态给对象加职责，不改进原对象 | 加日志 / 权限 / 缓存 / 重试 | 需要改内部结构、顺序敏感 | 包装层多、调试跳转多 |
| Facade（外观） | 给复杂子系统一个简单入口 | 请求层、SDK 封装、跨模块流程 | 子系统简单、入口会变上帝对象 | 门面膨胀、隐藏能力 |
| Flyweight（享元） | 共享内在状态，减少对象数量 | 图标 / 字体 / 大列表、缓存 | 状态差异大、对象少 | 共享状态管理复杂 |
| Proxy（代理） | 用代理控制对原对象的访问 | 懒加载、权限、缓存、响应式 | 直接访问更简单、无控制需求 | 多一层、性能开销 |

## 3. 行为型（Behavioral）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Chain of Responsibility（责任链） | 请求沿处理器链传递，直到被处理 | 中间件、拦截器、审批流 | 处理顺序不重要、链短 | 链路难追踪、可能无人处理 |
| Command（命令） | 把请求封装成对象，可排队 / 撤销 / 重放 | 撤销重做、patch、宏、队列 | 一次性操作、无撤销需求 | 对象多、序列化成本 |
| Interpreter（解释器） | 为语言定义文法并解释句子 | DSL、规则引擎、查询表达式 | 文法简单、只一种规则 | 类爆炸、性能 |
| Iterator（迭代器） | 顺序访问集合，不暴露内部结构 | 分页、游标、树遍历 | 直接数组访问足够 | 多一层抽象 |
| Mediator（中介者） | 用中介集中对象间通信 | 复杂表单联动、组件通信 | 对象少、直接通信更清晰 | 中介变上帝对象 |
| Memento（备忘录） | 捕获并恢复对象状态 | 撤销、快照、草稿 | 状态大、无恢复需求 | 内存、序列化 |
| Observer（观察者） | 发布者通知订阅者 | store subscribe、事件、跨组件通知 | 简单父子通信、事件链短 | 泄漏、顺序 / 异常、事件意大利面 |
| State（状态） | 行为随状态改变，状态是一等类型 | 异步、互斥状态、多步流程 | 纯视觉开关、无守卫 | 样板、状态爆炸 |
| Strategy（策略） | 可互换算法，运行时按键选择 | 多算法 / 多渠道 / 多导出 | 分支签名不同、只有 2–3 个局部分支 | 表丢穷尽性、调试多一跳 |
| Template Method（模板方法） | 骨架固定，步骤由子类 / 回调实现 | 流程骨架、生命周期钩子 | 步骤差异大、流程常变 | 继承耦合、难组合 |
| Visitor（访问者） | 在不改对象结构的前提下加操作 | AST、报表、树遍历 | 结构常变、操作少 | 双分派、理解成本 |

## 4. 函数式与 JS/TS 惯用（Functional / JS）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Higher-Order Function（高阶函数） | 接收或返回函数 | 回调、装饰、策略注入 | 简单直接调用 | 调试栈深 |
| Function Composition（函数组合） | 把小函数组合成大函数 | 数据管道、转换链 | 步骤有副作用、顺序敏感 | 错误定位难 |
| Currying（柯里化） | 多参函数转成一元函数链 | 配置复用、部分应用 | 参数固定、可读性优先 | 调用形式陌生 |
| Partial Application（偏应用） | 固定部分参数，返回新函数 | 复用配置、事件处理 | 简单调用 | 额外函数 |
| Memoization（记忆化） | 缓存纯函数结果 | 昂贵计算、重复查询 | 结果易变、内存敏感 | 缓存失效、内存 |
| Lazy Evaluation（惰性求值） | 需要时才计算 | 大列表、昂贵初始化 | 结果马上要用 | 时机难追踪 |
| Immutable Data（不可变数据） | 不修改原数据，返回新数据 | 状态更新、撤销、并发 | 大对象高频更新 | 拷贝成本 |
| Lens（透镜） | 可组合的嵌套 getter / setter | 深层状态更新 | 浅层对象 | 概念成本 |
| Monad（单子） | 带上下文的链式计算 | 可选值 / 错误 / 异步链 | 普通同步代码 | 学习成本高（前端少用） |

## 5. 前端与 UI（Frontend / UI）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Container / Presentational（容器 / 展示） | 容器取数，展示只渲染 | 页面与纯展示分离 | 组件很小、取数简单 | 文件多 |
| Higher-Order Component（高阶组件） | 函数接收组件返回新组件 | 横切能力（权限 / 埋点） | Hooks 可解决、层级多 | 嵌套地狱、props 冲突 |
| Render Props（渲染属性） | 用函数 prop 决定渲染 | 共享有状态逻辑 | Hooks 可解决 | 嵌套、可读性 |
| Hooks / Composables（钩子 / 组合式函数） | 复用有状态逻辑 | 取数、表单、分页、订阅 | 纯函数足够、逻辑简单 | 规则约束、闭包陷阱 |
| Provider / Inject（提供 / 注入） | 跨层级传递依赖 | 主题、i18n、权限、弹窗 | 层级浅、props 清晰 | 来源难追踪 |
| Compound Components（复合组件） | 父子组件共享隐式状态 | Tabs、Select、Menu | 结构简单、无共享状态 | 隐式契约 |
| Headless Components（无头组件） | 只给状态与行为，不给样式 | 设计系统、跨端 UI | 一次性页面 | 抽象成本 |
| Controller（控制器） | 把 UI 逻辑从视图抽出 | 复杂页面、可测逻辑 | 简单页面 | 多一层 |
| State Machine（状态机） | 显式状态 + 事件 + 转移 | 异步、互斥、多步流程 | 纯视觉开关 | 样板、状态爆炸 |
| Reducer（归约器） | `(state, action) => state` | 可预测状态更新 | 简单局部状态 | 样板 |
| Store（状态仓库） | 集中状态 + 订阅 | 跨页面共享、持久化 | 局部状态 | 全局化、耦合 |
| Event Bus / Pub-Sub（事件总线 / 发布订阅） | 全局发布订阅 | 跨模块解耦 | 可追踪性要求高 | 意大利面、泄漏 |

## 6. 数据与韧性（Data / Resilience）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Repository（仓储） | 集合式数据访问，隔离存储细节 | API 模块、缓存、离线、多数据源 | 一次性请求、纯展示 | 抽象泄漏、分页 / 缓存语义 |
| Source Adapter（来源适配） | 每个外部来源一个成功判定 / 拆包 / 错误映射，对外统一结果 | 多后端、第三方 API、OSS、上传、GraphQL | 单一来源的简单请求 | 每个来源一份适配代码 |
| Optimistic Update（乐观更新） | 先改本地，失败回滚 | 点赞、收藏、低风险读侧展示 | 金额 / 权限 / 强一致 / 上传保存业务状态 | 回滚与冲突处理 |
| Cache-Aside（旁路缓存） | 先查缓存，未命中再加载 | 读多写少、配置 / 字典 | 强一致、频繁写 | 失效策略 |
| Stale-While-Revalidate（过期重验） | 先返回旧数据，再后台刷新 | 列表、详情、弱实时 | 强一致、首次必须最新 | 数据短暂过期 |
| Circuit Breaker（熔断） | 连续失败后暂停调用，半开探测 | 第三方 API、不稳定下游 | 本地纯函数 | 状态与阈值 |
| Retry / Backoff（重试 / 退避） | 失败后延迟重试 | 网络抖动、幂等请求 | 非幂等、确定性失败 | 放大流量、延迟 |
| Feature Flag（特性开关） | 运行时开关功能 | 灰度、AB、回滚 | 永久配置、无开关治理 | 分支膨胀、技术债 |

- 写操作的 loading 由请求状态驱动，放在触发组件上；不要用全屏 loading 掩盖局部失败。

## 7. 架构（Architecture）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| MVC（模型-视图-控制器） | Model / View / Controller 分工 | 简单–中型应用、传统框架 | 复杂状态、强测试 | 规模化难 |
| MVP（模型-视图-展示器） | View 被动，Presenter 承担逻辑 | 需要可测展示逻辑 | 简单页面 | 样板多 |
| MVVM（模型-视图-视图模型） | ViewModel 暴露状态，View 自动绑定 | 响应式框架、复杂 UI | 无响应式系统 | 绑定魔法、调试 |
| Flux / Redux（单向数据流） | 单向数据流 + 纯 reducer | 可预测全局状态、时间旅行 | 局部状态、小应用 | 样板、全局化 |
| Clean Architecture（整洁架构） | 依赖向内，核心独立 | 长期、复杂业务 | 小工具、脚本 | 层多、映射多 |
| Hexagonal Architecture（六边形架构） | 端口与适配器，核心不知外部 | 多外部系统、可替换 IO | 单一 IO、简单应用 | 端口 ceremony |
| Vertical Slice（垂直切片） | 按功能切竖片 | 功能多、变更按 feature | 共享逻辑多、强横切 | 跨片重复 |

## 8. 并发与数据访问（Concurrency / Data Access）

| 模式（中英） | 一句话 | 何时用 | 何时不用 | 代价 |
|---|---|---|---|---|
| Unit of Work（工作单元） | 跟踪变更，一次提交 | 多写操作需原子性 | 单条写、无事务 | 状态跟踪复杂 |
| Data Mapper（数据映射器） | 在对象与存储之间映射 | 领域模型与存储解耦 | 简单 CRUD | 映射代码多 |
| Active Record（活动记录） | 对象自带 CRUD | 简单 CRUD、小项目 | 复杂领域、测试隔离 | 领域与存储耦合 |
| Identity Map（身份映射） | 同一行只保留一个对象 | 避免重复实例、一致性 | 无对象身份需求 | 内存、生命周期 |
| Actor（参与者） | 独立状态 + 邮箱，串行处理消息 | 并发、隔离、分布式 | 简单同步逻辑 | 消息协议、调试 |
| Worker / Queue（工作线程 / 队列） | 后台任务队列 | 重任务、异步、削峰 | 即时轻任务 | 运维、重试、幂等 |

## 9. 反模式（Anti-patterns）

| 反模式（中英） | 表现 | 后果 | 替代 |
|---|---|---|---|
| God Object（上帝对象） | 一个类 / 模块什么都知道 | 难改、难测、冲突多 | 按职责拆 |
| Anemic Domain Model（贫血领域模型） | 数据与行为分离，逻辑散在 service | 规则重复、边界模糊 | 把规则放回领域 / 纯 core |
| Event Bus Spaghetti（事件总线意大利面） | 全局事件到处发 / 收 | 难追踪、泄漏、顺序问题 | 显式调用 / 状态机 |
| HOC Hell（高阶组件地狱） | 多层包装、props 改名 | 调试难、类型难 | Hooks / Composables |
| Inheritance Hell（继承地狱） | 深继承、覆写链 | 脆弱、难组合 | 组合优先 |
| Prop Drilling（属性钻透） | 层层传 props | 中间层污染 | Provider / Inject / Store |
| Global Singleton（全局单例） | 全局可变状态 | 测试隔离差、隐式依赖 | 显式传参 / 依赖注入 |
| Over-abstraction（过度抽象） | 为未来造层、造 port | 认知成本、文件多 | 等第二个消费方 |
| Golden Hammer（金锤子） | 所有问题都用同一模式 | 不适配、变形 | 按力选型 |
| Optimistic Write（乐观写业务状态） | 上传 / 保存先写本地临时值（表单 / store）再请求，失败不回滚 | 临时路径 / 半成品进库 / 进缓存 | 先请求成功再落状态，或显式回滚 + loading |
| Error Normalization Loses Cause（错误归一吞因） | 包装第三方 / 平台错误时只留兜底文案，丢掉 `errMsg` / `cause` / status | 排查只能靠猜 | 至少保留一个底层原因；拿不到原因才用兜底文案 |
| Universal Status Check（全局状态码判定） | 所有来源共用 `code === 200` 或一个全局 interceptor 判业务码 | 不同来源互相误判；第三方 204 / errMsg 被当失败 | 每来源一个 Source Adapter，内部结果统一 |

## 10. 八个深潜

### 10.1 Strategy（策略）

- **一句话**：把可互换的算法抽成同一签名的函数表，运行时按键选择。
- **何时用**：多算法 / 多渠道 / 多导出，分支签名一致。
- **何时不用**：分支签名不同、只有 2–3 个局部分支。
- **代价**：表丢穷尽性；键与实现会漂移；调试多一跳。
- **形态**：

  ```ts
  const fetchers = { a: fetchA, b: fetchB } satisfies Record<Kind, Fetcher>
  const fetcher = fetchers[kind]
  ```

- **反例**：两个分支返回形状完全不同，还硬做成函数表。

### 10.2 State（状态）/ State Machine（状态机）

- **一句话**：状态是一等类型，事件驱动转移，非法状态不可表示。
- **何时用**：异步、互斥状态、多步流程、上传 / 支付 / 鉴权。
- **何时不用**：纯视觉开关、无异步 / 无守卫 / 无动画。
- **代价**：样板；状态爆炸；状态机库是运行时依赖。
- **形态**：discriminated union（可辨识联合）+ reducer；需要层级 / 并行 / 取消时再上库。
- **反例**：`loading && error && data` 同时为真。

### 10.3 Adapter（适配器）

- **一句话**：把不同外部接口转成统一内部接口。
- **何时用**：多平台请求 / 存储 / 路由 / 设计 token 出口。
- **何时不用**：只有一个实现且不会换。
- **代价**：多一层映射；外部能力差异被抹平。
- **形态**：一个内部接口 + 每平台一个实现；选择在入口一次完成。
- **反例**：为每个函数都包一层 adapter。

### 10.4 Facade（外观）

- **一句话**：给复杂子系统一个简单入口。
- **何时用**：请求层、SDK 封装、跨模块流程。
- **何时不用**：子系统本身简单；入口会变上帝对象。
- **代价**：门面膨胀；隐藏能力。
- **形态**：门面只编排，规则留在子系统；门面不写业务分支。
- **反例**：Facade 里塞业务分支。

### 10.5 Observer（观察者）

- **一句话**：发布者维护订阅者列表，状态变化时通知。
- **何时用**：store subscribe、事件、跨组件通知。
- **何时不用**：简单父子通信、事件链短。
- **代价**：内存泄漏、顺序 / 异常、事件意大利面。
- **形态**：订阅返回取消函数；使用方负责释放。
- **反例**：全局事件总线，谁都能发。

### 10.6 Command（命令）

- **一句话**：把操作封装成对象，可排队、撤销、重放。
- **何时用**：undo / redo、patch、宏、队列。
- **何时不用**：一次性操作、无撤销需求。
- **代价**：对象多、序列化、状态一致性。
- **形态**：命令 = 数据 + 执行 + 逆操作；历史栈只存命令数据。
- **反例**：为每个按钮造一个 Command 类。

### 10.7 Composite（组合）

- **一句话**：树形结构，叶子与容器同一接口。
- **何时用**：菜单、组件树、布局槽位、文件树。
- **何时不用**：扁平列表、层级不稳定。
- **代价**：递归、父子边界模糊、调试深。
- **形态**：节点统一 `children` 契约；遍历与渲染分离。
- **反例**：为两层结构造 Composite。

### 10.8 Repository（仓储）

- **一句话**：把数据访问封装成集合式接口，隔离存储细节。
- **何时用**：API 模块、缓存、离线、多数据源。
- **何时不用**：纯展示组件、一次性请求。
- **代价**：抽象泄漏、分页 / 缓存语义、过度封装。
- **形态**：仓储只做取数 / 归一，不写 UI 逻辑；分页与缓存语义在契约里写清。
- **反例**：Repository 里写 UI 逻辑。

## 11. 选型速查（力 → 模式）

| 遇到的力 | 优先模式 |
|---|---|
| 运行时选算法 / 渠道 | Strategy（策略） |
| 状态互斥 / 异步 / 多步 | State（状态）/ State Machine（状态机） |
| 多平台 / 多实现 / 多出口 | Adapter（适配器）/ Ports & Adapters（端口与适配器） |
| 给对象动态加能力 | Decorator（装饰器） |
| 简化复杂子系统 | Facade（外观） |
| 撤销 / 重放 / 队列 | Command（命令）+ Memento（备忘录） |
| 解耦发布 / 订阅 | Observer（观察者）/ Pub-Sub（发布订阅） |
| 统一数据访问 | Repository（仓储） |
| 树形结构 | Composite（组合） |
| 延迟创建 / 复用对象 | Flyweight（享元）/ Singleton（单例） |
| 调用前后加逻辑 | Proxy（代理）/ Decorator（装饰器）/ Middleware（中间件） |
| 多步骤构建 | Builder（建造者） |
| 跨组件共享 | Provider / Inject（提供 / 注入）/ Store（状态仓库） |
| UI 逻辑与渲染分离 | Headless（无头）/ Controller（控制器）/ State Machine（状态机） |
| 按功能组织 | Vertical Slice（垂直切片） |
| 按技术职责组织 | Layered（分层）/ MVC / MVVM |

## 12. AI 使用契约

- **先答四问**：变化点 / 生命周期 / 替换需求 / 代价；答不出就不许上模式。
- **输出必须写三件**：为什么选它、替代方案是什么、代价是什么。
- **不许用模式名当装饰**：没有代码结构支撑的「策略模式」不算。
- **不许无说明引运行时依赖**：先说明体积与必要性。
- **优先语言原生**：能用函数、联合类型、模块解决的，不造类层次。
- **每个模式附一个反例**：没有反例，说明还没理解边界。
- **同族同形**：同一代码族只用一种实现方式；换模式要写迁移理由（A1）。
