# 身份、会话与授权 v1

> 2026-10-28 · v1
> 用途：架构设计时给登录 / 会话 / 权限方案；老项目审计时指出不足与迁移建议。
> 不在范围：口令哈希参数、TLS、密钥与密文（属于安全基线，不在本文）；业务角色与流程建模。
> 用法：设计报告取 §2 / §3 / §4；审计取 §6；反例见 §7。
> 不新增不变量；本文给的是建议与判据，不是门禁。

## 1. 三个维度

| 维度 | 回答 | 产出 |
|---|---|---|
| 认证（AuthN） | 谁在访问 | 登录方式、MFA、找回、认证事件 |
| 会话（Session） | 能在线多久、几处有效 | 会话存储、超时、单点 / 多点、撤销 |
| 授权（AuthZ） | 能做什么 | 权限模型、权限点、PDP / PEP、数据范围 |

三者分开设计、分开命名。把「登录」当「权限」、把「角色」当「会话策略」，都是后面返工的起点。

先分清三个容易混的词：

| 词 | 含义 | 不是什么 |
|---|---|---|
| SSO | 一次认证跨多个应用 | 不等于同一账号只能一处在线 |
| 单会话 | 同账号只允许一个有效会话，新登录踢旧 | 不等于 SSO |
| 多端 | 允许多设备 / 多端同时在线 | 不等于不做安全控制 |

三者的会话是分层的：IdP 会话与各应用会话独立建立、独立失效；IdP 退出不自动等于应用退出。

## 2. 场景 → 方案

| 场景 | 认证 | 会话 | 授权 | 备注 |
|---|---|---|---|---|
| C 端轻应用 | 手机号 / 邮箱 + 验证码或口令；可选第三方登录 | 多端 + 设备列表 | RBAC + 数据范围（本人） | 不自研 SSO |
| B 端后台 | 账号口令 + 可选 MFA | 多端默认，可配单会话 / 并发上限 | RBAC + 页面与接口同源 | 动态菜单 |
| 多租户 SaaS | 口令或企业 SSO | 多端 + 设备管理 | RBAC + tenant 数据范围 | 数据层兜底隔离 |
| 企业内部系统 | OIDC / SAML SSO + MFA | 短会话 + 再认证 | 角色可由 IdP 提供，授权仍本地判 | 记录 IdP 与 subject |
| 高敏（支付 / 财务 / 运维） | passkey / 硬件密钥 + MFA | 单会话 + 短超时 + 敏感操作再认证 | 细粒度 + 全量审计 | 新设备通知 |
| 小程序 / App | 平台登录 + 手机号绑定 | 多端 | RBAC + 数据范围 | 平台凭据不入前端存储 |

## 3. 分层默认

| 档 | 默认能力 | 升级触发 |
|---|---|---|
| L0 | 单应用；账号口令；服务端会话；RBAC + 数据范围；401 / 403 分离 | — |
| L1 | 加 MFA；会话 / 设备管理；认证事件审计；找回与改密流程 | 有资金、隐私或后台管理入口 |
| L2 | 加 SSO（OIDC / SAML）；单会话或并发限制；ABAC / ReBAC；外部决策服务 | 多应用、多租户、资源关系复杂、合规要求 |

默认 L0，按触发升级。不要为了「架构完整」先上 L2。

## 4. 落点

| 层 | 职责 | 反例 |
|---|---|---|
| 前端 | 展示与体验：隐藏按钮、路由跳转 | 把守卫当授权；把菜单当权限 |
| 入口 / 中间件 | 是否登录、令牌校验、粗粒度角色 | 只查登录不查资源 |
| Service | 资源级校验：owner / tenant / 共享关系；调用 PDP | 校验散落在 Controller 或页面 |
| 数据层 | 租户隔离兜底（行级策略 / 强制 tenant 条件） | 只靠前端传 tenant_id |

- PDP（决策）可以外置或内置；PEP（执行）永远在服务端。
- 失败安全：权限服务异常时拒绝，不默认放行。

## 5. 权限方案怎么选

先看三个决策维度，不要先看产品：

| 维度 | 取值 | 倾向 |
|---|---|---|
| 决策需要的数据 | 属性 / 关系 / 图 | 属性 → RBAC / ABAC；关系或图 → ReBAC |
| 策略变更频率 | 随发版 / 运行期可改 | 随发版 → 代码内；运行期 → 策略库或服务 |
| 部署形态 | 单应用 / 多服务 / 多租户 | 单应用 → 应用内；多服务 → 外部 PDP |

三档路径：

| 档 | 形态 | 适合 | 代价 |
|---|---|---|---|
| L0 | 手写 RBAC + 数据范围，收口到 `authz/` | 权限点稳定、单应用 | 复杂后难维护；要补测试 |
| L1 | 应用内策略库：模型 / 策略与代码分离，进程内判断 | 需要运行期改策略、多语言共用 | 模型与 matcher 学习成本 |
| L2 | 外部决策服务：关系引擎或策略引擎，服务端 PDP | 多服务、多租户、关系复杂 | 部署、数据同步、一致性成本 |

可选实现（会变，不排名）：L1 常见 Casbin、CASL；L2 关系引擎常见 OpenFGA、SpiceDB，策略引擎常见 OPA、Cedar；多租户兜底可用数据库行级策略。工具只作例子，选型看上面三个维度。

不要：同时维护两套业务授权真源；把 UI 能力判断当接口授权；为一个页面引入整套引擎。

## 6. 诊断清单（老项目）

| 组 | 信号 | 判定 | 建议 |
|---|---|---|---|
| 认证 | 登录失败提示区分「用户不存在 / 密码错误」 | `fail`（P0） | 统一文案与耗时 |
| 认证 | 有后台 / 资金 / 隐私入口但无 MFA | `warn`（P1） | 按 L1 补 MFA |
| 认证 | 不记录登录方式、无认证事件 | `warn`（P1） | 记 method、认证时间、设备 |
| 会话 | 登录后不换会话，或退出只清前端 | `fail`（P0） | 重建会话、服务端失效 |
| 会话 | 要求单会话，但用无状态 JWT 且无撤销表 | `fail`（P0） | 会话表或版本号 |
| 会话 | 无设备列表、无退出所有设备 | `warn`（P1） | 补会话管理 |
| 授权 | 前端路由守卫 / 隐藏按钮是唯一控制 | `fail`（P0） | 接口补校验 |
| 授权 | 只查角色不查资源归属（IDOR） | `fail`（P0） | Service 查 owner / tenant |
| 授权 | 权限点散落在页面 `v-if` 或字符串字面量 | `warn`（P1） | 收口到权限点表 |
| 授权 | 页面权限与接口权限各一套 | `warn`（P1） | 同源生成或校验 |
| 授权 | 权限服务异常时放行 | `fail`（P0） | 失败即拒绝 |
| 数据 | 多租户只靠前端传 tenant_id | `fail`（P0） | 数据层强制隔离 |

报告句式：

> `src/views/order/list.vue:88` 用 `v-if="hasRole('admin')"` 隐藏导出按钮，但 `/api/order/export` 无权限校验：属 `fail`（P0）。建议在 Service 增加资源级校验并补越权用例；验证：普通账号直接调接口返回 403。

## 7. 反例

- 把 SSO 当单会话：IdP 退出后应用仍在线，或以为一处登录会踢掉所有端。
- 单会话只用 JWT、没有撤销表：旧 token 到期前一直可用。
- 登录方式用自由字符串：`wechat` / `wx` / `weixin` 并存，风控无法聚合。
- 前端守卫当授权：改 URL 或直接调接口即绕过。
- 只查角色不查归属：有「编辑」不等于能编辑别人的记录。
- 权限判断散落页面：改一个入口漏一处。
- 同时上两套授权真源：角色表一套、策略引擎一套。
- 权限服务超时默认放行：故障变成越权。
