# 文件存储与上传 v1

> 2026-10-28 · v1
> 用途：新项目选存储与上传方案；老项目审计上传链路、路径、访问控制与一致性。
> 不在范围：bucket 策略、CDN 规则、生命周期配置、价格核算（属运维与基础设施）；图片视觉效果。
> 用法：设计取 §1 / §2 / §3；审计取 §8；反例见 §8.2。
> 不新增不变量；本文给的是建议与判据，不是门禁。

## 1. 环节与实现

文件存储是一个**环节**，不是某个服务。业务只依赖「存、取、签、删」，实现可换：

| 实现 | 成立条件 | 不成立 |
|---|---|---|
| 本地磁盘 / 持久卷 | 单机部署、低并发、内网工具、开发演示 | 多实例、容器重建、自动扩缩 |
| 对象存储（S3 兼容或云厂商） | 绝大多数生产业务 | 超低延迟随机写、强事务 |
| 网络盘 | 遗留应用需要共享目录 | 高并发小文件、跨区 |
| 数据库 blob | 极小文件、强一致 | 大文件、大量读 |

判断顺序：**先看部署形态**。只要有多实例、容器、自动扩缩，本地盘就不成立；单机项目用本地盘合理，但必须抽象成接口，后面能换。

存储层对业务只暴露四个动作：

- `createUploadPolicy(input)` → 上传地址 / 表单字段 / key / 过期时间
- `completeUpload(key)` → 文件记录
- `getFileUrl(key, { ttl })` → 可访问地址
- `deleteFile(id)` → 标记并异步删除

## 2. 场景 → 方案

| 场景 | 存储 | 上传 | 访问 | 备注 |
|---|---|---|---|---|
| 单机小工具 | 本地盘 / 持久卷 | 服务端中转 | 登录后校验 | 必须备份与磁盘告警 |
| 常规 Web / App | 对象存储 | 服务端签名直传 + 完成后确认 | 私有 + 短期签名 URL | 默认方案 |
| 大文件 / 弱网 | 对象存储 | 分片或可续传 | 私有 + 短期签名 | 记录分片状态，清理未完成 |
| 多租户 SaaS | 对象存储 | 签名直传 | 私有 + 前缀或独立 bucket 隔离 | 服务端强制 tenant |
| 图片密集型 | 对象存储 + 变换服务 | 签名直传 | 公开与私自分域 | 原图入库，变体按需 |
| 必须同步扫描 / 转码 | 对象存储 | 服务端中转 | 私有 | 接受带宽与超时成本 |

三档默认：

| 档 | 能力 | 升级触发 |
|---|---|---|
| L0 | 本地盘或对象存储；中转上传；私有；登录校验；备份 | — |
| L1 | 对象存储；签名直传；业务表状态机；短期签名 URL | 有多实例、外网用户、文件列表 |
| L2 | 加分片续传；变换服务；内容扫描；版本与生命周期 | 大文件、图片量大、合规要求 |

默认 L0，按触发升级。

## 3. 上传链路

| 链路 | 机制 | 适合 | 代价 |
|---|---|---|---|
| 签名直传 | 服务端签发短期 URL 或 policy，客户端直接写存储 | Web / App 常规上传 | 需要 CORS 与临时凭证；内容校验后置 |
| 服务端中转 | 客户端传到业务服务，服务端再写存储 | 必须同步扫描 / 转码 / 合规禁止直连 | 带宽、内存、超时压在应用上 |
| 分片 / 续传 | 按块上传，失败重传单块，最后合并 | 大文件、弱网 | 需要分片状态与未完成清理 |

直传要点：

- policy 限制 key 前缀、大小上限、内容类型；不发整个 bucket 的写权限。
- 客户端拿到的是短期凭证，不是长期密钥。
- 上传完成后回调业务服务确认，再写业务表；未确认的对象按临时对象清理。

## 4. 接口与元数据

文件记录（业务表）：

| 字段 | 说明 |
|---|---|
| `id` / `key` | 业务 ID 与对象 key；key 不可由用户输入直接拼 |
| `bucket` / `provider` | 便于迁移与多环境 |
| `mime` / `size` / `hash` | 校验与去重；hash 可选 |
| `owner_id` / `tenant_id` | 访问控制与隔离 |
| `status` | `initiated` / `uploaded` / `confirmed` / `deleted` / `failed` |
| `created_at` / `deleted_at` | 生命周期与清理 |

规则：

- **业务表是元数据真源**：不要用列举 bucket 代替列表查询。
- **状态机先行**：未确认的上传不进入业务可见状态，避免半成品被引用。
- **URL 不落库**：存 key，取用时再签；换域名、换 bucket、加 CDN 不影响历史数据。
- **删除先标记后异步**：业务不可见与对象真删除分开，失败可重试。

## 5. 路径与命名

- key 由服务端生成：`<业务>/<日期>/<随机名>.<规范化扩展名>`。
- 用户原始文件名只作展示字段，不参与路径。
- 目录按用途隔离（头像、合同、导出、临时），不同用途不同前缀或 bucket。
- 禁止把用户输入直接拼进路径：防 `../`、双扩展名、控制字符与超长名。
- 扩展名白名单化，小写归一；不允许的扩展名直接拒绝。
- 临时文件与正式文件分开前缀，便于生命周期清理。

## 6. 访问控制

- **默认私有**：bucket 不公开读；需要公开的资源显式声明，最好单独 bucket 或前缀。
- **短期签名 URL**：按用户与资源鉴权后签发，TTL 尽量短。
- **下载同样鉴权**：能拿到 key 不等于有权下载；导出、缩略图、原图走同一套授权。
- **多租户**：前缀或独立 bucket 隔离，服务端强制 tenant 条件，不信任前端传参。
- **CDN**：私有资源用签名 URL / 签名 Cookie / 回源鉴权，不要挂在无鉴权的 CDN 上。
- **公开资源**：单独域或单独前缀，避免和私有文件共用路径规则。

## 7. 校验与安全

- **扩展名白名单**：在解码文件名之后校验，防双扩展名与大小写绕过。
- **内容嗅探**：读文件头判断真实类型，不能只信 `Content-Type` 与后缀。
- **图片重编码**：解码再编码，去掉 EXIF 与嵌入内容；处理库要更新、限制格式与资源。
- **SVG / HTML**：可执行内容，默认不当图片内联展示；需要时用独立域或转位图。
- **大小与数量**：单文件、单用户、单请求都有限制；压缩包防 zip bomb。
- **恶意文件**：对外接收文档 / 可执行文件时加扫描；扫描失败按拒绝处理。
- **服务端抓取**：按 URL 拉取要防 SSRF（内网地址、重定向、协议）。
- **本地存储位置**：放在 webroot 之外或独立域名，文件权限最小化。

## 8. 诊断与反例

### 8.1 诊断清单（老项目）

| 信号 | 判定 | 建议 |
|---|---|---|
| 前端代码里出现 `accessKey` / `secret` / 签名密钥 | `fail`（P0） | 改服务端签发短期凭证，密钥立即轮换 |
| bucket 公开读，靠「链接猜不到」 | `fail`（P0） | 转私有，改签名 URL |
| 上传目录 / key 由前端拼接 | `fail`（P0） | 服务端生成 key，白名单前缀 |
| 本地盘跑在容器或多实例上 | `fail`（P0） | 迁对象存储或挂持久卷并改架构 |
| 永久 URL 入库 | `warn`（P1） | 存 key，取用时签 |
| 只校验后缀，无内容嗅探 / 重编码 | `warn`（P1） | 补三层校验 |
| 只删业务表不删对象 | `warn`（P1） | 状态机 + 异步清理 |
| 未确认上传即展示 / 引用 | `warn`（P1） | 加确认步骤与临时状态 |
| 用列举 bucket 当列表 | `warn`（P1） | 业务表查询 |
| 同一上传位置多份实现 | `warn`（P1） | 收口到一个 storage 模块 |
| 无大小 / 数量限制 | `warn`（P1） | 加限制与错误提示 |
| 无备份 / 无孤儿清理 | `warn`（P1） | 补备份与定时清理 |

报告句式：

> `src/pages/upload/index.vue:42` 在前端初始化存储 SDK 并写入长期密钥：属 `fail`（P0）。建议改服务端签发短期 policy，密钥立即轮换；验证：前端产物中搜不到密钥，上传仅接受服务端下发的 key 前缀。

### 8.2 反例

```ts
// 前端持有长期密钥
new OSS({ accessKeyId: 'LTAI...', accessKeySecret: '...' })

// 用户文件名直接进路径
const key = `uploads/${file.name}`

// 永久 URL 入库
file.url = 'https://bucket.example.com/avatar/1.png'

// 只删表
await db.file.delete(id)

// 只校验后缀
if (!file.name.endsWith('.jpg')) throw new Error('invalid')
```

- 把「链接猜不到」当访问控制。
- 上传成功但未确认就展示，失败后留下孤儿对象。
- 替换文件时覆盖旧 key，导致缓存与旧引用读到半截。
- 图片不重编码，直接对外展示用户上传的 SVG / EXIF。
- 本地盘放在容器里，重新发布即丢文件。

## 9. 升级路径

- 本地盘 → 对象存储：先抽象四个接口，再换实现；历史文件按 key 迁移并保留旧路径映射。
- 中转 → 直传：先加 policy 与确认回调，再切客户端；保留中转作为降级路径。
- 私有 → 签名 URL：先把 URL 生成收口，再批量替换库里的永久 URL。
- 单图 → 变体：先接变换服务或预生成任务，再改展示端引用。
