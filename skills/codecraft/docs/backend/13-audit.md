# 后端审计判定 v1

> 2026-10-27 · v1
> 用途：A1–A21 在后端的判定方式与后端专项检查；报告结构、证据、优先级沿用 `docs/shared/08-audit-contract.md`。
> 范围：JS/TS 后端；前端解释见 `docs/frontend/09-audit.md`。运行时差异记录在报告范围里，不改变角色划分。
> 关系：规则见 `docs/shared/00-constitution.md`；族卡见 `docs/backend/10-family-cards.md`。

## 1. 静态检查边界

`codecraft check` 的结构规则以 JS/TS 前端为主；后端只把以下项当抽样工具：

- **A21**：密钥 / 明文口令扫描可用于后端源码与配置；没有命中不等于不存在。
- **A2 / A6 / A11**：可复用于模块依赖、空 catch、生成物标记；不覆盖事务、幂等、迁移。
- **A17**：只覆盖 import 边界；外部 SDK 类型是否泄漏到领域层仍需人工判断。

因此：

- 后端报告不能因为 CLI 0 findings 就判 `pass`。
- 事务、幂等、迁移兼容、N+1、权限矩阵必须人工或通过集成测试验证。
- 报告必须写明执行了哪些检查、覆盖哪些目录。

## 2. A1–A21 后端解释

| ID | 后端判定方式 | `pass` 条件 | 常见误判 |
|---|---|---|---|
| A1 | 人工抽样 | 同一模块内 controller / service / repository 形状一致；跨模块同族同形 | 只看一个模块，忽略另一个模块的写法分叉 |
| A2 | 静态依赖 + 人工 | 入口不 import 数据层；模块间只走 public API；无环 | 只看 service 的 import，漏掉 controller 直连 repository |
| A3 | 人工 | Controller 不解释业务 code、不承担业务反馈 | 只有一个接口收口，其它接口仍散落 |
| A4 | 人工 + 计数 | 错误映射、权限判断、事务入口、外部调用各一处收口 | 权限在 guard 与 service 各写一套 |
| A5 | 人工 + 类型 | 非法状态不可表示；状态机 / 联合类型 / DB 约束 | 有 TS 类型但大量 `any` 或字符串状态 |
| A6 | 人工 + 静态（空 catch） | 错误是值；异步错误不吞；调用方必须处理；错误归一保留 `cause` / 原始 code / status | `catch {}` 后返回成功；Promise 未 await；统一改成一句兜底文案 |
| A7 | 人工 | 错误码、状态转换、路由用表；加 case 只加一行 | 有表但仍有并行 if / switch |
| A8 | 人工 | 派生值不重复落库；缓存不算真源 | 冗余列与计算字段双写 |
| A9 | 人工 | 注释只写意图 / 契约 / 边界 / 反例 | 注释复述代码；迁移说明缺失 |
| A10 | 人工 + 配置 | 例外有理由 / owner / 到期；安全不可豁免 | 「历史原因」无到期 |
| A11 | 静态（标记）+ CI 比对 | 生成物（OpenAPI client / ORM model）有只读标记且 diff 为空 | 只有标记，没有重生成比对 |
| A12 | 人工 | 多服务共享代码有母版、版本、分叉点 | 复制粘贴后各自演化 |
| A13 | 人工 | 每个模块能一眼定位入口、用例、数据 | `common/` 成为跨模块业务桶 |
| A14 | 人工 | 抽象有真实消费方与触发条件 | 提前拆服务 / 预建 shared 业务层 |
| A15 | 流程 / 输出检查 | 变更说明含改了什么 / 为什么 / 怎么验 / 风险 | 用 A15 评价代码结构 |
| A16 | 人工 + 搜索 | 命名标角色、可搜索；表 / 列 snake_case，代码 camelCase | 同一概念多种后缀 |
| A17 | 静态（import）+ 人工 | 外部 API / SDK 形状只经 Wrapper；DTO / 领域 / 持久化模型分离 | 外部 SDK 类型进入 domain；ORM entity 直接当响应 |
| A18 | 人工 | 有档位：模块化单体 → 拆分服务；默认最小 | 小项目直接微服务 / CQRS |
| A19 | 人工 + 契约测试 | API 契约固定；有 consumer-driven / schema diff | 接口靠口头约定 |
| A20 | 人工 | 记录环节与职责，不把框架当层 | 「Express 层」「Nest 层」当架构 |
| A21 | 静态扫描 + 人工 | 无密钥 / 越权 / 注入 / 日志泄漏；交付白名单一致 | 只扫源码，漏配置与日志 |

## 3. 后端专项检查

这些检查复用 A 编号，不新增规则 ID：

| 检查 | 判定要点 | 关联 |
|---|---|---|
| 事务边界 | 事务在 Service；Repository 不提交；一个用例一个事务 | A4 / A5 / A19 |
| 幂等 | 写接口有幂等键或业务唯一约束；重复请求返回同一结果 | A4 / A19 |
| 迁移兼容 | expand / contract；删列 / 改类型独立发布；有回滚 | A11 / A19 |
| 查询性能 | 高频查询有索引；无 N+1；分页显式 | A13 / A14 |
| 异步任务 | 至少一次投递；消费幂等；重试上限 + 死信 | A6 / A19 |
| 缓存 | TTL 必填；有失效触发点；故障降级 | A8 / A19 |
| 权限 | 认证与授权分开；越权默认拒绝；有权限矩阵用例 | A4 / A21 |
| 密码学 / 凭据 | 按 `docs/shared/09-security.md` §6 查落点：密码只哈希、TLS 校验未关、密钥不硬编码、令牌必 verify | A21 / A6 |
| 身份 / 会话 / 授权 | 按 `docs/shared/10-auth.md` §6 查：认证事件可查、会话可撤销、资源级校验在 Service、PEP 不缺失 | A4 |
| 文件存储 / 上传 | 按 `docs/shared/11-storage.md` §8 查：密钥在服务端、key 服务端生成、私有 + 签名、删除有对象回收 | A19 / A21 |
| 配置 | 启动校验；密钥不入库；无危险默认值 | A21 |
| 可观测 | request id；结构化日志；错误可定位；无敏感字段 | A9 / A21 |
| API 契约 | 版本 / 兼容策略；schema 可 diff；错误结构统一 | A19 |

### 3.1 运行时差异

报告范围里记录运行时与版本，并检查：

| 项 | 检查点 |
|---|---|
| 模块系统 | ESM / CJS 是否混用；动态加载是否依赖特定运行时 |
| TS 执行 | 直接运行 TS 还是构建产物；类型检查是否独立 |
| 环境变量 | 是否集中在 Config；是否依赖某个运行时的 env 对象 |
| 文件与系统 | 是否依赖特定运行时的文件 / 进程 API；在目标部署形态是否可用 |
| HTTP 服务 | 标准 Request / Response 还是运行时私有 server API |
| 包管理 | 锁文件与依赖来源是否单一 |
| 权限模型 | 目标运行时 / 部署形态的权限与网络限制 |
| 原生模块 | Node-API / 原生依赖在目标运行时是否可用 |
| 部署限制 | 冷启动、长连接、定时任务、文件系统 |
| 锁定点 | 运行时 / 框架专属 API 是否只出现在适配层 |

## 4. 一致性检查

| 场景 | 要求 |
|---|---|
| A3 判 `pass`，但 Controller 里有业务分支 | 改为 `warn`；入口承担了业务 |
| A17 判 `pass`，但 ORM entity 直接作为响应 | 改为 `warn`；持久化模型外泄 |
| A19 判 `pass`，但没有契约测试 / schema diff | 最多 `warn`；只能写「有接口文档」 |
| A21 判 `pass`，但只扫了源码 | 写 `pass（有限）`；配置、日志、权限未覆盖 |
| A4 判 `pass`，但事务在 controller 与 service 各开一次 | 改为 `warn`；事务入口不唯一 |
| A8 判 `pass`，但冗余列与计算字段双写 | 改为 `warn`；派生值落库 |
| 事务 / 幂等 / 迁移未做集成测试 | 不能给 `pass`；最多 `pass（静态）` 或 `warn` |

## 5. 机检映射

| 检查 | 机检形态 |
|---|---|
| 依赖方向 / 模块边界 | eslint boundaries / dependency-cruiser |
| 输入校验 | schema 单测；类型从 schema 推导 |
| 迁移 | 空库 + 生产快照跑迁移；回滚演练 |
| 幂等 / 事务 | 集成测试（重复请求、并发请求） |
| 权限 | 权限矩阵用例；越权用例 |
| 密钥 / 配置 | secret scanning + config schema 校验 |
| API 契约 | schema diff / consumer-driven contract |
| 日志 | 字段快照；敏感字段黑名单 |

## 6. 交付前自检

除 `docs/shared/08-audit-contract.md` 的通用项外：

- [ ] A1–A21 全部出现，或写明 `na`
