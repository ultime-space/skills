# Audit Existing（旧项目审计）

## 何时用

接手 / 升级 / 重构前体检。

## 输入

- 仓库路径 / 分支
- 目标（升级、拆分、迁移、只体检）

## 先读

项目规则 → 宪法 → 相关族卡 → 现有 `README` / `docs`

## 步骤

1. 确认范围：仓库 / 分支 / 目录、只读声明、能否跑命令。
2. 盘点：技术栈、目录、页面、请求层、状态、类型、测试。
3. 先跑静态检查，记录 `files / findings` 与覆盖范围；写明 A17 / A21 盲区。
4. 逐条对照 A1–A21；标 `pass` / `pass（静态）` / `warn` / `fail` / `na`，每条带证据。
5. 做一致性检查：A4 / A8 / A11 / A17 / A21 与证据矛盾时降级。
6. 找“历史实现”与“环节缺失”：哪些是习惯，哪些是必需。
7. 出差距清单：影响、成本、优先级（P0–P3）。
8. 出升级计划：分阶段、可回滚、每阶段验收；不写时间估算。
9. 风险：兼容、数据、权限、发布。

## 输出

- 体检报告（按 `docs/contracts/08-audit-contract.md`）
- 逐条判定表（A1–A21，含证据与局限）
- 差距清单（P0–P3）
- 升级计划
- 回滚方案

## 停止条件

- 无法只读访问
- 需要改动生产配置
- 发现密钥 / 隐私：停止并提示轮换

## 验收

- 只读；不改代码
- A1–A21 全覆盖或写明 `na`
- 每条结论有文件路径 / 命令 / A-ID
- `0 findings` 已注明“仅静态未命中”，没有写成通过
- 计数可用文中命令复现
