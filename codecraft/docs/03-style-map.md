# 风格总图（一页）

> 一页看完全套约束的形状；细则见 `00-constitution.md`，字段见 `01-family-cards.md`。
> 范围：默认 JS/TS 前端项目；结构与判据可迁移，页面 / 组件相关条目只适用于前端。
> 读法：先看第 1 节「不变的」和第 2 节「变的」，其余是判据与代价。

## 一句话

先画承重墙，再摆家具。
承重墙 = 边界、契约、收口、命名；家具 = 栈、状态库、UI 库、样式实现。

> 完整在底层，取舍在上层：规范覆盖大项目能力，默认只启用小项目所需（A18）。

## 1. 不变的承重墙

| 层 | 不变量 |
|---|---|
| 边界 | 外部契约不参与内部规范；外部只在 Wrapper 出现；内部不 import 外部类型（A17） |
| 传输 | 传输层只负责收发与取消，不解释业务 code（A3） |
| 收口 | 鉴权失效、错误提示、分页、配色、分类各一处（A4） |
| 页面 | 一个页面一个编排入口；页面只编排，不写传输与领域规则（A1） |
| 组件 | 原语薄、业务组件按域；同族同形（A1） |
| 行为 | 页面无关行为单独成层；页面不复制行为（A1 / A4） |
| 状态 | 异步 / 多态用联合类型；非法状态不可表示（A5）；派生不存储（A8） |
| 类型 | 外部保持原名；内部通用层与业务层分离（A17） |
| 命名 | 同族一种前缀；前缀标层、防重名、可搜索（A16） |
| 错误 | 预期失败是值；空 catch 为零（A6） |
| 生成物 | 只读；有标记；可重建（A11） |
| 实现 | 模块内部自由；public contract 固定（A19） |
| 环节 | 记录职责，不记录实现；环节可消失（A20） |
| 注释 | 只写代码不能直接表达的意思（A9） |
| 目录 | `apps/` 交付物；`packages/` 能力；`assets` / `docs` 默认是目录 |
| 文档 | 统一 `docs/`；分级 + 安全边界（A21） |

## 2. 变的家具

- 栈：按项目选；一次只换一个轴。
- 状态：按复杂度选；局部状态优先。
- 样式：字面量 → 变量 → token + 审计。
- 类型：手写 → 生成；生成物只读。
- 传输：手写 → 库；换实现不换契约。
- 设计：无 → 设计工程；稿码同构是翻译前提。

换栈 = 换家具，不动承重墙；换家具要重建该轴的体系，不是局部替换。

## 3. 抽象判据

- 语义同源 > 形状相同 > 文本相同；文本相同不构成理由。
- Wrapper 只承载转换，不承载样式补丁与业务堆叠。
- 差异收在边界：平台差异走目录 / 后缀 / Wrapper。
- 抽不抽：第二次出现警惕，第三次出现或第三个消费者再抽象（A14）。
- 复制 vs 抽象：复制要登记母版、版本、分叉点（A12）。
- 加一层必须能一眼定位源头（A13）。

## 4. 复用方式

| 方式 | 场景 | 代价 |
|---|---|---|
| 复制母版 | 一次性交付、生命周期短 | 同一缺陷修多次 |
| 同仓多分支 | 多客户强定制 | 长期 fork，合并面大 |
| 同仓多包 | 多应用共享能力 | 包负责兼容矩阵与版本 |

## 5. 稿码关系

```
设计稿（展开态）── 折叠 ──► 代码（组件调用）
        └── class / DOM 同构 ──┘
```

- 结构 / 样式默认 design-first；行为导致的样式变化 code-first。
- 同构是翻译前提；不成立时只能靠理解，必然漂移。
- 审计只做可判定项初筛，终审是人。

## 6. AI 协作

- AI 是实施者，人是判断者；瓶颈是审稿带宽。
- 规则从现有代码与既有决策提炼，不发明。
- 输出必须说明改了什么 / 为什么 / 怎么验 / 风险（A15）。
- 被 AI 使用的形态要短、硬、可验证；长解释放参考文档。

## 7. 代价

- 复制放大缺陷；测试缺位时只在线上暴露。
- 换 UI 库要重建样式体系。
- 收口点多，接手要先学一张地图。
- 规范本身有维护成本；改契约要整族刷新。

## 8. 一句话

**先定边界，再选实现。**
承重墙是契约与收口，不是某个框架或某个库。
